# 测试与验收

本页是 Bailey 完成标准的唯一归属，负责完成标准、测试层次、执行入口和通用验收。
测试结构、覆盖范围或验收要求改变时更新。操作细节见[测试环境](testing-environment.md)和[性能验收](testing-performance.md)。

## 完成标准

需求／文档驱动决定做什么和如何验收，测试驱动验证实现；二者属于同一流程。

| 检查 | 完成条件与证据 |
| --- | --- |
| 行为回归 | 新增或调整受影响测试；可测试的新行为和缺陷先确认 Red，再修复为 Green，最后 Refactor |
| 最小实现审查 | 每次开发和修复均须在首次提交及标记任务完成前，按[简单与可维护](standards.md#简单与可维护)主动审查受影响的完整调用链及 diff，清除已确认的冗余与废弃路径，复验受影响行为；提交正文说明清理结果，若无可删项则说明依据。未完成审查或仍遗留已确认的冗余，不得提交为完成 |
| 自动测试 | 本地只运行受影响的 XCTest，正式完整验收时运行 `make test`；测试必须实际被发现和执行 |
| 构建与签名 | 功能代码通过 `make build`；Swift 6 全面迁移、依赖或发布路径变更还检查 `make build:release`，无未解释的新诊断 |
| 架构与数据保护 | 按 [模块边界](architecture.md#模块化与依赖) 核对所有者、反向依赖与镜像状态、明确动作意图及取消／目标失效后的真实副作用；每次重构在同一改动中删除已被替代的旧路径 |
| 用户路径 | 按下文运行受影响的原生／工作区和人工回归；未执行的 E2E、真实网络与恢复明确列出 |
| 文档与差异 | 受影响文档在同一提交更新，现行链接可达；通读 diff，`git diff --check` 通过 |

**纯文档改动**检查事实、路径、命令和导航，不机械编译或安装 App。
文档体系调整逐页核对职责、更新时机、功能页首节、索引覆盖、路径大小写与标题锚点；
现行计划单独查失效引用，历史审计不全局替换。检查脚本未覆盖的格式或目录明确列出，
不将“无断链”冒充全部文档通过。纯翻译检查字符串表、中英文、占位符与链接，涉及提取时按需构建；
快捷键、路由和布局不是纯文案改动。

编译成功、全部低层测试转绿或事件已发出，都不能证明完整用户路径正确。
不能禁用失败用例或增加任意等待来制造绿色；既有正确行为也不能为了错误断言而被修改。

## 根因与回归覆盖

**必须尽可能覆盖受影响功能的全部测试环境、测试条件、异常状态、边界与极端情况及其组合；不得以正常路径或几个代表性测试通过作为完成依据。**
覆盖范围由本次改动的真实影响路径决定，不等于每次都执行全仓测试。
修复缺陷须还原真实触发条件，沿入口、状态所有者、共享依赖及失败／恢复路径定位失效不变量，
在归属处修复；逐一核对同一根因涉及的其它入口，不能吞错、加等待或只调整断言。
可复现缺陷保留 Red→Green 证据；测试夹具必须证明前置条件成立，例如真实 Git 冲突索引，
而不仅是命令非零。

开始验收时，先枚举**全部已识别且适用于受影响功能**的条件，并尽最大可行程度逐项执行，
而非事先挑选少数高风险示例：

- **环境／配置**：最低及当前支持的系统、工具链版本、默认与非默认配置、语言区域、权限／签名、
  本机及获授权的 SSH 后端、在线／离线／网络不稳定。
- **输入／容量**：空／缺失／非法输入、特殊字符／Unicode、二进制、特殊路径、最小／通常／大规模数据、
  长度与容量边界、超限及资源耗尽。
- **状态／失败／恢复**：初次及已有数据、冲突、部分成功、读写失败、断线／超时／重连、取消、重新打开、
  关闭与恢复、旧状态拒绝或恢复边界。
- **时序／交互／生命周期**：并发与重复操作、乱序回写、窗口或目标切换、资源释放、长时间运行，
  以及受影响的尺寸、主题、焦点、多窗口和键盘操作。

**所有已识别且可在安全隔离环境中执行的适用条件都应覆盖。** 对有限且可承受的条件组合尽可能逐一验证；
组合规模过大时，应覆盖每个适用维度的取值与极值，并系统地扩展两两、多因素和已知失效条件的组合，
不得用“风险驱动”或“抽样”跳过单独可执行的条件及极端情况。
无法实测的项目逐项写明环境／前提、原因、替代验证、影响及是否阻塞验收；
关键条件未验证不得宣称功能已完整验收。测试须核对最终可观察结果。
**XCTest 全绿不等于整个 `make test` 成功**：还须核对构建、签名等后置检查与完整命令退出状态；
本地测试、Tag 发布构建与真实用户路径分别报告。

## 测试目录与入口

`BaileyTests/` 是**唯一的宿主 XCTest Target**，测试直接按领域放在 `App/`、`Editor/`、`Files/`、
`Git/`、`Remote/`、`Settings/`、`Terminal/`、`Workspace/`，不再按 Unit／Integration 额外分目录。
宿主测试既可检查纯算法和模型，也可使用真实临时 Git／文件、
最小 AppKit 组件验证 `NSTextView` 行号像素、TextKit 2 视口、IME 或 PTY；它们都不属于完整 App E2E。
`BaileyUITests/` 使用独立 UI Test Target（`Bailey-UI` Scheme），
通过 `XCUIApplication` 操作完整 App，不导入产品模块。
只有底层测试无法证明的真实用户入口、系统交互与跨窗口操作才放入这个目标。

每个文件按主要职责归档，不因混合用例机械拆类，不创建空目录或空测试。
移动文件时核对工程发现路径，不能让它退出真实测试集合。
宿主与 UI 测试共用的固定音视频样本放在 `TestFixtures/Media/`，不依赖 Feature 计划目录或进入 App 发布包。

```sh
make test:FileTabPersistenceTests,NativeFileTabTests
make test            # 完整宿主 XCTest
make build:ui        # 只编译独立 UI Test，不启动 App
make test:ui         # 独立图形会话中运行完整 App UI Test
make test:ui ONLY_TESTING=BaileyUITests/WorkspaceSmokeUITests  # 本地只跑指定 UI 类
```

本地迭代人工指定 `make test:类名1,类名2,...`（逗号分隔，不加空格）选择任意数量的宿主 XCTest 类；
涉及共享组件时补测相关类。指定 `ONLY_TESTING` 时先通过 Xcode 原生测试枚举检查选中方法数；
无匹配方法直接失败，不再把 0 项 XCTest 当作通过。`make test:ui` 单独执行整个 UI Test Target，
不混入本机日常宿主测试。

## CI 测试

GitHub Actions **不对 PR 或普通 `main` 提交自动运行 XCTest**。
独立的 [XCTest workflow](../.github/workflows/ci-ui-test.yml) 在显式推送 `ci-ui-*` 测试标签时运行，
并在工作流合入默认分支后提供手动运行入口。
手动触发时可选择 `both`／`host`／`ui`，分别为两套测试填写类名／方法筛选项；
筛选项接受逗号或空格分隔的 `GitStatusModelTests`、`GitStatusModelTests/test...`
或完整 `BaileyTests/...`／`BaileyUITests/...` 路径，留空运行对应完整测试集。
非空选择项交给 Makefile 的 `ONLY_TESTING` 和 Xcode 原生枚举校验，
不存在的测试不得被视为通过；`ci-ui-*` 标签推送仍执行全部两套测试。
两个独立的 macOS Runner Job 将系统 `xcode-select` 与 `DEVELOPER_DIR` 一起指向 Xcode 27.2，
避免 XCTest 子进程重新调用旧版 Xcode 工具链；各自保存 `.xcresult`。
CI 结果与本机验收分别记录，失败不能冒充已验收；
授权 SSH、系统外观等特殊条件仍按[测试环境](testing-environment.md)另行核验。
合并前的结果由提交者负责，Tag 发布工作流不重复执行测试。

UI Job 必须检出完整 Git 历史：`GitChangesUITests.testRealBaileySourceHistoryDiffLoadsAcrossIndexWorktreeAndOtherSource`
会从实际 Bailey 源码取两个提交版本并在隔离克隆中构造 Staged／Worktree 变化；默认浅克隆仅有当前提交会导致夹具无法创建，而非产品 Git Diff 故障。
测试入口由 [Makefile](../Makefile) 与
[共享 scheme](../Bailey.xcodeproj/xcshareddata/xcschemes/Bailey.xcscheme) 决定；
不另建不参与 XCTest 的检查脚本，也不在产品启动时执行断言式自检。


## 测试层次

**尽可能由宿主测试证明行为，完整 App UI E2E 只补不可替代的用户路径。** `BaileyTests`
可以直接测试生产 Model、真实隔离 Git／文件、`NSAlert`、最小 `NSHostingView`／`NSWindow`、
TextKit／IME 和原生组件像素；并非涉及界面、真实 IO 就必须启动 App。
只有系统菜单与选择器、实际前台键鼠、跨窗口路由、系统拖放或重启等无法通过宿主证明的行为，
才进入 `BaileyUITests`。Unit／Integration 只是测试性质，不另设目录或比例。

| 层次 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 宿主测试（`BaileyTests`） | 纯计算、模型／状态、解析、异常／容量矩阵；真实临时文件、Git／受控 SSH、持久化及最小 AppKit/TextKit／IME／Undo 组件契约 | 不证明完整 App 的菜单、前台键盘交接或真实跨窗口路由；模拟 SSH 不等于实际远端 |
| UI E2E（`BaileyUITests`） | 通过 `XCUIApplication` 启动 Bailey Dev，操作真实菜单、Sheet、焦点和跨窗，并核对最终文件、Git 或窗口结果 | 不能替代宿主测试中全部异常、容量和组件组合；组件绿色不等于 UI E2E 通过 |

必须访问 TextKit／AppKit 内部状态的原生组件测试保留在宿主 XCTest；
Ghostty 的真实 PTY 只有原生终端表面附着最小 `NSWindow` 才会启动，
相关集成测试不得挂载完整 SwiftUI 工作区或模拟用户交互。
完整外部路径（Finder／Dock 拖放、真实 SSH、脏文件保存冲突和不同窗口混合停靠）仍需独立验收；
组件测试与宿主 XCTest 都不能冒充完整 App E2E。

**新增和现有 UI E2E 都应优先考虑转交宿主。** 逐方法核对断言：纯规则与数据、真实 Git／文件结果、
表单默认值／控件状态和可独立挂载的原生渲染，尽可能由宿主承接；仅保留宿主无法证明的实际 App 接线。
混合用例先补齐宿主验证，再移除 UI 中的重复步骤；如果唯一的完整用户路径已由其它 E2E 覆盖，
就删除整个重复方法及其专用夹具。不能因用例名称包含 GUI、菜单、像素或 Git 就默认保留完整 App 测试；
也不能以组件测试冒充真实系统焦点、跨窗、拖放或应用重启。

完整覆盖仍须验证全部适用条件、极值、异常、失败恢复与关键组合，尤其要核对最终文件字节、
Git index／HEAD／Ref 和目标身份。逐项记录被删用例的原断言、实际宿主替代与剩余真实用户入口；
不能通过 `XCTSkip`、合并超长 UI 脚本、减少断言或仅搬迁代码凑精简数量。
主题、字号、宽度确实影响原生交互时仍须验证对应边界，但不为每项数据组合重复执行整套 App 启动、
菜单和点击。

**本地迭代先定点验证。** 先根据实际入口、共享依赖和最终结果确定受影响的条件，
优先运行对应测试方法（`make test ONLY_TESTING=BaileyTests/类名/方法名`）；
必要时扩展到相关类及共享使用方，不为保险运行无关模块的耗时或性能测试。
只有宿主无法证明的真实交互才运行指定 UI 方法；没有独立图形会话时记录未测，
不得抢占用户桌面。仅在明确要求的阶段验收或发布门禁中运行全量 `make test`／`make test:ui`，
中断、超时和未执行均不能报告为通过。

测试断言应到达磁盘字节、Git index/HEAD、原生内容、窗口归属或实际焦点。
需要前台原生输入的用例由运行环境保证焦点，不以窗口是否为 Key Window 决定跳过或放宽断言。
只验证 mock 被调用、字段改变或事件送出，不足以守住最终结果。
临时 Git 仓库若依赖固定分支名，应在 `git init -b` 时明确指定，
不能依赖执行环境的 `init.defaultBranch`。

具体测试入口按[功能索引](README.md#功能文档)查找各页「验证」；
原生交互的环境与夹具见[测试环境](testing-environment.md)。

## 架构与异步检查

纯 Model 不引入 UI 或环境效果；其时钟、文件事实和外部输入按实际边界注入。
按真实职责和调用关系检查分层，不以文件名、目录名或一次文本扫描代替验证。

职责重构须逐任务记录**原所有者 → 新的唯一所有者 → 被删除的重复状态／反向依赖 → 用户最终结果**。
新增 Manager／Coordinator／Protocol 本身不算模块化；未使用的协议、镜像状态或只转发的壳必须删除。
应用／窗口拆分覆盖外部路由、双窗隔离、关闭保存与恢复；各项完成前没有第二套全局登记或保存路径。

焦点和列表交互必须分别验证六种事实：**展开、选中、悬停、展示、激活、真实键盘焦点**。
在同一动作可合法联动时，也要核对动作是否明确要求联动；
目录展开不误打开文件，Files／Git 浏览可展示 Diff 但不抢另一组焦点，图谱提交展开不制造持续灰底，
行边框只随实际键盘接收者变化。核对 `NSWindow.firstResponder`／原生 field editor、
实际按键文本或 Shell marker、选区、当前展示内容与对应文件／Git 结果；
`selected` 字段、视觉高亮、请求已排队或事件已发出都不能单独证明焦点成功。
具体状态所有权见 [焦点协调边界](architecture.md#焦点协调边界)。

跨组件焦点迁移按 Dock／Files、Git、原生 Terminal／Editor／Diff、Browser、
Palette 等**已触及的真实调用链逐段交付**；每段在原始实现基线和上一验收点上验证静态画面、中间帧、
交互步骤、输入及对象身份**零 UI/UX 变化**，不把旧实现清理和重要 E2E 留到全部迁移结束。
新旧策略不能同时争夺焦点；尚未迁移的功能继续独立维持原行为。
按全部可行条件／组合验证，并逐条记录无法执行的系统级路径、原因、影响及 Gate 限制。

平台范围以 [architecture.md](architecture.md#平台范围) 为准：
当前验收仍须尽可能覆盖受影响的 macOS 最低／当前系统、配置和原生路径，不为暂缓的 iOS、
iPadOS 或 visionOS 建立测试目标或承诺兼容性。新规则的静态文档检查不等于架构迁移或产品验收通过。

使用明确事件和有界等待控制异步测试，覆盖取消、目标切换和乱序回写。
并发改动须在真实入口确认耗时工作不在 `MainActor` 上同步执行；
不能以出现 `async`、`await`、`Task {}` 或后台线程日志作为证明。
受控地暂停生产者和 IO，验证取消到达实际任务、最后一个使用者退出后释放资源，
以及取消／失败／迟到结果不覆盖新状态、不破坏其它仍活跃的使用者。
有流式或大量并发工作时核对队列字节峰值、同时执行量、背压和完成顺序；
不能用 UI 已更新证明底层写入、进程退出或资源关闭。
写入、编码转换和关闭竞态按[文件保存验证](features/file-saving.md#验证)执行。
原生集成检查观察、绑定、嵌套变化、窗口菜单和重挂载，
不只检查类型注解。

Swift 语言模式或并发隔离规则变更须在实际模式下构建、运行测试并严格验签。
静态扫描、只改编译选项或屏蔽并发诊断不算通过。

## 人工回归

受影响功能的全部可行人工操作、环境差异和极端条件应尽可能逐项执行；
不把未触及的其它项目硬加进回归，也不把没有执行的项目写成通过。

逐项回归受影响功能的真实入口、异常与恢复，按[功能索引](README.md#功能文档)中的验证段落选择具体用例。
原生界面与远端实测遵循[环境隔离](testing-environment.md)，性能与容量遵循[性能验收](testing-performance.md)。

视觉改动使用同窗口尺寸、内容和动作的前后并排录屏；截图和自动检查作为补充，不能把静态图当成焦点、
拖动或滚动验收。纯架构重构对受影响区域逐任务对照原生截图和交互，不夹带重设计。
受影响控件保留原生角色、名称、稳定标识、当前值、选中／启用状态及可执行动作。
自动化按真实操作及结果验证，不以元素存在、事件已发送或静态截图判定动作成功。
VoiceOver 专项导览、语音播报、语音交叉矩阵不属于现行验收范围，不再阻塞任务或阶段。
不为此打开系统旁白或改变系统权限；现有基础无障碍语义、键盘和真实焦点回归仍须保留。
验收产品自身负责的行为，不把系统原生能力的专项认证变成产品门禁。
不单独验证减弱动态效果或与改动无关的系统辅助设置，不要求独立设备与输入条件的无关联全排列。
