# 终端与面板

修改会话、停靠布局或焦点时，保留以下约束。

## 生命周期与布局

- 一个终端会话持有一个长生命周期进程与表面。切换项目、拖动标签或重挂载只移动现有表面，不新建 Shell，不丢选区、滚动与查找状态。
- 面板与标签页一一对应，`PaneTab` 只持有一份内容。停靠位置由 `DockNode` 管理；diff 统一/并排只是内容显示方式，不是额外面板。
- 每个停靠区域地位相同，使用相同的「＋」入口；工具面板移动而非重复创建。默认三列只是初始布局。
- 系统「显示（View）」菜单统一提供面板、标签和项目切换；动作读取当前窗口的协调者，不路由到后台窗口。文件和 diff 的未保存状态由标签发布到项目与窗口，保存仅在聚焦内容有修改时启用；设置与空窗口的关闭仍走系统窗口关闭。
- 布局按项目保留。移动与关闭后焦点必须落在有效内容；视图重挂载不重新创建其内容。
- 关闭工作标签只结束它持有的内容；未保存内容必须先确认。关闭工具面板不删除项目或会话。

## 输入、搜索与通知

SwiftUI 接收交互，AppKit/Ghostty 处理终端表面、输入和原生焦点；不要以重建表面修复焦点。

命令面板的文件搜索仅支持本机项目。SSH 目标不得搜索本机同名目录；选择结果后应完成真实打开或会话聚焦，不能只验证命令已派发。

通知使用对应项目名称，保留程序正文；点击须定位发出通知的会话。关闭与重启不能承诺恢复运行中的命令，恢复边界见[设置与恢复](SETTINGS.md)。

## 验证重点

实际检查多项目切换、独立标签拖动停靠、关闭后焦点、快捷键与通知定位。终端进程不得因重挂载重启，后台命令不得意外中断。

停靠模型检查不能代替原生焦点与输入验收；浏览器和未保存文件重挂载另见[浏览器](BROWSER.md)与[编辑器](EDITOR.md)。
