# 性能

修改文件读取、高亮、输入、Git、diff 或大列表性能时，按本文验证；容量和正确性边界仍以各功能维护文档为准。

## 先定位，再减工作

先测最重的共享路径，再减少主线程工作、重复读取/计算和无关命令。不凭源码行数判断热点，不为未测瓶颈换掉 SwiftUI、TextKit 或 WebKit。

保留已有的增量解析、按视口请求高亮、查询缓存、懒加载、Diff 原生 TextKit 懒布局与视图复用、事件驱动 Git 刷新和 SSH 批量执行。后台任务必须读取稳定快照，回主线程应用时核对目标与代次；增加 `Task {}` 不等于离开主 actor。

优化不能牺牲未保存编辑、超时与错误反馈、机器身份、中文/emoji/CRLF 坐标、撤销、共享树行或无障碍。缓存须有释放边界，不以无限预热换取热路径数据。

## 测量用户看到的结果

| 路径 | 分开记录 |
| --- | --- |
| 打开编辑器 | 可见文本、可输入、可见高亮稳定 |
| 输入 | 按键到文本/光标更新、高亮追上、主线程最长连续占用 |
| Git | 状态可用、详情完成、进程数、读取量与 SSH 往返 |
| diff | Git/SSH 读取、差异计算、TextKit 首屏布局、语法高亮、滚动与编辑 |
| 多标签与空闲 | 冷开、重复切换、关闭后的内存释放、前后台 CPU 与唤醒 |

骨架、数据已加载或 FPS 回调不能代替真实显示与响应。调查 Diff 时测量原生 TextKit 布局、高亮、差异计算和 App 进程，不再追查 WebKit 渲染进程；浏览器仍使用 WebKit。

## 样本与工具

同一台机器、同一构建配置和同一批公开或合成样本做前后比较，记录提交、系统、硬件、屏幕、字体、布局与缓存状态。Debug 和优化构建分开，冷开和热操作分开。

按改动选择小/中/接近上限文件、长行、密集语法、嵌入语言、大变更集、多个标签及本地/SSH；包括受影响的空内容、Unicode、二进制和超限边界，不机械穷举组合。

热操作至少重复 30 次，记录样本数、中位数、p95 与最差值；少量冷启动样本只报告中位数和最差值。清理缓存不得破坏用户文件或系统状态。

优先用 Instruments Time Profiler 定位 CPU 热点，卡顿但 CPU 不高时查线程等待；用 Allocations 查文本和视图生命周期。仅在需要对齐阶段时添加轻量 signpost，不先搭完整埋点框架。

## 完成条件

记录样本、环境、前后数据、热点与正确性回归。没有测量只说明实现变化，不宣称提速；观测值不是容量承诺或硬门槛。

具体优化方案和一次性调查留在 `.github/features/`，不作为当前功能事实。构建与真机验收按 [AGENTS.md](../AGENTS.md) 执行；trace 可能含文件、路径或终端输出，分享前脱敏，不默认入库。
