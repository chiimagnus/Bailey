# Git 与差异

在项目旁审查修改、暂存和提交，不必离开终端工作区。选中项目后按 ⇧⌘G 打开 Git 面板，先确认面板里的仓库路径。

## 审查修改

- 未提交和已暂存分区分别列出工作区与索引变化；同一文件可同时出现在两区。
- 点击文件打开相应 diff。最近提交中的文件打开历史 diff。
- 右侧按钮执行暂存、取消暂存或丢弃，不会打开文件。
- 目录折叠状态按仓库记住。设置中的“文件布局”可在目录树与列表之间切换。

## 识别文件状态

文件面板、Git 目录树和提交文件列表共用状态表示，不另设字母列：

| 状态 | 文件名颜色 |
| --- | --- |
| 修改 | 黄色 |
| 新增或未跟踪 | 绿色 |
| 删除 | 红色 |
| 重命名或复制 | 蓝色 |
| 冲突 | 紫色 |
| 忽略 | 灰色 |

提示和无障碍描述也提供状态，不必只靠颜色判断。顶部增删行数是概览；较大的未跟踪文件或超过统计预算的集合可能不计入，审查范围以文件列表和实际 diff 为准。

## 查看与编辑 diff

diff 支持统一和并排布局，以及行内变化高亮。它使用独立标签；并排布局不是[终端分屏](TERMINAL.md#分屏与焦点)。

可编辑的工作区文本可在 diff 顶部切入编辑模式，修改后按 ⌘S 保存。暂存与历史 diff 只读；保存工作区内容不等于暂存或提交。
符号链接不作为普通文件写入。二进制、不能解码为 UTF-8，或任一侧超过 5 MiB 的文件不提供文本 diff。
保存失败保留修改；SSH 断线暂时只读，重新连接后再保存，见[连接中断](PROJECTS.md#连接中断)。

## 暂存、丢弃与提交

1. 逐文件审查后暂存需要提交的内容。取消暂存只改变索引，保留工作区修改。
2. 输入提交说明，选择提交已暂存内容；只有明确选择“全部暂存并提交”时才包含全部改动。
3. 提交后检查操作结果与更新后的列表。需要修改上一条提交时，使用提交菜单里的 amend 选项；它会改写上一条提交，已分享的历史先与协作者确认。

丢弃会撤销工作区改动：普通已跟踪文件从索引恢复，不是简单恢复到 HEAD。未跟踪文件在本机移入废纸篓；远程删除没有本机废纸篓保护，确认范围与备份后再执行。
丢弃不是撤销编辑器里未保存文字的替代品。

## 分支、远端与储藏

分支菜单可切换分支或新建分支；“更多操作”提供获取、拉取、推送/发布分支、同步、储藏和弹出储藏。
拉取只允许快进，不自动制造合并提交。储藏全部改动包含未跟踪文件；弹出储藏可能冲突，先检查结果再继续操作。
遇到冲突时，修改文件解决冲突后再暂存，不把冲突状态当成普通改动直接丢弃。

操作期间按钮可能暂时不可用。失败时查看面板里的错误和操作输出；首次状态加载超时可重试。大仓库或大 diff 卡顿的定位方法见[性能](PERFORMANCE.md)。
