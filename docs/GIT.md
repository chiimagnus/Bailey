# Git 与差异

修改 Git 操作、刷新、提交草稿或 diff 时，保留以下约束。树行交互统一见[编辑器](EDITOR.md#共享树与文件操作)。

## 仓库与刷新

- 仓库身份包含机器与路径，状态、折叠和提交草稿不能串仓库。工作区、索引与历史是不同数据，不能把暂存状态当成工作区状态。
- 刷新由实际事件驱动，合并进行中的请求；保留最后一次有效刷新。操作前的旧快照不能覆盖操作后的状态。
- 结果核对工作范围与请求代次；远端保留批量查询和超时，不退回逐文件往返或无限并行。
- 尚无提交的仓库仍支持状态、未跟踪与首次暂存。首次加载失败或超时须退出等待状态并提供重试。
- 未跟踪行数保留文件数与字节预算，概览数字不代表所有内容都已统计。

## 操作与草稿

操作互斥，执行前校验目标、路径、HEAD 与 upstream；错误与输出可检查，不静默成功。

- 本机执行器与终端共用登录 shell 的选择，首次调用在用户主目录启动交互式登录 shell，加载超时为 5 秒，缓存其导出环境；不在仓库目录执行启动配置。NUL 分隔及唯一标记隔离启动输出，保留含换行或等号的变量，不输出环境内容。启动失败、超时或无有效 PATH 时明确失败，重启后重试，不退回残缺环境执行写操作。
- 所有本机 Git 路径按该 PATH 解析可执行文件，继续用独立 argv 传参，不把文件名、提交说明或分支拼进 shell 命令。保留 `GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0` 与 `LC_ALL=C`，并发排空输出和超时终止共用现有执行机制。远端沿用后端环境，不接收本机变量。

- 暂存写入索引；取消暂存保留工作区内容。重命名须处理新旧路径，路径参数使用 literal pathspec，不把特殊字符当作模式。
- 丢弃普通已跟踪文件从索引恢复，不直接等同于 HEAD；未跟踪删除按[安全约束](SECURITY.md)处理。`GitStatusModel` 在打开确认时记录原机器／仓库／分支／HEAD 与文件指纹，用户确认后重新校验再执行；远端读取失败、文件变化或切换连接都不得回退到本机或执行旧操作。确认文案与取消交互属于 Git 面板。
- 默认只提交已暂存内容，全部暂存并提交和 amend 须由明确选择触发。拉取仅快进，储藏全部包含未跟踪文件；冲突不可当作普通修改自动丢弃。
- 提交草稿在当前窗口按机器与仓库保留，不持久化。失败保留草稿；成功仅清空本次未继续编辑的说明。

## diff

工作区、暂存和历史 diff 分开读取。只有可编辑的工作区文本可保存；保存不意味着暂存或提交。符号链接不作为普通文件写入。

任一侧超过 5 MiB、二进制或非 UTF-8 内容不提供文本 diff。Git blob 读取保留原始字节，不能先解码丢掉 NUL 或无效字节再判断。

同一仓库的 Git 状态刷新暂时失败时，保留上次成功加载的分支、文件状态和提交历史，同时展示错误与重试入口；只有切换目标或确认不是 Git 仓库时才清除旧展示。SSH 换用新连接时立即使旧连接的在途查询失效，不等待旧请求超时或采用其结果。失败信息不是仓库已消失的证据。

diff 标签使用 STTextView/TextKit 原生渲染统一/分栏差异与行内高亮，不用 WebKit 或 PierreDiffsSwift。分栏两侧的水平和垂直滚动双向联动；内容宽度不同则各自遵守可滚动边界，不让短侧把长侧拉回。标签保留原生渲染资源，切换项目或重挂载不丢编辑、撤销和滚动。进入编辑后，之前发起的读取不得覆盖当前缓冲区。异步结果不能覆盖新目标；保存失败与 SSH 断线沿用[文件保存](EDITOR.md#编辑与保存)和[机器身份](PROJECTS.md#机器与连接身份)约束。

## 验证重点

使用临时仓库检查工作区、索引与实际提交结果，覆盖初始提交前、重命名、特殊路径、超时、失败草稿、提交期间编辑与快速切换。diff 覆盖未跟踪、暂存、历史、字节与大小边界，以及真实文本显示、滚动和编辑；桥接完成不代表页面可用。

执行环境检查从精简 GUI PATH 启动，覆盖 shell 启动噪声、导出变量、PATH 中的 Git 与 hook 工具、启动失败和超时；推送须检查临时接收仓库的实际提交，安装 Git LFS 时再核对接收端的大文件对象。
