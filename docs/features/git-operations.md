# Git 历史、引用与工作树操作

维护针对提交、分支、Tag、Worktree 和已有 Stash 的命令及确认。
未提交改动、提交草稿见 [Git Changes](git-changes.md)；选择与展示见 [Git Graph](git-graph.md)。

## Invariants

- **明确目标再执行。** 窗口、机器、仓库、工作树和 Git 对象必须保持有效，确认不可复用到其他目标。
- **保护现有编辑。** 会写工作区的命令遵守 [文件保存](file-saving.md#git-操作前保护)，不强行关闭内容。
- **保留 Git 原生结果。** 不跳过冲突、不擅自强推、不把部分成功伪装成回滚。

## 历史提交操作

提交右键可创建分支或 Tag，或对选定提交执行检出、拣选、撤销、合并、变基、复位及符合拓扑条件的 Drop；
检出会进入游离 HEAD；确认可勾选“总是接受”，后续略过这一步确认，
但不会略过 Git 自身的错误。拣选可记录来源或只暂存不提交；拣选和撤销 Merge 提交时选择主线父提交，
默认第一父。

变基默认忽略提交者日期，交互式变基不使用此选项，而是在新终端运行真实编辑器。
Cherry-pick 按真实父子依赖从旧到新执行，可选择记录来源或仅暂存；
Revert 按反向依赖撤销，Merge 提交需要选择主线的操作在多选菜单中禁用。
Git 序列操作成功后不擅自创建额外提交；冲突则保留原生 sequencer 和恢复入口，
不跳过失败项。Drop 仅对目标 HEAD 第一父链上连续、单父、无额外子分叉且不含根提交的
区间开放；通过单次原生 Rebase 移除该区间，不能用多次 Drop 绕开拓扑约束。
Squash 同样仅允许目标 HEAD 第一父链上的连续线性区间，但可包含根提交，
并在原生弹窗填写新提交信息。提交的 Checkout、Cherry-pick、Revert、Merge、Rebase、Reset、Drop 与 Squash
均在原生确认框选择目标 Worktree，不必切换当前 Project。
只有一个合法目标时，确认框直接显示其路径；多个目标时才显示选择器，
当前 Worktree 排在首位。同一提交属于多个 Worktree 时由用户选择，
不从提交哈希推测归属。
Drop／Squash 仅列出满足选区拓扑条件的 Worktree（包括 detached HEAD），
其它提交操作列出有效 Worktree。执行前复核目标路径、HEAD 和分支；
历史重写还要求目标工作区干净。未选 Worktree 的 HEAD 不变，
但共享分支和 Git 原生 `rebase.updateRefs` 行为仍需遵循。
多选本身不受历史拓扑限制，菜单禁用不符合条件的历史操作。所有写操作沿用原有窗口身份、
保存保护、HEAD 和 Git 实际拓扑复核；不会自动强推远端。
执行前再次从 Git 读取真实第一父链，核对 HEAD、分支、项目及所有待合并提交；
先保存 Bailey 中相关文件，再要求暂存区及已跟踪工作区无改动，未跟踪文件仍由 Git 原生保护。
先按最新选中提交的文件树和最旧选中提交的父节点生成单父提交，
保留最旧提交的作者和日期、尊重签名配置，再通过 Git Rebase 重放范围之后的提交，
核对最终文件树及提交数量。原提交的 Branch／Tag 不强制移动，其他本地引用遵循
`rebase.updateRefs`；不会自动强推远端。Rebase 冲突或 Hook 失败保留 Git 原生恢复现场。
Reset 默认 Mixed，也可选择 Soft 或 Hard；Soft/Mixed 不写工作文件，不要求保存无关的工作区编辑。
Hard 先完成保存保护，再按 Git 原生规则覆写。
Drop 不额外禁止 Tag 或同节点 Ref，detached HEAD 同样适用。

合并默认即使可快进也创建提交。压缩合并优先于此选项；
自动提交的 Squash 必须在开始前确认索引没有原先暂存的内容，否则拒绝操作并保留 HEAD、
索引和工作区（可先提交或取消暂存）；选择 No Commit 时仍由用户自行处理暂存。
没有选择“不创建提交”且 Squash 新增了暂存差异时，使用 `Merge commit '<完整 SHA>'` 创建单父提交。
允许快进时，“不创建提交”并不阻止 HEAD 前移。冲突及 Hook 失败保留真实 index、工作区和错误，
仍在现有终端继续、跳过或中止相应 Git 操作。

弹窗绑定发起窗口、项目、机器、仓库和明确选择的 Worktree，
确认及异步预检后重新核对。
会改工作区的历史操作先等待目标 Worktree 同一机器的文件和 Diff 保存；
失败或保存期间再次编辑会停止，标签不关闭。执行前发现新编辑、在途写入，
或正文虽干净但编码转换仍有保存错误时也会拒绝；
已开始的 Git 进程不声称能锁住外部 CLI。操作结束重读干净标签，包括可编辑但没有未保存改动的工作区 Diff，
不覆盖新的未保存文本。

Branch 和 Tag 的同名替换确认固定被替换对象；确认期间若引用被其他工具移动，即使列表已经刷新，
也会拒绝旧确认。重新打开确认后才能替换新目标。

## 本地分支与归档

尚未在任何工作树检出的本地分支，右键才提供「创建工作树…」。
用户输入绝对路径后调用 `git worktree add -- <路径> <分支名>`，不会新建分支，也不会切换原工作树。

已检出的工作树由对应分支标签的「工作树」右键子菜单管理：可在 Bailey 中打开、定位或移除；
只有本机工作树提供「在访达中显示」。多工作树共享 HEAD 时先选目录；
没有关联分支时，使用具名 Worktree 标签的右键菜单。标签单击只展开历史详情，不会打开项目。
SSH 工作树始终在原远端机器上打开。

移除前显示完整路径和分支并请求确认。仅执行 `git worktree remove -- <路径>`，不使用 `--force`，
也不删除 Git 分支。主工作树、存在未提交改动、锁定或等待清理的工作树不能移除；
仍被 Bailey 的项目、终端、文件或 Diff 标签使用时也会拒绝。

项目目录与终端沿用项目面板的机器范围，文件和 Diff 则按标签自身的机器判断，不被项目过滤。
SSH 项目中的本机文件同样保护本机工作树；
固定 SSH 终端也不会因握手前身份为空或实际连接使用主机名而丢掉项目别名下的保护。

创建前校验当前机器、项目、HEAD 和所选本地 Ref OID，并重读 Worktree 列表确认分支未被检出；
删除前重新读取列表、选中工作树的路径/HEAD/分支/主工作树和锁定状态以及真实文件状态，
外部变化、查询失败或未提交文件均拒绝。缓存可继续只读显示，但 Worktree 列表重新成功核验前不授权操作。
与现有 Branch/Tag/Stash 菜单及其 Git 操作日志、互斥和自动刷新机制共用数据流；
Worktree 删除和 Branch 删除保持明确独立。

在历史提交新建 Branch 时可输入名称并选择是否检出，**默认不检出**；
顶部的「新建分支」沿用从当前 HEAD 创建并检出的默认行为。已存在同名 Branch 时会询问替换或重新命名；
只有确认替换才强制移动该分支引用，Git 对当前检出分支或其他 worktree 的拒绝不会绕过。
检出前先保存属于同一仓库和机器的未保存编辑，保存失败不切分支、不关标签。

当前和其他本地 Branch 的操作绑定所选 Ref 的名称、OID 和原仓库。Rename 不覆盖重名分支；
Delete 默认不用 Force，也不删远端。若普通 Delete 因尚未合并被拒绝，会单独询问是否强删；
选择「同时删除远端」会列出已知的同名远端跟踪分支，只有本地删除成功才逐个向这些远端请求删除。
中间某个远端失败不会阻止处理后续远端，操作日志保留真实的部分成功结果。

切换分支绑定菜单选中的原始本地 Ref OID；确认执行前若同名分支被外部移动则拒绝旧操作。
Graph、分支菜单与底部工具栏共用当前窗口的切换事务：
执行前核对当前窗口、项目和 Ref，保存所有 Bailey 窗口中同一仓库的相关编辑；
同一文件存在互相冲突的未保存草稿时拒绝执行，保存失败或 Git 拒绝时保留现场，
成功后重载所有受影响窗口的文件和 Diff。
Diff 接受不同的磁盘内容时清除旧文档的原生撤销记录，避免撤销使用失效的编辑范围；
同内容保存与原生视图重新挂载保留撤销历史。
仍按 Git 标准分支名校验，外部工具写入的非标准 Ref 不能被解释成命令选项或“上次分支”简写。

Branch Push 可选一个或多个远端，默认目标依次参考所选 Branch 的 `pushRemote` / `remote`、
仓库 `remote.pushDefault`、`origin` 和首个远端。默认设置 upstream；
模式为普通、`--force-with-lease` 或明确选择的 `--force`。依次推送，首个失败即停止并记录未执行目标；
最后一次成功设置 upstream 的远端为最终追踪目标。非当前分支使用完整 Ref，不推送当前 HEAD 或同名 Tag。
仓库没有配置任何 remote 时会显示原因并禁用 Push 确认，而不是点击后无响应。

Branch、Remote Branch 与 Tag 的「创建归档」只生成 ZIP，macOS 原生保存面板只选择文件名和位置，
内容来自**确认时所选的 Git 对象**而非当前 HEAD。生成完成后才原子替换文件；失败不能损坏已有归档。
本机使用 Git 的登录环境，SSH 在原机器生成临时文件后有界传输（最多 64 MiB），
远端断线或清理失败明确报告残留路径。Remote Branch 按当前已知的远端跟踪 Ref 内容导出。

## 历史文件操作

历史文件点击／Space／Return 浏览 Diff，右键不重复「Open Historical Diff」；
仍可在非删除的普通历史文件菜单中读取原文（只读）、与当前工作区比较、
打开现行文件或恢复历史版本。历史目录和其他 Worktree 文件仅用于导航／浏览 Diff，
不显示路径复制菜单；已删除历史文件仅保留 Diff 浏览。
Tree 和 List 使用同一批历史文件变更；同一提交中旧文件／gitlink 被删除、目录复用其路径时，
Tree 中旧文件与新目录独立显示，展开与键盘导航都能访问目录下的新增文件。
折叠目录不隐藏同路径的旧文件；文件操作始终作用于原始 Git 变更而非推导的目录。
若历史路径已经被重命名，先使用 Git Index 与历史提交的重命名记录定位；
直接比较因累计内容变化无法识别时，再按历史提交→HEAD→Index 串联两次确实发生的重命名，
并验证最终文件存在。定位时不对实时工作区运行 Git Diff：
其 clean filter 可能仅因浏览历史文件就新增 LFS 对象。
原路径仍存在时不凭猜测打开其它文件。读取 Git blob 失败与文件不存在必须区分；
二进制、错误 UTF-8 与超过 5 MiB 不显示伪造文本，但二进制文件仍可通过真实 Git 恢复。

「恢复文件到此版本」明确提示将同时覆盖此路径的 Git index 与工作区，
经确认后执行 `git --literal-pathspecs checkout <SHA> -- <path>`。
先核对确认打开时的文件状态，再完成未保存编辑的保存保护；自己的保存不算外部改写。
首次 Git 覆写前再次核对准备后的文件状态和原 index；外部修改、保存失败或新编辑都会拒绝操作。
成功后只重读干净的打开标签，HEAD 与其他历史引用不改变。
保留现有文件树的原生命中、图谱线和独立横向滚动。

历史文件的行为回归分为两层：`NativeGitHistoryFileTests` 在受控真实 Git 仓库中核对 revision、重命名、
索引／工作区快照、SHA-256、5 MiB 上限和错误／竞态；
`GitHistoryUITests` 经真实 Git Graph 的历史文件入口核对只读原文、取消／确认恢复及最终 Git 字节。
`NativeDiffTabTests` 保留原生文本的辅助功能只读写保护组件契约。
图谱历史文件具有独立 AX 行标识，防止同一路径的 Git Changes 行抢占历史菜单。

## 远端分支操作

右键远端 Branch 或在 `+N` 菜单中选择相同操作，均绑定**实际 remote、完整分支路径与选定 Git Ref**；
有多层路径或 remote 名称自身包含 `/` 时按配置识别最长匹配 remote。
`origin/HEAD` 及其它符号远端引用按 Ref 快照的 `symref` 判定，只作为可查看、
可复制名称的引用别名显示，不提供检出、Fetch、Merge、Pull、删除或归档操作；
真正名为 `HEAD` 的非符号分支仍正常显示与操作。

Checkout Remote Branch 默认以远端分支名创建本地跟踪分支并切换，创建前保护同一项目尚未保存的编辑。
同名本地分支出现时不会自动覆盖，而是选择“重新输入名称”，或明确“切换现有分支并拉取”。
两条路径都先校验标准分支名，不把外部特殊名称当作 Git 选项或“上次检出”简写。
后一种操作的切换已成功、拉取失败属于**部分成功**：保留当前分支、Git 冲突与错误，不假装撤销。

已有同名**非当前**本地分支时才提供 Fetch into Local Branch，默认不强制。
它获取服务器最新分支，但执行前核对表单打开时的本地目标；
期间本地分支被移动，即使勾选 Force Fetch 也拒绝旧确认。
重新确认后可强制更新，仍不能修改其他 worktree 正在检出的分支。

Merge into Worktree 使用历史提交相同的原生目标工作树表单；
Pull into Current Branch 独立提供 No-FF 和 Squash（默认均关闭），
不会混用顶部只允许快进的 Pull 快捷键。Squash 仅在确有暂存差异时创建单父提交。

删除远端 Branch 只作用于该 remote 的完整分支路径，服务端拒绝、认证错误或保护策略不被绕过。
若服务器已删除该分支，Git 原生删除流程会清理**同一个**本地 remote-tracking Ref，
不影响其它 remote 的同名分支。Archive 使用本次所选跟踪 Ref 的对象，
不会先 Fetch 或擅自选取服务器上可能已移动的分支。

## 标签（Tag）

历史提交「添加标签」默认创建**带注释的 Tag**，可填写多行注释，也可选择轻量 Tag；
切换类型保留尚未提交的注释输入。已有同名 Tag 时明确选择替换或保留输入重新命名；
只有确认替换才强制移动本地 Ref，不自动强推远端。支持创建后选择一个远端推送，默认不推送；
取消后续推送保留已成功创建的本地 Tag。

Tag 右键根据 Git 的实际对象类型显示「查看详情」（仅带注释标签，显示创建者/日期、标签及提交对象、
注释与签名验证结果）、「删除标签」「推送标签」「创建归档」「复制名称」。
菜单绑定最初的完整 Ref 与 Tag 对象 OID；带注释 Tag 即使被替换为指向同一提交的新对象，
旧菜单也不会作用于新 Tag。删除默认只改本地；
选择一个远端时**先请求远端删除，成功才删除本地**，服务器拒绝则保留本地 Tag。
推送可以选择一个或多个远端，默认依次采用仓库 `remote.pushDefault`、`origin` 或首个远端，
不使用当前 Branch 的设置。按选择顺序执行、首次失败即停止，不使用 `--tags` 或隐式 Force。
其他同提交 Tag 不受影响。

推送前通过已存在的本地 remote-tracking 分支判断远端是否已知包含该提交；
不因这个启发式自动 Fetch 或断言服务端一定缺失。查询失败会报告错误并停止，不当作允许推送。
可能未包含时先询问是否仍要推送，可选择继续或取消；「以后总是继续」默认不勾选。
这一选择仅关闭相应警告，不修改服务端权限或 Git 推送错误。
创建后立即推送前先读取实际 Tag object OID 并核对它仍指向所选提交，不等待状态缓存碰运气。
归档沿用 Branch/Remote 已有的 ZIP 原生保存路径。

## 具体储藏（Stash）

右键某条储藏可应用、弹出、从它创建分支、删除或复制名称／哈希。
应用与弹出默认不恢复暂存状态，勾选 Reinstate Index 才带 `--index`。
应用使用选中对象的固定 OID，但旧 selector 移位或记录变更时同样拒绝执行，
不能以 OID 仍存在为理由把旧菜单操作带到新 Stash 列表；成功应用不移除条目。
弹出及创建分支只在 Git 成功后移除相应储藏，
冲突保留真实工作区、index 与 reflog。创建分支会检出该新分支并恢复变更，不只是创建一个 Ref。

弹出、删除和创建分支必须使用 selector；
对话框打开时保留整份储藏列表，执行前在同一互斥操作中重读列表核对 selector、OID 和记录说明，
外部新增／删除或同 SHA 条目移位时拒绝并要求重新选择。
这不是外部 CLI 的跨进程原子锁。顶部「弹出最新储藏…」捕获显示时的首条身份，使用同一表单及校验，
不再盲弹当前栈顶。应用、弹出及创建分支走现有保存／重载保护；仅删除 reflog 的操作不保存无关编辑，
也不自动清空冲突。

## 验证

`GitCommitActionTests` 使用真实仓库核对批量 Cherry-pick、Revert、Drop、Squash 的依赖顺序、
HEAD、作者、文件树、提交数、索引选项、非法拓扑与过期目标拒绝，以及部分冲突后的原生 Abort 恢复。
`GitBranchActionTests`、`GitTagActionTests`、`GitWorkspaceActionTests` 验证相应操作的真实结果；
`GitRemoteBranchActionTests` 核对确认期间 Fetch 目标变化、Force 重试与正常快进；
`GitStashActionTests` 核对 Stash 身份及 Pop／Drop／Branch。

`GitNativeDialogTests` 检查实际 NSAlert 的默认选项、按钮联动、目标选择及取消。
`GitDialogUITests` 保留完整 Bailey Dev 的 Graph → 菜单 → 原窗口 Sheet → 实际 Git 操作，
包括多选、跨窗归属和交互式 Rebase。交互式 Rebase 使用 `/bin/sh -c` 内联编辑器，
