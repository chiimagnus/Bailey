# SSH 工作区

SSH 后端让文件和 Git 面板直接操作远端项目，不要求挂载文件系统。
连接、远端命令或目标绑定改变时更新本页；长期转发另见 [tunnels.md](tunnels.md)。

## Invariants

- **远程失败不能回退写入本机。** 同名路径不是同一文件，读取、保存、删除和 Git 操作都不能换目标重试。
- **标签保留创建时的机器。** 主机、端口、连接与路径一起参与身份；当前终端变化不能偷偷改写标签目标。
- **断线保留编辑。** 文件及可编辑 Diff 转为只读，已输入内容、撤销与错误仍在。
- **换连接立即失效旧请求。** 同一机器重连或切到另一条可用通道也要重新绑定，不要求先经过只读状态。
- **主机信任失败不能绕过。** 不关闭校验，也不借用用户正在工作的连接进行测试。

## 连接与后端

终端中的手动 SSH 仍由终端自身检测连接和归属，但不会把本机项目的 Files、
Git 根目录变成该终端的远端工作目录。
远端文件和 Diff 只由明确创建的 SSH 项目主机驱动重连后的读写状态。

GUI 与使用私有握手的隔离测试都显式调用 `WorkspaceApplication.connectServices()`，
让 SSH 和通知查询同一个应用所有者；测试结束恢复原绑定。构造 owner 本身不重绑共享服务。

复用既有 OpenSSH 配置、密钥和工作区 master。
GUI 启动时将应用级 `WorkspaceApplication` 显式提供给已存在的 `BaileySSHService`；
私有 handoff 经 token、终端 ID、端口和 PID 校验后，仅查找该所有者内仍存活的 Session，
不能遍历窗口单例或误交给测试宿主的其它所有者。交互会话与文件／Git 操作不是同一条生命期路径：
终端仍能输入，不足以证明后端连接正常。

固定 SSH 主机的新终端与 Files/Git 使用相同的 OpenSSH `ControlMaster=auto`、
`ControlPersist=180` 以及按有效主机、用户、端口与跳板隔离的 `%C` socket；
标签关闭不主动关闭共享连接。固定主机的文件／Git 后台命令在新建 SSH 连接时启用标准压缩，
已存在的 master 不重新协商。后台命令使用 `BatchMode=yes`，不弹出交互式认证，也不跨机器回退到本机。
Files 全折叠时首次只读取根目录，恢复已展开层级或点击子目录时按需读取，
目录压缩不会触发额外的深层扫描；刷新已缓存目录时批量读取。
网络读取由后端异步执行，已读取目录优先使用缓存，失联保留原内容与绑定。

固定 SSH 主机使用 `ControlMaster=auto`，
旧连接失效时可能通过现有 OpenSSH 密钥新建**无需交互认证**的连接；仍不绕过主机密钥校验。
用户在 Shell 中手动建立的 SSH 会话不被接管。真实 SSH 验收必须使用测试专属 socket，
不借用或关闭用户 master。

本机工作区的进程后端必须同时排空 stdout／stderr，并以单调超时限制完整读取与直接子进程的存活；
即使后代继承管道且父进程已退出，也不得无界等待 EOF。
超时只终止该次创建的子进程，不清理用户终端、SSH master 或其它任务。
SSH 命令的 stdin 写入同样要能在对端不读取、父进程先退出时按截止时间结束。

Finder 的本机文件 URL 只适用于 Bailey 本机终端。
固定 SSH 项目的 Shell **在建立连接前**就有远端启动意图，
不以尚未设置的 `workspaceIdentity` 误判为本机；已连接及断线未退出的 SSH 终端同样拒绝插入 Mac 路径；
用户自行启动、未经过 Bailey 接管的前台系统 `ssh` 进程也拒绝本机文件投放；
`exec ssh` 保留根 PID 时以系统实际可执行文件而非 PID 是否变化判断，真正退出回到本机后才恢复。
SSH Files 树条目不会向 Finder／其它本机应用导出伪造的 Mac 文件 URL，路径仍可用「复制路径」。
普通窗口外部打开 Mac 文件只创建或复用本机 `FileTab`，即使标签位于当前 SSH 项目也仍读写 Mac，
不因同名远端路径更换机器或隐式上传。

远端外部工具不会触发终端的命令完成事件。
**Windows 固定 SSH Files** 使用独立、可取消的临时 PTY 接收系统文件通知；
订阅就绪且首次读取成功后才暂停健康态 2 秒轮询，通知失效则回退，不安装远端服务或占用用户 SSH master。
支持范围和异常恢复由 [Files 自动刷新](files.md#自动刷新) 详细维护。

**SSH Git** 仍在前台可见时每 5 秒检查，见 [Git 刷新](git.md#刷新与显示)。
文件事件不能替代连接存活或终端工作目录探测。

已接管的 SSH 终端另每秒检查本机 SSH 进程和控制 socket；
健康连接约每 2 秒进行一次真正到达远端的存活探测。
**它不是 Files 或 Git 刷新**，不能在缺少等价断线检测的情况下删除。

交互式变基是明确创建的新终端，拥有独立的 SSH 连接。固定 SSH 项目捕获原机器、端口和 Git 根；
握手前暂存启动目标，握手后由真实 RemoteConnection 接管。
以普通登录终端接收原生启动输入，不把复杂远端 command 的 Windows 参数重组当作 POSIX 语义。
连接或会话结束后保留断线目标与结果，不回退操作 Mac。

Git Ref 归档在所选 SSH 工作区的临时目录生成，经 Git 原生进程写入后，
通过已有后端一次有界读取保存至 Mac：传输限制为 **64 MiB**，超限不替换目标文件。只清理本次临时目录；
断线导致清理失败时保留具体远端路径和失败反馈，不把 Mac 路径交给远端或反向写入。

SSH 项目的 ⌘P 直接使用当前远端 Git/文件后端索引，只展示该机器的项目文件；
Git 报连接或权限错误不转为全树扫描，目录遍历和 Git 输出都有上限，结果不完整会提示，
打开前再次核对当前连接。Finder 和 Files 的 `files.exclude` 不改变这一搜索范围。

远端命令要求 POSIX shell 与相应 GNU 工具。Windows 支持依赖 MSYS2 路径和 shell，
不承诺原生 PowerShell 命令兼容；路径转义与参数边界必须由后端处理。
文件写入须确认全部输入字节已传给子进程；
子进程提前关闭输入时报告失败，不能把进程正常退出误判为保存成功。

## 断线与恢复

发布异步结果、开始副作用以及保存完成回写时，都核对当前绑定。
旧通道的保存结果不能清除新通道／新目标的未保存标记。
重连只恢复原机器上的操作能力，不通过创建另一份编辑缓冲来“修复”状态。

固定 SSH 主机的命令结果也会通知项目重绑文件与 Diff；
Files／Git 的异步发布同时核对当前项目许可、`PanelContext.Identity` 和本次请求代次，
不依赖整个窗口模型在后台查询中保持可用；
已知断线不再被当作可写后端，首次连接状态未知时仍允许原机器初读。
同一固定 SSH 机器重连失败不会清空此前可信的 Files 行及选中项；
在新通道根目录列举成功前，旧显示项不能直接移动、删除或重命名。
已消费的文件在重连后恢复读取，未被消费的恢复标签不因此预读。面板查询或重新选择标签可探测原主机，
成功后恢复原缓冲的操作资格；没有后台重连循环。

远端文件复制在同一台远端机器的目标卷上制作私有临时副本，随后通过已有的无覆盖重命名发布；
普通文件、目录与符号链接按原类型复制。失败不删除源，当前不支持跨 SSH 主机或从 Mac 向 SSH 上传。
真实 SSH 传输需要获授权的临时远端目录验收；本机 shell 模拟不能冒充实机。

远端删除不进入本机废纸篓，需在发起窗口明确确认。
缺失路径返回失败而非假成功，删除符号链接不会递归删除其目标；
操作前确认范围和可恢复性，不能承诺像本机文件一样从废纸篓找回。
安全边界统一见 [SECURITY.md](../../SECURITY.md)。

## 验证

`RemoteCommandsTests`、`RemoteLifetimeTests`、
`WorkspaceIdentityTests` 和工作区身份回归检查 SSH 批量目录读取、复用参数、绑定、取消、
失败与过期结果。`FileTabPersistenceTests` 的受控后端还检验文件断线、重连、目标变更、
保存失败和过期读取不会丢稿或错写；
`NativeFileTabTests` 通过固定主机的 `SSHHostWorkspaces` 状态验证原生编辑器的只读、缓冲与 Undo，
不用终端 `RemoteConnection` 模拟 Files 断线。受控后端只能证明这些逻辑，不能证明真实传输；
`SSHFileTreeLiveTests` 使用专用、获准的 Windows SSH master 检查特殊目录名、批量读取、
单目录失败隔离和文件树冷加载／缓存展开／批量刷新各自的 SSH 请求次数；
显式 `BAILEY_SSH_BENCHMARK=1` 时再测冷加载与 30 次热路径的中位数/p95。
`SSHGitRecoveryLiveTests` 使用另一个专用 master 和 Windows 临时仓库，模拟仅该测试传输失联，
验证 Git Graph 保留、写操作拒绝、恢复后重新允许暂存；
显式开启 `BAILEY_SSH_BENCHMARK=1` 时测首次 Git 核心/详情耗时和 30 次热刷新。
不会切断用户或系统网络连接。测量不代替完整 App 视觉响应或原生网络异常的 UI 验收。

归档的验证分层：模拟 SSH 后端覆盖传输上限与远端清理失败；
`GitWorkspaceSSHTests` 在真实 Windows SSH 中核对选定 Ref 的 ZIP 原始字节，
远端分支经原生保存面板归档仍需单独验收完整 App 操作。
这些成功路径不代表断线时完整 App 的清理与恢复已完成验收。

实现边界：[WorkspaceBackend.swift](../../Bailey/Workspace/WorkspaceBackend.swift)、
[RemoteCommands.swift](../../Bailey/Remote/RemoteCommands.swift)。
统一运行方式见 [testing.md](../testing.md)。
