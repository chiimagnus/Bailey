# 原生文本编辑器

本页维护原生源码缓冲、编码、输入法、Undo 和文本布局，供文件和 Diff 共用。
[文件查看](file-viewer.md)、[查找替换](find.md)及[保存与关闭](file-saving.md)各自维护共享契约。

## Invariants

- **唯一正式编辑器是 Apple 原生 NSTextView + TextKit 2。** 文件与 Diff 都复用同一原生控件，
  不引入 STTextView、CodeEditTextView 或第二套编辑器。
  优化不能损失输入法、撤销、命中、保存、辅助功能与行号。
- **编辑内容属于长生命周期标签。** 文本、保存基线、原生编辑器、撤销栈、
  光标和滚动不能由临时 View 持有。
- **按标签 ID 保留原生文档。** 切换或移动复用原有编辑器，真实关闭才释放旧文档。
- **未保存状态逐字节精确。** 原生小范围编辑先用 UTF-16 变更量快速判定，
  缺失可靠替换范围的 Undo／IME 则以有界 UTF-16 块严格逐单元比较，
  不在主线程构建全文字符频数字典或复制完整 UTF-8 缓冲。
  Unicode 规范等价但原字节不同仍需保存；撤销回原字节必须清除标记。
  保存和外部消费者按需读取完整正文，不在普通输入后无条件回写全文。
- **保存失败保留编辑。** 详见[文件保存](file-saving.md)。
- **旧读取不能覆盖新编辑。** 只有干净文件可重载，回写还要核对目标、请求代次和当前编辑状态。
- **展示与真实输入分离。** 文件在某个分屏展示，不等于其 NSTextView 已成为第一响应者；
  局部选区、IME、查找与 Undo 由所属内容管理，外部浏览请求不擅自把键盘从 Files／Git 抢走。

## 读取与编码

可编辑文本原始字节不得超过 32 MiB（含 BOM），不含真实 NUL 字符。
文本优先识别 UTF-8、UTF BOM 和文件开头声明的编码（Python `coding:`）；
Windows Abaqus 的 `mbcs` 按**远端 Windows 系统 ANSI 代码页**读取，不取 Mac 的默认编码。
无声明且无法用 UTF-8 解码时不猜 GBK；可从文件中选择「以编码重新打开」。
编辑器保存沿用加载时的编码；「以编码保存」需严格可往返编码，
字符不可表示或与现有 `coding:` 声明冲突时拒绝写入并保留草稿。
保存前还会按**编码后的最终字节数**验证 32 MiB 限制（包括 BOM）；
超限拒绝写盘且保留原文件与草稿，避免保存后变成无法重新打开的文件。
重新打开编码须先保存或处理未保存草稿，不能静默覆盖编辑。
二进制、编码未知、过大、读取失败分别报告原因；[Diff](diff.md) 另有独立上限。
已打开的文本刷新时若编码未知或解码无效，保留有效正文、显示错误并拒绝过期保存；
文件确实删除或变成二进制时则按新文件状态清除旧正文，不冒充仍可编辑的文本。

## 原生正文与重载

`FileTab` 持有唯一可写的 `NSTextStorage`／`NSTextContentStorage`；原生视图只挂接此正文，
不保留第二份 Swift 文本缓冲。TextKit 2 的编辑通知可能扩大到整段落，
普通输入和 IME Undo 均以编辑前实际替换范围、长度与写后字符校验增量，不能逐键全篇扫描。
标签切换器的文件缩略预览仅截取最多 7,000 个 UTF-16 单元。
文件身份、按需读取、刷新合并及重连由[文件查看路由](file-viewer.md#按需读取与重载)统一维护。

干净文件刷新失败且原文已加载时继续显示原文与原生编辑器，并标明上次加载的内容；
在成功刷新前临时只读，不能把旧版本写回磁盘，仍可选择、复制和查找；
文件确实不存在、超限或变成二进制时仍按对应不可用状态处理。
成功重读后清除提示，脏编辑或断线使旧读取和待补读失效。只有磁盘内容确实改变时才替换原生文档；
同字节刷新不丢原生编辑器、光标、撤销。接受不同版本（包括文本变二进制）按下文退役旧原生文档。
字节、UTF-16 与行列坐标要一致，包含中文、emoji 和 CRLF。

## 原生文本布局

远处选区须滚动至实际可见区域，不以缩短文档强制定位；`EditorState.scrollY` 记录原生滚动位置。
查找浮层遵循[独立布局契约](find.md)。

`NSTextView` 文档视图与 `NSTextContainer` 必须同宽且有限，外层滚动视口可以更窄；
只扩大容器会导致 TextKit 2 提前创建大量段落。

### 行高与滚动范围

不折行且实际行高一致时，编辑器用原生行分隔位置与实测行高保持文档高度稳定，
并通过同一原生视图的坐标转换对齐文字、选区、命中和行号，不改字体、行高和用户段落间距。
行长度与段落分隔信息只在初次需要时建立，并用前缀索引查找行起点及段落序号；
普通局部编辑只更新受影响行，不再平移后续所有行。不折行的水平范围由实际字体测得的各行宽度决定，
不能用 UTF-16 长度乘固定倍数扩大文档。
冷加载的全文测宽在后台执行，并发度最多占当前可用 CPU 的一半，
避免低核数机器的字体排版任务挤占主线程响应。

### 超长行

超长行绘制宽度由「文本编辑器 → 超长行显示宽度」控制，
默认 12,288 点，另提供 8,192、24,576 点和「完整显示」。
仅超出显示宽度的部分以原生省略号截断，始终只占一个视觉行；原文、复制、编辑、撤销和保存不截断。
「完整显示」不截断任何字符；超过 24,576 点的行在此宽度后自动换成后续视觉行，
避免 TextKit 2 在自然宽度达到数万点时漏画整行。普通「自动折行」则按视口宽度折行。
偏好以 `editor.long-line-width` 保存在 `config.toml`，非默认值分别为 `8192`、`24576`、`-1`；
修改即作用于现有文件编辑器及只读、可编辑 Git Diff，无须重建文本缓冲；
分栏 Diff 的对齐限制见[Diff 布局](diff.md#折叠与滚动)。

### 测宽与视口

文字宽度缓存随局部编辑增量更新；
初次测量顺序遍历已有段落索引，按有界 UTF-16 缓冲批量识别等宽 ASCII。
非 ASCII 和 Tab 仍由真实字体测量；固定字宽字体下仅 ASCII 数字不同的行可以复用整行实测宽度，
不以片段宽度相加替代字形排版。首次加载不折行的 FileTab 时，
在后台以冻结的原生字体描述符和实际正文计算所有行宽；长文档最多并行四个独立测量区段，
按原始行序合并结果。只有加载代次、正文长度、行数、字体及折行设置都匹配时，
首次挂载才接受测宽快照；挂载前的编辑、重载、关闭和字体变化都会使旧快照失效。
这避免了复杂 Unicode 文本首次挂载时在主线程连续进行整篇 CoreText 排版，
但后台计算仍需时间，且 Git Diff 及已显示文档的字体切换目前仍采用各自原生测宽路径。
普通编辑按原生行索引局部更新缓存；切换到折行模式暂时保留已测行宽，
折行期间的编辑仍更新该缓存，返回不折行时不重复测量整篇。字体或正文版本确实不匹配才重算，
不复制整篇文本。
缩短或删除最宽行后立即收回多余范围，撤销、字体与窗口尺寸变化后重新取得正确范围，
同时保持文档视图与 TextKit 2 容器同宽。首次装入正文后在首帧绘制前同步确定宽度；
Diff 共用显示策略；标准宽度保持固定行高与删除行间距，完整显示则按实际折行高度计算。
增删换行时重建受影响的索引结构，仍正确处理 CRLF 合并、
LS 与段落分隔的区别、末尾空行；滚动时不再为行号枚举全文前缀。它不代替 Tree-sitter 的 LF 索引。
共用原生文本视图设置固定文档高度后，首次挂载与窗口调整尺寸也必须立即同步实际视图高度和滚动限制；
短正文至少覆盖可点击的视口，不能靠一次初始设置假定 AppKit 后续不会调整 frame。
视口替换旧渲染视图、行高检查及滚动锚点都只遍历当前已附着的布局片段，不扫描历史布局片段映射；
这不表示 TextKit 2 底层段落缓存已受控。折行、可变行高或超长段落产生额外视觉行时仍使用原生估算，
并按实际可见文字保持阅读位置；不逐屏排版全文。
卸载或更改字体时保留文字锚点，重新挂载不重放旧字体的像素位置。
首次安装正文不追随默认插入点，避免覆盖保存的滚动位置；正常编辑仍跟随光标。
首次布局、Dock 重挂载和窗口尺寸变化可能触发异步几何更新：
`RestorableScrollView` 必须在重排和 `tile()` 前取得原滚动位置，完成后按新的合法范围恢复；
不能先以 `scrollRangeToVisible` 预跳转再恢复像素坐标，因为后续异步跟随会覆盖用户的阅读位置。
重挂载后的验证要同时核对原生文字像素、滚动位置、原对象身份与 Undo。

## 行号与编辑事件

若原生视图绑定的是已填充的 `NSTextContentStorage`，
其初始行索引必须来自已有正文，不能假定从空文本开始；标签真正接管这种预加载来源前仍须通过完整宿主验收。
行号使用增量的本地行起点索引，
Tree-sitter 的 LF 行列索引独立于 TextKit 的自然段落。
行号栏与正文使用相同主题背景、选中行颜色和用户设置的代码字体；按最大行号位数和数字宽度布局，
两侧各保留 6 pt，数字右对齐，不为短文件强制额外最小宽度。
空文件的第 1 行及以 LF／CRLF 结束的末尾空行必须显示行号；光标位于这些位置时正文与行号栏同步高亮。
跨行文字选区保留每个实际被选中行号的强调文字颜色，但不绘制光标专属的行背景；
选区在下一行行首结束时，不误强调尚未选中的下一行。
普通文件的行号栏是独立的原生 `NSView`，与正文 `NSScrollView` 并列：行号固定在左侧，正文横向滚动，
`textContainerInset.width` 为零。行号栏按字体和行数调整宽度，纵向滚动同步重绘；
绘制裁剪到自身边界，不能覆盖正文。验收检查文字像素、行号位置与往返横滚后的固定边界。
从 `NSTextStorage.didProcessEditing` 得到真实编辑范围和替换后的文字，
避免系统 Undo/Redo 绕过 `NSTextViewDelegate.textDidChange` 导致脏状态和语法解析不同步。
共享编辑器的原生 UTF-16 段落索引同时增量维护分隔符种类，
向子类编辑回调提供自然段落数或分隔符类型是否变化的事实；
Diff 以此失效几何，CRLF 与裸 CR 的转换即使行数不变也正确处理，不能逐键全文扫描。
Files／Git 接收同一原生后置事件；有前置替换通知时须按 UTF-16 范围及原始字节
确认两次事件对应，缺失或不一致时走真实字节比较，不把旧前置通知套用到下一次编辑。
初次安装 Git 原文不是用户修改；仅后台 Diff 快照和保存需要读取整篇可写正文。
组合输入使用实际 UTF-16 替换范围记录一条 Undo 事务，
不为一次局部输入复制全文；原生候选结束时只将最终保留的编辑写入撤销历史。
离屏追加也必须拥有独立可撤销操作。

普通未折行源码的辅助功能行号和行文本范围查询不排版视口之外的前文；
折行、分页符和折叠 Diff 仍由 AppKit 按实际布局回答。

## 文档退役

AppKit 经 `NSTextViewDelegate.undoManager(for:)` 使用各标签的撤销管理器。
Undo／Redo 归当前原生文档代次所有，普通重挂载和相同内容刷新不换撤销栈；
接受不同内容重载时退役旧编辑器、停止原生撤销注册并创建新栈，旧宿主不能获取新文档的撤销记录。
真正退役的原生文档须禁止后续输入、清空 Undo／Redo 与语法任务，
并清理编辑事件和焦点回调。Neon 已排队的异步着色回调可能晚于正文释放；
Files 与 Diff 退役时先断开语法适配器、清空旧正文，再解除旧滚动宿主的文档视图和 TextKit 布局管理器绑定；
AppKit 即使保留旧视图也不能继续绑定旧正文。临时重挂载不得执行退役流程。
同时移除旧 `NSTextStorage` 编辑观察者；AppKit 缓存的无主视图不得持有旧正文、Undo 或解析器。
窗口关闭后 AppKit 可继续保留**已分离、已清空且不可编辑**的视图对象，
因此验收应检查标签／内容所有者释放、旧缓冲字节归零与语法任务停止，而不是以弱视图立刻析构作为唯一标准。
不能引入多段合并占位、无效缓存清理或丢全文的内容管理器来冒充优化。

语法解析、查询及着色由[语法高亮](syntax-highlighting.md)维护。

## 输入法与程序化编辑

组合输入结束标记时保留正文并清除临时样式；输入法交付最终文本时才替换组合范围。
首次默认替换使用当前完整选区，后续默认范围与显式替换使用同一正文坐标，
不能把已删除的组合长度再用于删除后续文字。直接确认与替换已有内容只生成一次可撤销编辑，
撤销恢复输入前的原文，重做恢复最终输入。输入法候选框在编辑器已拆卸时不再读取失效窗口，
跨多行查询返回首行实际字符范围。

Git Ignore 离屏追加复用普通 `.gitignore` 标签的原生缓冲，仅读取行尾格式，不拷贝全文。
干净缓冲先刷新磁盘内容，刷新失败即停止追加和保存；未加载时等待共享初读，不把空缓冲当作文件。
追加拥有独立撤销记录，已有未保存文本一同串行保存；失败保留草稿。
