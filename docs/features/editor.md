# 文件编辑器

本页维护读取、文本缓冲、保存、重载和高亮的契约。修改这些路径或原生编辑器集成时同步更新；树与文件操作见 [files.md](files.md)。

## Invariants

- **唯一正式编辑器是 Apple 原生 NSTextView + TextKit 2。** 文件与 Diff 都复用同一原生控件，不引入 STTextView、CodeEditTextView 或第二套编辑器。优化不能损失输入法、撤销、命中、保存、辅助功能与行号。
- **编辑内容属于长生命周期标签。** 文本、保存基线、原生编辑器、撤销栈、光标和滚动不能由临时 View 持有。Finder 打开的 Mac 文件即使归入 SSH 项目，仍使用本机后端、保持本机文件身份；同路径的远端文件不与之合并。
- **A 与 B 标签身份不同。** 同一停靠位置切换内容时按标签 ID 区分视图；切回或拖动后复用各自原有编辑器。真正关闭标签／整个项目／窗口时，`FileTab` 须退役原生文档、解除旧滚动视图的 `documentView` 强引用，即使 AppKit 暂存旧宿主也不能继续持有正文；标签栏 Hover／右键菜单回调按当前 ID 查找标签，不能强持有已关闭的旧 `PaneTab`。
- **未保存状态来自原始字节比较。** 原生小范围编辑先用变更范围快速判定，只有能够确认原字节相同时才清除未保存标记；Unicode 规范等价但编码不同仍需保存，撤销回原字节必须清除标记。保存和外部消费者按需读取完整正文，不在普通输入后无条件回写全文。
- **保存失败保留编辑。** 不清空缓冲、不换机器、不关闭窗口、不结束终端。
- **旧读取不能覆盖新编辑。** 只有干净文件可重载，回写还要核对目标、请求代次和当前编辑状态。
- **展示与真实输入分离。** 文件在某个分屏展示，不等于其 NSTextView 已成为第一响应者；局部选区、IME、Find 与 Undo 由原生编辑器维护，外部浏览请求不擅自把键盘从 Files/Git 抢走。

## 读取与原生内容

可编辑文本须为 UTF-8、不含 NUL 字节且不超过 8 MiB；图片走预览路径。超限、解码失败和读取失败分别给出可理解的结果；容量限制不保证打开速度，Diff 独立保留 5 MiB 上限。

标签创建和会话恢复只建立身份；首次显示或非视图消费者等待文本时才共用一次初读。窗口重新激活不取消正在进行的初读；只有所属窗口成为主窗口才检查外部变化，同一文件在途刷新时合并重复焦点事件，完成后最多补读一次，后续磁盘变动仍可见。其他窗口不会被连带读取。SSH 断线重连只自动恢复已请求过的读取，从未消费的恢复标签仍保持懒加载。此前不可用的同一文件被重新创建后，新的文本请求可重新读取，不被旧失败状态锁死。文本读取有 8 MiB 上限，IO 与 UTF-8 解码在后台完成；图片仍完整读取并在原生侧建立预览，无效图片回到文本／容量规则。初读期间重命名会继续读取新路径，过期任务不能清除新读取的句柄。

Git Ignore 等非视图追加动作在文本缓冲干净时先读取磁盘当前内容；刷新失败即停止追加和保存，避免用过期缓存覆盖外部修改，原有草稿保留。尚未加载的文件与在途读取继续复用同一读取，真正的重载替换读取任务时等待者跟随同目标新任务；机器、连接或路径改变仍拒绝操作。

干净文件刷新失败且原文已加载时继续显示原文与原生编辑器，并标明上次加载的内容；在成功刷新前临时只读，不能把旧版本写回磁盘，仍可选择、复制和查找；文件确实不存在、超限或变成二进制时仍按对应不可用状态处理。成功重读后清除提示，脏编辑或断线使旧读取和待补读失效。只有磁盘内容确实改变时才替换原生文档；同字节刷新不丢原生编辑器、光标、撤销。接受新文件版本（包括文本变二进制）时，`FileTab` 先退役旧 Coordinator，取消其高亮工作并解除旧 `NSScrollView.documentView` 对过期正文的持有；即使旧 SwiftUI 宿主仍被 AppKit 缓存，也不能延长旧文档生命周期。退役时同时禁用旧视图编辑并清除它专属 UndoManager 的过期事务；普通 Dock 重挂载不是内容版本变化，必须保留同一编辑器及原有 Undo。旧编辑器的回调不能改写新标签内容。字节、UTF-16 与行列坐标要一致，包含中文、emoji 和 CRLF。

查找或选择远处文字时，目标必须真正进入可见区域，前进和后退都不能误跳到文末。定位不改变正文或固定行高，也不以缩短整个文档来强制滚动。原生查找／替换栏展开后不能覆盖第一行或遮挡其行号：AppKit 自动管理 `NSClipView.contentInsets.top`，但不会同步移动阅读原点；由同一个 `RestorableScrollView` 在栏高度变化时对可见原点作等量反向补偿，栏收起时恢复。系统提前夹回负滚动原点时以查找栏可见期间最后的真实位置恢复，避免二次滚动。文件中部开启、查找期间滚动、窗口改尺寸以及切换查找／替换均必须保持正文与行号对齐，不能引入第二套文本容器。会话存储的 `EditorState.scrollY` 始终是排除查找栏占位高度的阅读位置，不得将查找栏展开后偏移的原始 `NSClipView.bounds.origin.y` 直接持久化。

不折行且实际行高一致时，编辑器用原生行分隔位置与实测行高保持文档高度稳定，并通过同一原生视图的坐标转换对齐文字、选区、命中和行号，不修改字体或段落样式。行长度与段落分隔信息只在初次需要时建立，并用前缀索引查找行起点及段落序号；普通局部编辑只更新受影响行，不再平移后续所有行。不折行的横向宽度由同一索引维护的分组行长最大值决定：缩短或删除最长行时收回多余滚动范围，撤销后按实际正文恢复宽度，而不是永久保留历史最大值。增删换行时重建受影响的索引结构，仍正确处理 CRLF 合并、LS 与段落分隔的区别、末尾空行；滚动时不再为行号枚举全文前缀。它不代替 Tree-sitter 的 LF 索引。视口替换旧渲染视图、行高检查及滚动锚点都只遍历当前已附着的布局片段，不扫描历史布局片段映射；这不表示 TextKit 2 底层段落缓存已受控。折行、可变行高或超长段落产生额外视觉行时仍使用原生估算，并按实际可见文字保持阅读位置；不逐屏排版全文。卸载或更改字体时保留文字锚点，重新挂载不重放旧字体的像素位置。首次安装正文不追随默认插入点，避免覆盖保存的滚动位置；正常编辑仍跟随光标。首次布局、Dock 重挂载和窗口尺寸变化可能触发异步几何更新：`RestorableScrollView` 必须在重排和 `tile()` 前取得原滚动位置，完成后按新的合法范围恢复；不能先以 `scrollRangeToVisible` 预跳转再恢复像素坐标，因为后续异步跟随会覆盖用户的阅读位置。重挂载后的验证要同时核对原生文字像素、滚动位置、原对象身份与 Undo。

## 大文件编辑的内容管理边界

2026-10-18 的原生隔离实验确认：`NSTextView` 的文档视图和 `NSTextContainer`
**必须保持同宽且为有限宽度**。不折行时两者一起扩大，外层 `NSScrollView`
可以更窄；若仅扩大容器，10 万行远距导航会让 TextKit 2 提前创建所有段落。
匹配宽度后，17 次交错远跳只请求约 399 个段落；
系统编辑中位约 1.34ms。此前的 STTextView 在相同宽度下仍沿途请求大量段落，
是其视口管理逻辑带来的额外成本，而不只是系统 TextKit 2 的限制。

Bailey 已改用 `NativeCodeTextView: NSTextView`，不再绕过系统原生视口布局。
AppKit 组件测试 `NativeEditorLayoutTests` 在 10 万行和深度跳转后实测文首字符插入
中位约 1.54ms、P95 约 1.73ms（2026-10-19 Debug XCTest，30 次）。
该数字只说明已测内容输入路径，**不是所有 macOS 版本、输入法／视觉帧延迟的完整保证**。
长行横滚、变宽、UTF-16 命中、字体／折行、尾行、短文档、滚动位置恢复
必须同时通过验证，不能靠牺牲数据和命中正确性换速度。

正文仍仅由原生 `NSTextStorage` 持有。行号使用增量的本地行起点索引，
Tree-sitter 的 LF 行列索引独立于 TextKit 的自然段落。
行号栏与正文使用相同主题背景、选中行颜色和用户设置的代码字体；行数增长时按实际字体自动拓宽。
空文件的第 1 行及以 LF／CRLF 结束的末尾空行必须显示行号；光标位于这些位置时正文与行号栏同步高亮。跨行文字选区保留每个实际被选中行号的强调文字颜色，但不绘制光标专属的行背景；选区在下一行行首结束时，不误强调尚未选中的下一行。
原生 `NSRulerView` 在滚动视图内绘制时必须同时裁剪脏区域和图形上下文到自身 `bounds`：否则其背景会覆盖整个正文，即使文本数据、AX 和 TextKit 2 布局都正确。
正文的第一个字形必须位于行号栏右侧；`textContainerInset.width` 跟随真实行号栏宽度，不能使用 `NSScrollView.contentInsets.left`，后者会把内容原点向左滚动。必须用真实窗口像素和文字起始坐标双重验收，而非仅检查有非空文本。
从 `NSTextStorage.didProcessEditing` 得到真实编辑范围，避免系统 Undo/Redo
绕过 `NSTextViewDelegate.textDidChange` 导致脏状态和语法解析不同步。
组合输入保持一条 Undo 事务；离屏追加也必须拥有独立可撤销操作。
不能引入多段合并占位、无效缓存清理或丢全文的内容管理器来冒充优化。

历史方案及与 Zed Rope／VS Code Piece Tree 的对比见[归档证据](https://github.com/chiimagnus/Bailey/blob/e1b9fe700424a561910c6dedb0c5653150212740/.github/features/editor-rendering-performance/evidence-p1.md)。当前使用 Apple 原生实现，不再回退 STTextView。

文件树单击文件可以在其它 Dock 组显示常规 FileTab，但不抢走仍可见的 Files 输入焦点；双击或显式打开转入编辑器。这里复用已有文件标签和原生 TextKit 2 缓冲，不引入独立临时预览标签，也不改变已有 Undo 或延迟读取语义。

## 保存与关闭

自动保存由编辑器失焦、工作标签／项目切换、窗口失焦等事件触发；文件内容不设保存定时器。⌘S 仍可用，读取当前聚焦内容的保存资格。

切入工具或其它 Dock 组也保存离开的工作内容。项目切换覆盖离开项目的全部脏缓冲，窗口失去 key 时覆盖该窗口各项目的脏文件和可编辑 Diff，不再只保存最近标签；写入仍复用同一保存队列，失败保留正文。

文件标签右键可定位到当前项目同机 Files 树；仅本机文件可调用 Mac Finder，远端标签绝不在 Mac 上查找同名路径。定位只改变 Files 树的展开与选中，不修改编辑缓冲或撤销历史。

文件管理器移动、重命名和删除受影响路径前，必须等待对应文件及可写 Diff 的保存队列；操作中暂缓旧路径的后续写入，成功后更新标签路径并继续保存。保存失败或两个窗口存在同一路径的不同脏稿则拒绝文件操作，不损坏缓冲与 Undo；已删除文件的迟到编辑保留只读，不因重连恢复对旧路径的保存。后台和手动写入按请求顺序串行。每次写入在前一个请求完成后才获取当前正文、路径、后端和目标代次并冻结快照；在途新增编辑不能被旧快照覆盖，旧保存结果也不能把后续编辑误标为已保存。错误与原生编辑缓冲必须保留。

历史 Git 操作等待相应仓库的保存完成，不使用会关闭标签的保存路径。文件版本恢复还核对打开确认时该路径的 index 和工作区内容；取消或发现内容已变更时不得覆写。历史原文使用原生只读 TextKit，不能因共享编辑设置变成可写；只有真正的工作区文本属于文件编辑缓冲。保存失败或等待期间再次编辑时停止 Git；操作结束只重载干净缓冲。Git 操作的选项与目标检查由 [git.md](git.md#历史提交操作) 维护。

本机保存范围使用系统标准化路径比较，`/private/var` 与 `/var` 的同一文件不会漏过保护；远端路径不交给 Mac 的文件系统解析。其他仓库的未保存文本不随本次 Git 动作保存。

关闭文件先等待保存；失败时保留「保存／不保存／取消」确认，取消或写入失败不能丢弃编辑。确认 Sheet 只属于文件／Diff 所在窗口，不借用全局 key window；单标签或批量关闭中的重复请求不得提前删除其它标签；关闭项目也不能跳过仍在结束的标签关闭流程。取消后可重新发起并正常保存。关闭项目、单独窗口和应用退出同样等待保存；窗口保护复用现有保存路径，并让原生关闭通知继续到达 SwiftUI。异步保存其他标签／窗口期间，原本干净的文件也可能产生新编辑；销毁项目、允许窗口关闭或应用退出前必须重新检查所有当前编辑器，发现新草稿就保留工作区并终止本次关闭，下一次关闭重新保存，不能只相信开始保存时的脏文件清单。显式关闭项目后必须清空已移除项目所拥有的标签；退役编辑器须解除原文本视图的语法解析，即使 SwiftUI 已先移走其滚动容器。真正关闭窗口以 `NSWindow.willCloseNotification` 为生命周期准绳：保存该窗口的会话快照后从 `WorkspaceApplication` 注销 `WorkspaceWindowModel`，终止并释放其项目、文件和编辑器所有权；不能仅依赖 SwiftUI `.onDisappear`，因为窗口已经关闭时该回调可能仍未执行。两种关闭通知最多清理一次，不能让重复回调覆写已保存的会话快照。 另外，WindowGroup 的「Tabs」和「Switch Project」系统菜单只能持有轻量标题／ID／序号，不直接持有 `PaneTab` 或 `Project` 数组；否则 SwiftUI 长期菜单缓存仍可能在窗口关闭后留下完整文件内容。

远端断线、重连与保存结果失效规则见 [ssh.md](ssh.md)。重新启动只重新读取磁盘，不承诺恢复未保存文本，见 [session-restore.md](session-restore.md)。

## 高亮与编辑

使用原生 NSTextView/TextKit 2 和现有增量解析。TSX 使用独立解析器，Markdown／HTML 保留嵌入语言；未知语法显示纯文本。文件扩展名变更时，在同一个编辑器上切换语法并清除旧色，不丢未保存内容和撤销历史。Markdown 是源码编辑，不承诺排版预览。

高亮只添加／清除临时前景色，不写入正文属性或重复设置字体；不能修改文本、污染撤销或更改用户字体。实际换字体仍由原生编辑器应用。原生视图与语法资源维护由 [development.md](../development.md#依赖与本地补丁) 说明，性能测量见 [testing.md](../testing.md#性能与内存测量)。

首次解析按空文档插入全文通知解析器。Tree-sitter 的行只按 LF 递增，列按 UTF-16 字节计数；不能使用 TextKit 的段落／字符列代替。CRLF、裸 CR、Unicode 段分隔符和代理对保留原字节，非法位置不伪装成文首。

坐标按正文的 LF 行长度与 UTF-16 前缀索引查询；普通局部编辑只更新受影响的行长度，增删换行时重建索引，不再每次从文首扫描或平移所有后续行。索引不另存一份正文。

非空编辑沿用 Neon 的串行后台解析，不让小修改在主线程同步解析整棵语法树；正文快照保持稳定，当前视口在解析完成后更新颜色。文本布局等原生输入成本仍需单独测量。

每次编辑同时更新解析器和高亮器的范围。普通高亮与嵌入语言合并只交付同一编辑版本；过期成功和失败都丢弃，由当前版本重新请求，不能把旧范围标成已完成。

同一语言、同一种查询的首次编译由编辑器、嵌入片段与 Diff 共用，关闭一个等待者不取消其他消费者。内置查询没有热更新入口；编译失败在本进程内记住，保留纯文本或根语言着色，不通过反复重画触发重编译。

嵌入区域在后台解析和查询，同一编辑版本内共用片段结果；编辑时取消并清理旧结果，根语言与片段仍按同一版本交付。两者只更新本次请求的区间，不把尚未着色的整块区域提前标为有效。关闭编辑器后释放其独占的片段工作与结果。

围栏语言或标签变化可能改变整个片段的着色，但根语法树只报告局部变化。嵌入文档收到新根树时清除旧版本的有效标记，仍只请求当前视口；普通单语言文档继续使用局部失效范围。

后台解析返回的失效位置还须经过后续排队编辑的范围变换，不能让当前视口保留已经过时的有效样式。第三方运行时补丁归 [开发文档](../development.md#neon)。

组合输入结束标记时保留正文并清除临时样式；输入法交付最终文本时才替换组合范围。首次默认替换使用当前完整选区，后续默认范围与显式替换使用同一正文坐标，不能把已删除的组合长度再用于删除后续文字。直接确认与替换已有内容只生成一次可撤销编辑，撤销恢复输入前的原文，重做恢复最终输入。输入法候选框在编辑器已拆卸时不再读取失效窗口，跨多行查询返回首行实际字符范围。

Git Ignore 在普通 `.gitignore` 标签持有的原生缓冲末尾插入规则，即使标签暂时未显示也不重建编辑器；已有未保存文本一同串行保存，重新显示后可撤销此次插入。追加与显示共用标签的按需读取，不能把加载中的空文本当作文件内容；失败保留缓冲和未保存状态。

## 验证

原生编辑、输入法、Undo、查找、保存、重载及高亮由 `FileTabPersistenceTests`、`NativeFileTabTests`、`NativeEditorCompositionTests`、`NativeEditorLayoutTests`、`NativeSyntaxHighlightingTests` 、`NativeContentIdentityIntegrationTests`、`NativePaneRetentionIntegrationTests` 与 `WindowCloseIntegrationTests` 共同验证；分别覆盖 File／Diff／Browser 身份、旧滚动视图缓存与弱引用释放，以及关闭失败后缓冲保留与重试保存。`EditorNavigationUITests` 从真实 App 验证远距键盘导航、撤销／重做与最终磁盘字节；十万行实际 TextKit 布局、编辑与释放由 `NativePaneRetentionIntegrationTests` 验证。编辑器仍通过 `NSTextViewDelegate.undoManager(for:)` 提供各标签的撤销管理器；实体中文输入法候选须单独验收。`EditorHighlightingUITests` 保留 Swift 对纯文本的真实 App 像素对比；`NativeSyntaxHighlightingTests` 直接检查 Markdown、TSX、HTML、CSS 的原生 TextKit 着色、嵌入语言范围及正文不变。行号、Diff、滚动坐标与多标签释放也必须在真实 AppKit 窗口中检查；五个文件标签的实际释放由 `NativePaneRetentionIntegrationTests` 检查；系统投递与关闭／恢复由 `WorkspaceWindowsUITests` 验证，不用 UI 标签计数冒充内存释放证据。具体环境、极端组合及完成标准由 [测试文档](../testing.md) 统一规定。

独立 App 验收必须实际输入、执行前台 ⌘S、核对磁盘字节，并在重启后再次读取。单纯派发快捷键、读取 AX 值或显示截图均不能代替最终保存结果。

TextKit 2 迁移的测试结果、历史缺陷及未完成验收条件见 [P1-T5 归档记录](https://github.com/chiimagnus/Bailey/blob/e1b9fe700424a561910c6dedb0c5653150212740/.github/features/editor-rendering-performance/evidence-p1.md)。当前的验证要求以本页与[测试文档](../testing.md)为准。
