# 文件编辑器

本页维护读取、文本缓冲、保存、重载和高亮的契约。修改这些路径或原生编辑器集成时同步更新；
树与文件操作见 [files.md](files.md)。

## Invariants

- **唯一正式编辑器是 Apple 原生 NSTextView + TextKit 2。** 文件与 Diff 都复用同一原生控件，
  不引入 STTextView、CodeEditTextView 或第二套编辑器。
  优化不能损失输入法、撤销、命中、保存、辅助功能与行号。
- **编辑内容属于长生命周期标签。** 文本、保存基线、原生编辑器、撤销栈、
  光标和滚动不能由临时 View 持有。Finder 打开的 Mac 文件即使归入 SSH 项目，仍使用本机后端、
  保持本机文件身份；同路径的远端文件不与之合并。
- **A 与 B 标签身份不同。** 同一停靠位置切换内容时按标签 ID 区分视图；
  切回或拖动后复用各自原有编辑器。真正关闭标签／整个项目／窗口时，`FileTab` 须退役原生文档、
  解除旧滚动视图的 `documentView` 强引用，即使 AppKit 暂存旧宿主也不能继续持有正文；
  标签栏 Hover／右键菜单回调按当前 ID 查找标签，不能强持有已关闭的旧 `PaneTab`。
- **未保存状态逐字节精确。** 原生小范围编辑先用 UTF-16 变更量快速判定，
  缺失可靠替换范围的 Undo／IME 则以有界 UTF-16 块严格逐单元比较，
  不在主线程构建全文字符频数字典或复制完整 UTF-8 缓冲。
  Unicode 规范等价但原字节不同仍需保存；撤销回原字节必须清除标记。
  保存和外部消费者按需读取完整正文，不在普通输入后无条件回写全文。
- **保存失败保留编辑。** 不清空缓冲、不换机器、不关闭窗口、不结束终端。
- **旧读取不能覆盖新编辑。** 只有干净文件可重载，回写还要核对目标、请求代次和当前编辑状态。
- **展示与真实输入分离。** 文件在某个分屏展示，不等于其 NSTextView 已成为第一响应者；
  局部选区、IME、Find 与 Undo 由原生编辑器维护，外部浏览请求不擅自把键盘从 Files/Git 抢走。

## 读取与原生内容

可编辑文本不含真实 NUL 字符，原始文件不超过 32 MiB；64 MiB 暂不支持。图片按独立上限走有界预览。
本机音频、视频候选在文本读取之前交给 AVFoundation 检查。实际可解码轨道决定播放方式：
例如，只有音轨的 MP4 按音频打开。媒体直接从读得动的本机普通文件播放，不复制整份文件，也不进入正文或保存。
打开与重载以原路径的实际文件身份为准；发现同路径被替换时停止旧播放器。SSH 文件明确不支持播放，
不以同名本机文件回退。Markdown 嵌入式媒体用同一轨道检查和播放器，仍按点击后授权暂存。
依赖其他文件的引用型 MOV 不支持播放；请改用包含音视频数据的自包含文件。

音频文件在内容区保留 macOS 原生的播放、进度、倍速、音量和静音控件；
播放器键盘输入归当前的原生控件，不给终端或编辑器增加全局快捷键。
切换标签或失去活动状态会暂停；标签仍在时保留播放位置和设置，真正关闭后释放 AVPlayer。
视频按实际画幅（包括旋转）显示，原生控件随画面而不是窗格边缘定位。
进入和退出 AVKit 全屏保留原来的播放或暂停状态，不按切换标签处理。
有系统支持的内嵌字幕时，从原生播放器的字幕菜单选择语言、开启或关闭；无字幕文件不提供语言选择。

文本优先识别 UTF-8、UTF BOM 和文件开头声明的编码（Python `coding:`）；
Windows Abaqus 的 `mbcs` 按**远端 Windows 系统 ANSI 代码页**读取，不取 Mac 的默认编码。
CSV／TSV 的合法 UTF-8 优先于首行的 `coding:` 字样，该字段也不会阻止用户明确转换编码。
为兼容已有非 UTF-8 数据，无法按 UTF-8 打开的旧 CSV／TSV 仍可用已支持的编码声明。
CSV／TSV 默认显示只读原生表格。用 `⌘⇧V` 切换源码，或在文件标签右键选择并排；
三种展示与 Markdown 共用文件菜单和停靠布局，不会创建第二个正文或改变原始字节。
点表头排序，右键表头可筛选列、切换表头或选择分隔符；`⌘F` 查找当前可见数据。
可选择和复制多个单元格，复制按显示顺序输出制表符分隔的文本，不把排序或筛选写回文件。
源数据有格式问题时报告原文行列；超过 4096 列时只显示前 4096 列，其余仍可从源码查看。
无声明且无法用 UTF-8 解码时不猜 GBK；可从文件中选择「以编码重新打开」。
编辑器保存沿用加载时的编码；「以编码保存」需严格可往返编码，
字符不可表示或与现有 `coding:` 声明冲突时拒绝写入并保留草稿。
保存前还会按**编码后的最终字节数**验证 32 MiB 限制（包括 BOM）；
超限拒绝写盘且保留原文件与草稿，避免保存后变成无法重新打开的文件。
重新打开编码须先保存或处理未保存草稿，不能静默覆盖编辑。
二进制、编码未知、过大、读取失败分别报告原因；Diff 独立保留 5 MiB 上限。
已打开的文本刷新时若编码未知或解码无效，保留有效正文、显示错误并拒绝过期保存；
文件确实删除或变成二进制时则按新文件状态清除旧正文，不冒充仍可编辑的文本。

`FileTab` 持有唯一可写的 `NSTextStorage`／`NSTextContentStorage`；原生视图只挂接此正文，
不保留第二份 Swift 文本缓冲。TextKit 2 的编辑通知可能扩大到整段落，
普通输入和 IME Undo 均以编辑前实际替换范围、长度与写后字符校验增量，不能逐键全篇扫描。
Dock 暂时卸载仍持有原文与 Undo；只有接受新磁盘内容或真实关闭才退役旧文档。
Git Ignore 离屏追加直接修改标签的原生正文，只读取行尾格式而不拷贝全篇；
标签切换器的文件缩略预览仅截取最多 7,000 个 UTF-16 单元。
标签创建和会话恢复只建立身份；首次显示或非视图消费者等待文本时才共用一次初读。
窗口重新激活不取消正在进行的初读；只有所属窗口成为主窗口才检查外部变化，
同一文件在途刷新时合并重复焦点事件，完成后最多补读一次，后续磁盘变动仍可见。其他窗口不会被连带读取。
SSH 断线重连只自动恢复已请求过的读取，从未消费的恢复标签仍保持懒加载。
此前不可用的同一文件被重新创建后，新的文本请求可重新读取，不被旧失败状态锁死。
文本读取有 32 MiB 上限，IO 与实际编码解码在后台完成；
受控 SSH Shell 的相同字节边界已验证，真实 Windows SSH 的 32 MiB 传输与保存性能尚未验收。
图片仅在确认普通文件、读取有界格式头且原始字节不超过 256 MiB 后完整读取；
预览经 ImageIO 核查首帧最多 3,200 万像素，并仅解码最长边不超过 4,096 像素的首帧缩略图，
不交给 AppKit 延迟解码整张或全部动画帧。伪装图片后缀不能绕过文本上限；
被拒绝的超大或无效图片不得清除已有未保存编辑。
初读期间重命名会继续读取新路径，过期任务不能清除新读取的句柄。

Git Ignore 等非视图追加动作在文本缓冲干净时先读取磁盘当前内容；
刷新失败即停止追加和保存，避免用过期缓存覆盖外部修改，原有草稿保留。
尚未加载的文件与在途读取继续复用同一读取，真正的重载替换读取任务时等待者跟随同目标新任务；
机器、连接或路径改变仍拒绝操作。

干净文件刷新失败且原文已加载时继续显示原文与原生编辑器，并标明上次加载的内容；
在成功刷新前临时只读，不能把旧版本写回磁盘，仍可选择、复制和查找；
文件确实不存在、超限或变成二进制时仍按对应不可用状态处理。
成功重读后清除提示，脏编辑或断线使旧读取和待补读失效。只有磁盘内容确实改变时才替换原生文档；
同字节刷新不丢原生编辑器、光标、撤销。接受新文件版本（包括文本变二进制）时，
`FileTab` 先退役旧 Coordinator，
取消其高亮工作并解除旧 `NSScrollView.documentView` 对过期正文的持有；
即使旧 SwiftUI 宿主仍被 AppKit 缓存，也不能延长旧文档生命周期。
退役时同时禁用旧视图编辑并清除它专属 UndoManager 的过期事务；
普通 Dock 重挂载不是内容版本变化，必须保留同一编辑器及原有 Undo。旧编辑器的回调不能改写新标签内容。
字节、UTF-16 与行列坐标要一致，包含中文、emoji 和 CRLF。

查找或选择远处文字时，目标必须真正进入可见区域，前进和后退都不能误跳到文末。
定位不改变正文或固定行高，也不以缩短整个文档来强制滚动。
原生查找／替换栏展开后不能覆盖第一行或遮挡其行号：AppKit 自动管理 `NSClipView.contentInsets.top`，
但不会同步移动阅读原点；由同一个 `RestorableScrollView` 在栏高度变化时对可见原点作等量反向补偿，
栏收起时恢复。系统提前夹回负滚动原点时以查找栏可见期间最后的真实位置恢复，避免二次滚动。
文件中部开启、查找期间滚动、窗口改尺寸以及切换查找／替换均必须保持正文与行号对齐，
不能引入第二套文本容器。会话存储的 `EditorState.scrollY` 始终是排除查找栏占位高度的阅读位置，
不得将查找栏展开后偏移的原始 `NSClipView.bounds.origin.y` 直接持久化。

不折行且实际行高一致时，编辑器用原生行分隔位置与实测行高保持文档高度稳定，
并通过同一原生视图的坐标转换对齐文字、选区、命中和行号，不改字体、行高和用户段落间距。
行长度与段落分隔信息只在初次需要时建立，并用前缀索引查找行起点及段落序号；
普通局部编辑只更新受影响行，不再平移后续所有行。不折行的水平范围由实际字体测得的各行宽度决定，
不能用 UTF-16 长度乘固定倍数扩大文档。
冷加载的全文测宽在后台执行，并发度最多占当前可用 CPU 的一半，
避免低核数机器的字体排版任务挤占主线程响应。
超长行绘制宽度由「文本编辑器 → 超长行显示宽度」控制，
默认 12,288 点，另提供 8,192、24,576 点和「完整显示」。
仅超出显示宽度的部分以原生省略号截断，始终只占一个视觉行；原文、复制、编辑、撤销和保存不截断。
「完整显示」不截断任何字符；超过 24,576 点的行在此宽度后自动换成后续视觉行，
避免 TextKit 2 在自然宽度达到数万点时漏画整行。普通「自动折行」则按视口宽度折行。
不能只缩小文本容器，否则长段落会意外产生多个视觉行。
偏好以 `editor.long-line-width` 保存在 `config.toml`，非默认值分别为 `8192`、`24576`、`-1`；
修改即作用于现有文件编辑器及只读、可编辑 Git Diff，无须重建文本缓冲；
分栏 Diff 为保持左右行对齐，完整显示模式仍以 24,576 点截断，可切换统一视图阅读全文。
文字宽度缓存随局部编辑增量更新；
初次测量顺序遍历已有段落索引，按有界 UTF-16 缓冲批量识别等宽 ASCII。
非 ASCII 和 Tab 仍由真实字体测量；固定字宽字体下仅 ASCII 数字不同的行可以复用整行实测宽度，
不以片段宽度相加替代字形排版。首次加载不折行的 FileTab 时，
在后台以冻结的原生字体描述符和实际正文计算所有行宽；长文档最多并行四个独立测量区段，
按原始行序合并结果。只有加载代次、正文长度、行数、字体及折行设置都匹配时，
首次挂载才接受测宽快照；挂载前的编辑、重载、关闭和字体变化都会使旧快照失效。
这避免了复杂 Unicode 文本首次挂载时在主线程连续进行整篇 CoreText 排版，
但后台计算仍需时间，且 Git Diff 及已显示文档的字体切换目前仍采用各自原生测宽路径。
普通编辑按原生行索引局部更新缓存；切换到折行模式暂时保留已测行宽，
折行期间的编辑仍更新该缓存，返回不折行时不重复测量整篇。字体或正文版本确实不匹配才重算，
不复制整篇文本。
缩短或删除最宽行后立即收回多余范围，撤销、字体与窗口尺寸变化后重新取得正确范围，
同时保持文档视图与 TextKit 2 容器同宽。首次装入正文后在首帧绘制前同步确定宽度；
Diff 共用显示策略；标准宽度保持固定行高与删除行间距，完整显示则按实际折行高度计算。
增删换行时重建受影响的索引结构，仍正确处理 CRLF 合并、
LS 与段落分隔的区别、末尾空行；滚动时不再为行号枚举全文前缀。它不代替 Tree-sitter 的 LF 索引。
共用原生文本视图设置固定文档高度后，首次挂载与窗口调整尺寸也必须立即同步实际视图高度和滚动限制；
短正文至少覆盖可点击的视口，不能靠一次初始设置假定 AppKit 后续不会调整 frame。
视口替换旧渲染视图、行高检查及滚动锚点都只遍历当前已附着的布局片段，不扫描历史布局片段映射；
这不表示 TextKit 2 底层段落缓存已受控。折行、可变行高或超长段落产生额外视觉行时仍使用原生估算，
并按实际可见文字保持阅读位置；不逐屏排版全文。
卸载或更改字体时保留文字锚点，重新挂载不重放旧字体的像素位置。
首次安装正文不追随默认插入点，避免覆盖保存的滚动位置；正常编辑仍跟随光标。
首次布局、Dock 重挂载和窗口尺寸变化可能触发异步几何更新：
`RestorableScrollView` 必须在重排和 `tile()` 前取得原滚动位置，完成后按新的合法范围恢复；
不能先以 `scrollRangeToVisible` 预跳转再恢复像素坐标，因为后续异步跟随会覆盖用户的阅读位置。
重挂载后的验证要同时核对原生文字像素、滚动位置、原对象身份与 Undo。

## 大文件编辑的内容管理边界

2026-10-18 的原生隔离实验确认：`NSTextView` 的文档视图和 `NSTextContainer`
**必须保持同宽且为有限宽度**。不折行时两者一起扩大，外层 `NSScrollView`
可以更窄；若仅扩大容器，10 万行远距导航会让 TextKit 2 提前创建所有段落。
匹配宽度后，17 次交错远跳只请求约 399 个段落；
系统编辑中位约 1.34ms。此前的 STTextView 在相同宽度下仍沿途请求大量段落，
是其视口管理逻辑带来的额外成本，而不只是系统 TextKit 2 的限制。

Bailey 已改用 `NativeCodeTextView: NSTextView`，不再绕过系统原生视口布局。
AppKit 组件测试 `NativeEditorLayoutTests` 在 10 万行和深度跳转后实测文首字符插入
中位约 1.54ms、P95 约 1.73ms（2026-10-19 Debug XCTest，30 次）。
该数字只说明已测内容输入路径，**不是所有 macOS 版本、输入法／视觉帧延迟的完整保证**。
长行横滚、变宽、UTF-16 命中、字体／折行、尾行、短文档、滚动位置恢复
必须同时通过验证，不能靠牺牲数据和命中正确性换速度。

正文仍仅由原生 `NSTextStorage` 持有。若原生视图绑定的是已填充的 `NSTextContentStorage`，
其初始行索引必须来自已有正文，不能假定从空文本开始；标签真正接管这种预加载来源前仍须通过完整宿主验收。
行号使用增量的本地行起点索引，
Tree-sitter 的 LF 行列索引独立于 TextKit 的自然段落。
行号栏与正文使用相同主题背景、选中行颜色和用户设置的代码字体；行数增长时按实际字体自动拓宽。
空文件的第 1 行及以 LF／CRLF 结束的末尾空行必须显示行号；光标位于这些位置时正文与行号栏同步高亮。
跨行文字选区保留每个实际被选中行号的强调文字颜色，但不绘制光标专属的行背景；
选区在下一行行首结束时，不误强调尚未选中的下一行。
普通文件的行号栏是独立的原生 `NSView`，与正文 `NSScrollView` 并列：行号固定在左侧，正文横向滚动，
`textContainerInset.width` 为零。行号栏按字体和行数调整宽度，纵向滚动同步重绘；
绘制裁剪到自身边界，不能覆盖正文。验收检查文字像素、行号位置与往返横滚后的固定边界。
从 `NSTextStorage.didProcessEditing` 得到真实编辑范围和替换后的文字，
避免系统 Undo/Redo 绕过 `NSTextViewDelegate.textDidChange` 导致脏状态和语法解析不同步。
共享编辑器的原生 UTF-16 段落索引同时增量维护分隔符种类，
向子类编辑回调提供自然段落数或分隔符类型是否变化的事实；
Diff 以此失效几何，CRLF 与裸 CR 的转换即使行数不变也正确处理，不能逐键全文扫描。
Files／Git 接收同一原生后置事件；有前置替换通知时须按 UTF-16 范围及原始字节
确认两次事件对应，缺失或不一致时走真实字节比较，不把旧前置通知套用到下一次编辑。
初次安装 Git 原文不是用户修改；仅后台 Diff 快照和保存需要读取整篇可写正文。
组合输入使用实际 UTF-16 替换范围记录一条 Undo 事务，
不为一次局部输入复制全文；原生候选结束时只将最终保留的编辑写入撤销历史。
离屏追加也必须拥有独立可撤销操作。
真正退役的原生文档须禁止后续输入、清空 Undo／Redo 与语法任务，
并清理编辑事件和焦点回调。Neon 已排队的异步着色回调可能晚于正文释放；
退役时先断开语法适配器对旧文本视图的访问，再解除 TextKit 布局绑定。
Files 的旧文档重新加载时仍可能被 AppKit 保留做布局，
在旧滚动宿主解绑前不得移除其原生布局管理器；临时重挂载不得执行退休流程。
真正退役后必须移除旧 `NSTextStorage` 编辑观察者并清空旧文本缓冲；
原文仍由 `FileTab` 与磁盘保存，不得让 AppKit 缓存的无主 `NSTextView` 继续持有旧正文、Undo 或解析器。
窗口关闭后 AppKit 可继续保留**已分离、已清空且不可编辑**的视图对象，
因此验收应检查标签／内容所有者释放、旧缓冲字节归零与语法任务停止，而不是以弱视图立刻析构作为唯一标准。
不能引入多段合并占位、无效缓存清理或丢全文的内容管理器来冒充优化。

历史方案及与 Zed Rope／VS Code Piece Tree 的对比
见[归档证据](https://github.com/chiimagnus/Bailey/blob/e1b9fe700424a561910c6dedb0c5653150212740/.github/features/editor-rendering-performance/evidence-p1.md)。当前使用
Apple 原生实现，不再回退 STTextView。

文件树单击文件可以在其它 Dock 组显示常规 FileTab，但不抢走仍可见的 Files 输入焦点；
双击或显式打开转入编辑器。这里复用已有文件标签和原生 TextKit 2 缓冲，不引入独立临时预览标签，
也不改变已有 Undo 或延迟读取语义。

## 保存与关闭

自动保存由编辑器失焦、工作标签／项目切换、窗口失焦等事件触发；文件内容不设保存定时器。
⌘S 仍可用，读取当前聚焦内容的保存资格。

切入工具或其它 Dock 组也保存离开的工作内容。
项目切换覆盖离开项目的全部脏缓冲，窗口失去 key 时覆盖该窗口各项目的脏文件和可编辑 Diff，
不再只保存最近标签。文件标签由一个写入者串行处理保存；重复普通保存只保留最新请求，
明确选择的编码转换单独执行。失败保留正文，不发生无限重试。

文件标签右键可定位到当前项目同机 Files 树；
仅本机文件可调用 Mac Finder，远端标签绝不在 Mac 上查找同名路径。
定位只改变 Files 树的展开与选中，不修改编辑缓冲或撤销历史。

文件管理器移动、重命名和删除受影响路径前，必须等待对应文件及可写 Diff 的保存队列；
操作中暂缓旧路径的后续写入，成功后更新标签路径并继续保存。
保存失败（包括正文干净但编码转换失败）或两个窗口存在同一路径的不同脏稿时拒绝文件操作，
不损坏缓冲与 Undo；
已删除文件的迟到编辑保留只读，不因重连恢复对旧路径的保存。
每次写入在前一个请求完成后冻结当前正文、路径、后端、编码及目标代次，
编码检查与无损往返在后台完成。最新编辑不会被旧快照覆盖，
旧保存结果也不能把后续编辑误标为已保存。

**文件标签保存会核对最初读取的原始字节版本**（长度及 SHA-256），
防止外部编辑器即使保留相同文件大小和修改时间仍被 Bailey 静默覆盖。
目标文件被改写、删除或重命名后拒绝保存，保留草稿并显示冲突；
用户在磁盘恢复原始字节后可以再次保存。
本机与 SSH 均先在目标目录中完整暂存并核验数据，再比对当前目标版本并原子替换入口；
保留原有执行权限，不会沿符号链接覆盖链接目标。SSH 上传必须同时通过字节长度和 SHA-256 校验。
远端发布成功但确认回执丢失时只读取目标核实结果，绝不盲目重试写入。
普通无条件工作区写入 API 仍服务于其它明确的文件操作；Files 与可编辑 Git Worktree Diff 均使用原始字节版本条件保存，不得回退到无条件写入。
文件版本检查不等于文件系统原子 compare-and-swap：外部进程仍可能在最后一次比较后、重命名前竞争写入，
没有跨进程协调协议时不能保证完全排除。

历史 Git 操作等待相应仓库的保存完成，不使用会关闭标签的保存路径。
文件版本恢复还核对打开确认时该路径的 index 和工作区内容；取消或发现内容已变更时不得覆写。
历史原文使用原生只读 TextKit，不能因共享编辑设置变成可写；只有真正的工作区文本属于文件编辑缓冲。
保存失败或等待期间再次编辑时停止 Git；操作结束只重载干净缓冲。
Git 操作的选项与目标检查由 [git.md](git.md#历史提交操作) 维护。

本机保存范围使用系统标准化路径比较，`/private/var` 与 `/var` 的同一文件不会漏过保护；
远端路径不交给 Mac 的文件系统解析。其他仓库的未保存文本不随本次 Git 动作保存。

关闭文件不仅检查正文是否修改：即使正文干净，显式转换编码的写入仍可能在途；
单标签、批量、项目、窗口及应用退出都须等待写入完成，失败时保留标签与错误提示，否决本次关闭。
多标签与跨窗口关闭在等待其它保存完成后须再次核对全部标签；即使某笔编码写入已失败并结束，
其保存错误仍保持未解决状态，不能因为正文干净而误判为保存成功。
编码转换失败后即使正文干净、写入任务已结束，也须保留未解决的保存错误；
再次关闭标签仍提示「保存／不保存／取消」，只有保存真正成功或用户明确选择「不保存」才能移除，
「取消」必须保留；窗口、项目或 App 退出不能直接丢弃这份意图。
脏稿保存失败时同样保留原生确认；取消或写入失败不能丢弃编辑。
确认 Sheet 只属于文件／Diff 所在窗口，不借用全局 key window；
单标签或批量关闭中的重复请求不得提前删除其它标签；关闭项目也不能跳过仍在结束的标签关闭流程。
取消后可重新发起并正常保存。关闭项目、单独窗口和应用退出同样等待保存；
窗口保护复用现有保存路径，并让原生关闭通知继续到达 SwiftUI。
异步保存其他标签／窗口期间，原本干净的文件也可能产生新编辑；
销毁项目、允许窗口关闭或应用退出前必须重新检查所有当前编辑器，发现新草稿就保留工作区并终止本次关闭，
下一次关闭重新保存，不能只相信开始保存时的脏文件清单。显式关闭项目后必须清空已移除项目所拥有的标签；
退役编辑器须解除原文本视图的语法解析，即使 SwiftUI 已先移走其滚动容器。
真正关闭窗口以 `NSWindow.willCloseNotification` 为生命周期准绳：
保存该窗口的会话快照后从 `WorkspaceApplication` 注销 `WorkspaceWindowModel`，终止并释放其项目、
文件和编辑器所有权；不能仅依赖 SwiftUI `.onDisappear`，因为窗口已经关闭时该回调可能仍未执行。
两种关闭通知最多清理一次，不能让重复回调覆写已保存的会话快照。
另外，WindowGroup 的「面板」和「项目」系统菜单中的动态列表只能持有轻量标题／ID／序号，
不直接持有 `PaneTab` 或 `Project` 数组；
否则 SwiftUI 长期菜单缓存仍可能在窗口关闭后留下完整文件内容。

远端断线、重连与保存结果失效规则见 [ssh.md](ssh.md)。重新启动只重新读取磁盘，不承诺恢复未保存文本，
见 [session-restore.md](session-restore.md)。

## 高亮与编辑

使用原生 NSTextView/TextKit 2 和现有增量解析。TSX 使用独立解析器，Markdown／HTML 保留嵌入语言；
未知语法显示纯文本。文件扩展名变更时，在同一个编辑器上切换语法并清除旧色，不丢未保存内容和撤销历史。
Markdown（`.md`／`.markdown`／`.mdx`）仍以同一原生 TextKit 文件缓冲编辑；
`⌘⇧V` 在源码和只读预览之间切换，文件标签右键还可选择 Dock 并排。
预览由 `swift-markdown` 解析 AST，Bailey 的 SwiftUI 组件直接渲染 GFM、YAML 元数据、
受限 HTML／SVG、Mermaid、本地音视频和 Canvas 原生公式；无效公式保留可选择的原文，
货币美元符及代码／链接不被当作公式；代码围栏复用 Tree-sitter 高亮。
资源经项目 backend 授权，内容不执行 WebKit 或 JavaScript。
SVG 允许引用同一文档中的渐变、剪裁、遮罩和滤镜，不加载外部资源。
SVG 图案、内嵌图像和复用符号目前会被省略，独立预览会提示。
Markdown 内嵌 GIF 超过 32 帧或解码像素预算时显示静态封面。
独立 SVG 默认显示矢量预览，与 Markdown 共用净化器和 SwiftDraw；
从文件菜单或标签右键切回源码，仍可编辑原始 XML。无法显示的内容不写回文件。
预览 XML 上限为 1 MiB，独立画布还受尺寸和面积限制；超限时仍可查看和编辑原文。
音视频必须主动加载，离开预览后停止播放并清理临时文件。
阅读排版沿用 GitHub Primer 的标题、表格、引用、代码与响应式语义；
普通换行随正文自然折行，显式硬换行保留。顶层引用中，GitHub 的五种提示标记显示图标和标题，
并随深浅外观切换配色。宽表格只在表格内横向滚动，表头有独立的辅助功能语义。
预览背景、正文与链接沿用当前 Bailey 选中的终端主题。不论同段还是跨块拖选，
预览只绘制一份连续选区，使用该终端主题的选区底色和文字色，不叠加 macOS 的文字选色。
可选择的正文保持 I-beam；只有文字链接、图片、展开控件、标题锚点和复制按钮的实际交互区域使用手形指针。
从带格式的链接文字开始拖选时仍可跨段落连续选择，不触发链接跳转。
代码复制在悬停／键盘聚焦时显示操作与成功反馈；页内与跨文件标题／脚注链接按解码片段定位，无效片段显示错误。
预览解析按文件标签身份及编辑代次取消过期任务，Dock 并排仍共用同一份原生正文、Undo 和保存路径。
并排预览默认使用原始 UTF-16 源码区间进行双向滚动同步，可在文件标签右键菜单关闭。
跳到屏外内容时，预览按懒布局的行身份找到目标，再用实际字形或媒体矩形对齐；
不先构建沿途各行，也不会仅为滚动而移动源码光标。
源码区间按 Markdown 的换行规则计算（LF、CRLF 或 CR）；其他 Unicode 分隔符保留在原位置。
公式和脚注的解析替换保留原文字节区间，所以替换前后的列宽不同也不会影响源码定位。
预览的文字字形、Canvas 公式和 Markdown 图片共用原文偏移与实际视口坐标；
同段多条公式或图片可精确同步滚动，嵌套在强调文字中的图片仍作为原生媒体呈现。
在块前增删内容后重新解析或切换视图，仍可恢复原阅读位置。
滚动后，选择和双击仍以视口内实际文字为准。双击有原文坐标的预览文字可定位到源码；
并排时保留预览，链接仍按原来的动作导航。
转义符或字符实体渲染成单个符号时，双击定位到原文记法的起点。
块 HTML 的普通文字与实体也可定位到原文；相同文字重复出现时以实际选中的位置为准。
预览支持跨段落分组、标题、引用、列表、表格及代码块的连续拖选，
也可用 Shift 扩选或 ⌘A／⌘C 复制可见内容；代码围栏、隐藏元数据不进入剪贴板。
任务复选框与嵌套层级保留阅读语义，引用中的任务也显示只读状态，不改写源码。
块 HTML 可部分选择，Details 的复制内容遵从当前展开状态。

文件标签右键的 **Outline…** 按标题层级打开导航大纲，方向键选择、Return 跳转、Escape 关闭。
预览标题悬停或键盘聚焦后可展开或折叠章节及其子章节；
折叠只改变展示，复制和全选不包含隐藏正文，编辑、Undo 或保存仍保留完整源文件。
在折叠章节中的页内链接目标会自动展开并定位。脚注定义末尾的 ↩ 可返回正文引用。
图片文件、内嵌 SVG 和 Mermaid 的放大查看共用原生滚动视口，不生成或写回工作区文件。
图片可捏合或用 ⌘＋滚轮围绕指针缩放，也可拖动平移；双击在适应窗口和实际大小之间切换。
右键和辅助功能操作提供相同的缩放入口。手动缩放为 10%～400%，适应窗口不受 10% 下限限制，
因此极宽或极高的图也能完整显示。
文件图片和 Markdown 栅格插图共用有界的 ImageIO 解码，并按 EXIF 方向展示。
标签切换器只用缩略图。打开大图时先显示缩略图，需要更多像素才通过原文件的后端重新读取，
核对原始字节版本后在后台解码。100% 按当前屏幕的实际像素计算。
切换标签或重挂载视口后，文件图片仍保持原来的缩放和查看位置；图片内容变更后重新适应窗口。
大图详情仍受 3200 万像素限制；当前按需解码完整图像，不承诺逐块解码。
独立 GIF 在前台文件视口中播放，右键可暂停或继续；切走标签或窗口失去焦点时不推进，
回到原标签后从原位置继续。动画按需读取同一文件版本，只预取下一帧，
不把全部动画帧留在内存里。只对零时长和极短帧限速，不缩短文件指定的较长停留时间。
GIF 缺失中间帧数据时保留可读的首帧，不播放不完整的动画。
Markdown 内嵌 GIF 仍使用自己的帧数与像素预算。

高亮只添加／清除临时前景色，不写入正文属性或重复设置字体；不能修改文本、污染撤销或更改用户字体。
实际换字体仍由原生编辑器应用。
原生视图与语法资源维护由 [development.md](../development.md#依赖与本地补丁) 说明，
性能测量见 [testing.md](../testing.md#性能与内存测量)。
普通未折行源码的辅助功能行号和行文本范围查询不排版视口之外的前文；
折行、分页符和折叠 Diff 仍由 AppKit 按实际布局回答。

首次解析按空文档插入全文通知解析器。Tree-sitter 的行只按 LF 递增，列按 UTF-16 字节计数；
不能使用 TextKit 的段落／字符列代替。CRLF、裸 CR、Unicode 段分隔符和代理对保留原字节，
非法位置不伪装成文首。

坐标按正文的 LF 行长度与 UTF-16 前缀索引查询；普通局部编辑只更新受影响的行长度，增删换行时重建索引，
不再每次从文首扫描或平移所有后续行。索引不另存一份正文。

非空编辑沿用 Neon 的串行后台解析，不让小修改在主线程同步解析整棵语法树；
正文快照保持稳定，当前视口在解析完成后更新颜色。文本布局等原生输入成本仍需单独测量。

每次编辑同时更新解析器和高亮器的范围。普通高亮与嵌入语言合并只交付同一编辑版本；
过期成功和失败都丢弃，由当前版本重新请求，不能把旧范围标成已完成。

同一语言、同一种查询的首次编译由编辑器、嵌入片段与 Diff 共用，关闭一个等待者不取消其他消费者。
Markdown／HTML 等根语法与嵌入语法查询并行准备，避免编译工作串行叠加首屏等待；
编辑时直接从当前文本存储取得解析快照，不为语法更新重新构造整篇富文本。
内置查询没有热更新入口；编译失败在本进程内记住，保留纯文本或根语言着色，不通过反复重画触发重编译。

嵌入区域在后台解析和查询，同一编辑版本内共用片段结果；
编辑时取消并清理旧结果，根语言与片段仍按同一版本交付。
两者只更新本次请求的区间，不把尚未着色的整块区域提前标为有效。
关闭编辑器后释放其独占的片段工作与结果。
后台高亮提供者不得强持有已关闭的 TextKit 内容管理器；
等待注入片段解析时不得跨 `await` 保留编辑器协调器，防止较慢查询阻碍窗口和标签释放。

围栏语言或标签变化可能改变整个片段的着色，但根语法树只报告局部变化。
嵌入文档收到新根树时清除旧版本的有效标记，仍只请求当前视口；普通单语言文档继续使用局部失效范围。

后台解析返回的失效位置还须经过后续排队编辑的范围变换，不能让当前视口保留已经过时的有效样式。
第三方运行时补丁归 [开发文档](../development.md#neon)。

组合输入结束标记时保留正文并清除临时样式；输入法交付最终文本时才替换组合范围。
首次默认替换使用当前完整选区，后续默认范围与显式替换使用同一正文坐标，
不能把已删除的组合长度再用于删除后续文字。直接确认与替换已有内容只生成一次可撤销编辑，
撤销恢复输入前的原文，重做恢复最终输入。输入法候选框在编辑器已拆卸时不再读取失效窗口，
跨多行查询返回首行实际字符范围。

Git Ignore 在普通 `.gitignore` 标签持有的原生缓冲末尾插入规则，即使标签暂时未显示也不重建编辑器；
已有未保存文本一同串行保存，重新显示后可撤销此次插入。
追加与显示共用标签的按需读取，不能把加载中的空文本当作文件内容；失败保留缓冲和未保存状态。

## HTML 文件的静态预览

`.html` 和 `.htm` 默认打开源码。用 `⌘⇧V` 切换预览，或在文件标签右键选择「显示并排」；
两边共用同一份正文、撤销和保存记录。预览直接使用已解码的正文，不另写临时 HTML。

系统 WebKit 排版网页和 CSS，但不运行网页脚本、提交表单、打开其它页面或访问外部网络。
相对样式、图片和字体只从这份文件所属的工作区读取，与 Markdown 使用同一权限边界；
项目外文件限于其父目录，SSH 资源不会改读本机。缺失或被拒绝的图片保留网页的替代文字，
不影响查看或编辑源码。
单页位图（动画逐帧累计）最多接收 3,200 万像素；超出预算的图片不会送给 WebKit 解码，
正文和样式仍可阅读。
如果渲染进程退出，可以回到源码，再切回预览。正在加载的资源会取消，源码和保存状态不受影响。

## 验证

原生编辑、输入法、Undo、查找、保存、重载及高亮由 `FileTabPersistenceTests`、`NativeFileTabTests`、
`NativeEditorCompositionTests`、`NativeEditorLayoutTests`、`NativeSyntaxHighlightingTests` 、
`NativeContentIdentityIntegrationTests`、
`NativePaneRetentionIntegrationTests` 与 `WindowCloseIntegrationTests` 共同验证；
分别覆盖 File／Diff／Browser 身份、旧滚动视图缓存与弱引用释放，以及关闭失败后缓冲保留与重试保存。
`EditorNavigationUITests` 从真实 App 验证远距键盘导航、撤销／重做与最终磁盘字节；
十万行实际 TextKit 布局、编辑与释放由 `NativePaneRetentionIntegrationTests` 验证。
编辑器仍通过 `NSTextViewDelegate.undoManager(for:)` 提供各标签的撤销管理器；
实体中文输入法候选须单独验收。`EditorHighlightingUITests` 保留 Swift 对纯文本的真实 App 像素对比；
`NativeSyntaxHighlightingTests` 直接检查 Markdown、TSX、HTML、CSS 的原生 TextKit 着色、
嵌入语言范围及正文不变。行号、Diff、滚动坐标与多标签释放也必须在真实 AppKit 窗口中检查；
五个文件标签的实际释放由 `NativePaneRetentionIntegrationTests` 检查，
包括连续挂载五个 0／8／16／32 MiB 原生文本标签、真实字节保存与重开、关闭后旧正文清空与所有者释放；
系统投递与关闭／恢复由 `WorkspaceWindowsUITests` 验证，不用 UI 标签计数冒充内存释放证据。
具体环境、极端组合及完成标准由 [测试文档](../testing.md) 统一规定。

`HTMLFilePreviewTests` 用真实 WebKit 验证原文编码、嵌套样式、生效的图片与外部请求隔离；
`HTMLFilePreviewUITests` 检查系统菜单、源码和 Dock 并排，以及磁盘原文不变。

独立 App 验收必须实际输入、执行前台 ⌘S、核对磁盘字节，并在重启后再次读取。
单纯派发快捷键、读取 AX 值或显示截图均不能代替最终保存结果。
