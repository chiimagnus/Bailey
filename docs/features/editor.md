# 文件编辑器

本页维护读取、文本缓冲、保存、重载和高亮的契约。修改这些路径或原生编辑器集成时同步更新；树与文件操作见 [files.md](files.md)。

## Invariants

- **唯一正式编辑器是 STTextView + TextKit 2。** 不引入 CodeEditTextView 或第二套编辑器；性能问题继续在现有技术路线内解决，不能以输入速度换取文字命中、输入法、撤销或保存正确性的退步。
- **编辑内容属于长生命周期标签。** 文本、保存基线、原生编辑器、撤销栈、光标和滚动不能由临时 View 持有。
- **A 与 B 标签身份不同。** 同一停靠位置切换内容时按标签 ID 区分视图；切回或拖动后复用各自原有编辑器。
- **未保存状态来自原始字节比较。** 原生小范围编辑先用变更范围快速判定，只有能够确认原字节相同时才清除未保存标记；Unicode 规范等价但编码不同仍需保存，撤销回原字节必须清除标记。保存和外部消费者按需读取完整正文，不在普通输入后无条件回写全文。
- **保存失败保留编辑。** 不清空缓冲、不换机器、不关闭窗口、不结束终端。
- **旧读取不能覆盖新编辑。** 只有干净文件可重载，回写还要核对目标、请求代次和当前编辑状态。

## 读取与原生内容

可编辑文本须为 UTF-8、不含 NUL 字节且不超过 8 MiB；图片走预览路径。超限、解码失败和读取失败分别给出可理解的结果；容量限制不保证打开速度，Diff 独立保留 5 MiB 上限。

标签创建和会话恢复只建立身份；首次显示或非视图消费者等待文本时才共用一次初读。窗口重新激活不取消正在进行的初读；只有所属窗口成为主窗口才检查外部变化，同一文件在途刷新时合并重复焦点事件，完成后最多补读一次，后续磁盘变动仍可见。其他窗口不会被连带读取。SSH 断线重连只自动恢复已请求过的读取，从未消费的恢复标签仍保持懒加载。此前不可用的同一文件被重新创建后，新的文本请求可重新读取，不被旧失败状态锁死。文本读取有 8 MiB 上限，IO 与 UTF-8 解码在后台完成；图片仍完整读取并在原生侧建立预览，无效图片回到文本／容量规则。初读期间重命名会继续读取新路径，过期任务不能清除新读取的句柄。

Git Ignore 等非视图追加动作在文本缓冲干净时先读取磁盘当前内容；刷新失败即停止追加和保存，避免用过期缓存覆盖外部修改，原有草稿保留。尚未加载的文件与在途读取继续复用同一读取，真正的重载替换读取任务时等待者跟随同目标新任务；机器、连接或路径改变仍拒绝操作。

干净文件刷新失败且原文已加载时继续显示原文与原生编辑器，并标明上次加载的内容；在成功刷新前临时只读，不能把旧版本写回磁盘，仍可选择、复制和查找；文件确实不存在、超限或变成二进制时仍按对应不可用状态处理。成功重读后清除提示，脏编辑或断线使旧读取和待补读失效。只有磁盘内容确实改变时才替换原生文档；旧编辑器的回调不能改写新标签内容。字节、UTF-16 与行列坐标要一致，包含中文、emoji 和 CRLF。

查找或选择远处文字时，目标必须真正进入可见区域，前进和后退都不能误跳到文末。定位不改变正文或固定行高，也不以缩短整个文档来强制滚动。

不折行且实际行高一致时，编辑器用原生行分隔位置与实测行高保持文档高度稳定，并通过同一原生视图的坐标转换对齐文字、选区、命中和行号，不修改字体或段落样式。行长度与段落分隔信息只在初次需要时建立，并用前缀索引查找行起点及段落序号；普通局部编辑只更新受影响行，不再平移后续所有行。增删换行时重建受影响的索引结构，仍正确处理 CRLF 合并、LS 与段落分隔的区别、末尾空行；滚动时不再为行号枚举全文前缀。它不代替 Tree-sitter 的 LF 索引。视口替换旧渲染视图、行高检查及滚动锚点都只遍历当前已附着的布局片段，不扫描历史布局片段映射；这不表示 TextKit 2 底层段落缓存已受控。折行、可变行高或超长段落产生额外视觉行时仍使用原生估算，并按实际可见文字保持阅读位置；不逐屏排版全文。卸载或更改字体时保留文字锚点，重新挂载不重放旧字体的像素位置。首次安装正文不追随默认插入点，避免覆盖保存的滚动位置；正常编辑仍跟随光标。

## 大文件编辑的内容管理边界

Bailey 只使用 STTextView + TextKit 2。文档内容由同一个原生存储持有；行号和语法索引仅负责查询坐标，
不是第二份正文。视口布局只控制当前渲染片段，**不保证 NSTextContentStorage 曾访问的
NSTextParagraph 元素缓存有界**。深度滚动后，局部编辑仍可能在系统内容管理器中遍历、同步大量历史段落；
优化字体、高亮、可见渲染视图、行号前缀索引或反复清理视口都不能代替这一步。

2026-10-18 的同机隔离测试发现了决定性的**视图与文本容器宽度关系**：

- 把原生 `NSTextView(usingTextLayoutManager: true)` 放进 900pt 滚动窗口，
  但其文档视图仍为 900pt、文本容器却设为 1000pt 或更大时，10 万行会提前请求
  全部段落；17 次导航后的文首输入中位约 569ms。这是**不匹配的布局配置**，
  不能据此认定原生 NSTextView 不折行也无法保持按需布局。
- 若文档视图宽度与文本容器宽度**同为 1000pt**，外部视口仍为 900pt，
  保持不折行的 10 万行、17 次交错导航仅累计创建 **399 个段落**，
  首次跳到 25% 约 **7.4ms**，文首原生输入中位／P95 **1.34／1.68ms**。
  当文档视图与容器都扩成 2300pt，250 字符的真实长行仍是一行，
  横向滚动、末字绘制和屏幕点击反查均正确。1000→2300pt 变化后继续深跳，
  段落创建请求仍是 399。该数据仅属于隔离原生窗口，不等于 Bailey 集成验收。
- `STTextView` 采用相同的文档视图／容器宽度也**没有**取得相同结果：
  10 万行深跳最终仍请求约 10 万个段落。抓取的系统调用栈显示，
  其 `prepareContent → layoutViewport/alignUniformViewport` 会使
  TextKit 2 沿途枚举段落；单独替换布局管理器、跳过重定位或更改宽度均不能根治。

因此，原生 NSTextView 是**已通过核心性能基线、尚未通过全部产品功能验收**的候选，
而非已经获准替换的编辑器。任何正式迁移都必须先完整验收中文输入法、Undo/Redo、
多光标、Neon/Tree-sitter、Find/替换、行号、AX、RTL、长行与宽度变化、保存及 Diff，
并最终只保留**一套编辑器**。现行 Bailey 仍使用 STTextView + TextKit 2，
失败的动态占位、全局清缓存和分块方案都没有进入产品源码。

这个边界不同于 [Zed 的聚合 Rope 与显示映射](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/editor/src/display_map.rs)
及 [VS Code 的 Piece Tree 和可见行集合](https://github.com/microsoft/vscode/blob/789f2c470d13c4760f2b5cc6a9e1919c05d04f7d/src/vs/editor/browser/view/viewLayer.ts)：
两者拥有独立的正文位置及显示位置模型，可以让一次局部编辑不必逐个更新所有历史渲染对象；
直接在 Bailey 增加相同的索引或复制其渲染算法，**不会改变默认 NSTextContentStorage 的元素同步开销**。

Apple 的 [TextKit 2 内容模型](https://developer.apple.com/videos/play/wwdc2021/10061/) 允许使用自定义
NSTextContentManager，但自定义元素必须保证真实段落边界、可靠的位置比较／范围调整、强缓存与布局失效、
完整正文、屏幕点命中及输入事务一致。不能把多个真实段落合成一个 NSTextParagraph，也不能用会截断全文读取、
破坏回跳命中、丢失文本或撤销的动态占位／临时重绑来换取微基准速度。只有经过远距交错访问、折行、复杂脚本、
中文输入法、Undo／Redo、Find／AX、保存字节及内存生命周期的联合测试，才允许在现有编辑器中替换内容管理层；
未达条件继续使用现有正确实现，不安装实验候选。

## 保存与关闭

自动保存由编辑器失焦、工作标签／项目切换、窗口失焦等事件触发；文件内容不设保存定时器。⌘S 仍可用，读取当前聚焦内容的保存资格。

后台和手动写入按请求顺序串行。每次写入在前一个请求完成后才获取当前正文、路径、后端和目标代次并冻结快照；在途新增编辑不能被旧快照覆盖，旧保存结果也不能把后续编辑误标为已保存。错误与原生编辑缓冲必须保留。

历史 Git 操作等待相应仓库的保存完成，不使用会关闭标签的保存路径。文件版本恢复还核对打开确认时该路径的 index 和工作区内容；取消或发现内容已变更时不得覆写。历史原文使用原生只读 TextKit，不能因共享编辑设置变成可写；只有真正的工作区文本属于文件编辑缓冲。保存失败或等待期间再次编辑时停止 Git；操作结束只重载干净缓冲。Git 操作的选项与目标检查由 [git.md](git.md#历史提交操作) 维护。

本机保存范围使用系统标准化路径比较，`/private/var` 与 `/var` 的同一文件不会漏过保护；远端路径不交给 Mac 的文件系统解析。其他仓库的未保存文本不随本次 Git 动作保存。

关闭文件先等待保存；失败时保留「保存／不保存／取消」确认，取消或写入失败不能丢弃编辑。关闭项目、单独窗口和应用退出同样等待保存；窗口保护复用现有保存路径，并让原生关闭通知继续到达 SwiftUI。

远端断线、重连与保存结果失效规则见 [ssh.md](ssh.md)。重新启动只重新读取磁盘，不承诺恢复未保存文本，见 [session-restore.md](session-restore.md)。

## 高亮与编辑

沿用 STTextView/TextKit 和现有增量解析。TSX 使用独立解析器，Markdown／HTML 保留嵌入语言；未知语法显示纯文本。文件扩展名变更时，在同一个编辑器上切换语法并清除旧色，不丢未保存内容和撤销历史。Markdown 是源码编辑，不承诺排版预览。

高亮只添加／清除临时前景色，不写入正文属性或重复设置字体；不能修改文本、污染撤销或更改用户字体。实际换字体仍由原生编辑器应用。第三方补丁与升级验证由 [development.md](../development.md#依赖与本地补丁) 维护，性能测量见 [testing.md](../testing.md#性能与内存测量)。

首次解析按空文档插入全文通知解析器。Tree-sitter 的行只按 LF 递增，列按 UTF-16 字节计数；不能使用 TextKit 的段落／字符列代替。CRLF、裸 CR、Unicode 段分隔符和代理对保留原字节，非法位置不伪装成文首。

坐标按正文的 LF 行长度与 UTF-16 前缀索引查询；普通局部编辑只更新受影响的行长度，增删换行时重建索引，不再每次从文首扫描或平移所有后续行。索引不另存一份正文。

非空编辑沿用 Neon 的串行后台解析，不让小修改在主线程同步解析整棵语法树；正文快照保持稳定，当前视口在解析完成后更新颜色。文本布局等原生输入成本仍需单独测量。

每次编辑同时更新解析器和高亮器的范围。普通高亮与嵌入语言合并只交付同一编辑版本；过期成功和失败都丢弃，由当前版本重新请求，不能把旧范围标成已完成。

同一语言、同一种查询的首次编译由编辑器、嵌入片段与 Diff 共用，关闭一个等待者不取消其他消费者。内置查询没有热更新入口；编译失败在本进程内记住，保留纯文本或根语言着色，不通过反复重画触发重编译。

嵌入区域在后台解析和查询，同一编辑版本内共用片段结果；编辑时取消并清理旧结果，根语言与片段仍按同一版本交付。两者只更新本次请求的区间，不把尚未着色的整块区域提前标为有效。关闭编辑器后释放其独占的片段工作与结果。

围栏语言或标签变化可能改变整个片段的着色，但根语法树只报告局部变化。嵌入文档收到新根树时清除旧版本的有效标记，仍只请求当前视口；普通单语言文档继续使用局部失效范围。

后台解析返回的失效位置还须经过后续排队编辑的范围变换，不能让当前视口保留已经过时的有效样式。第三方运行时补丁归 [开发文档](../development.md#neon)。

组合输入结束标记时保留正文并清除临时样式；输入法交付最终文本时才替换组合范围。首次默认替换使用当前完整选区，后续默认范围与显式替换使用同一正文坐标，不能把已删除的组合长度再用于删除后续文字。直接确认与替换已有内容只生成一次可撤销编辑，撤销恢复输入前的原文，重做恢复最终输入。输入法候选框在编辑器已拆卸时不再读取失效窗口，跨多行查询返回首行实际字符范围。

Git Ignore 在普通 `.gitignore` 标签持有的原生缓冲末尾插入规则，即使标签暂时未显示也不重建编辑器；已有未保存文本一同串行保存，重新显示后可撤销此次插入。追加与显示共用标签的按需读取，不能把加载中的空文本当作文件内容；失败保留缓冲和未保存状态。

## 验证

`FileTabTests` 覆盖读取、编辑、保存及原生行为；`TextCoordinateIndexTests` 对照完整扫描、重建索引与真实解析器，覆盖十万行文首／中／末、LF／CRLF／LS／PS、全文清空恢复及随机编辑；`SyntaxHighlightingTests` 检查真实解析器坐标、Unicode 分块字节、渲染色及字体／撤销不变；`EditorTextInputTests` 对照系统 NSTextView 验证组合输入结束、最终替换及撤销。工作区 UI 测试覆盖完整 `ContentView` 中的标签身份、多窗口和关闭。检查真实文件字节、原生文本、撤销和滚动，不只断言 ViewModel 字段。

覆盖写入期间编辑、保存失败、重命名、干净／脏文件重载、大小和编码边界、中文／emoji／CRLF、嵌入语言、A→B→A 与关闭失败。具体运行及人工验收范围见 [testing.md](../testing.md)。
