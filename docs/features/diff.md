# 差异查看与编辑

工作区 Git Diff 直接使用 Apple 原生 NSTextView/TextKit 2 编辑器。
Unified 在原文中显示增删标记和不可编辑的删除行；Split 左侧展示只读旧版本，右侧仍为同一编辑器，
不重建文本或撤销栈。编辑状态的 Split 使用当前缓冲区重新计算两侧对照，
不折叠左侧上下文或重复填入替换行；只为真正缺失的行补齐对齐空间。
暂存区及历史提交维持只读 Unified/Split。
本页负责数据读取、渲染、编辑和重挂载。

## Invariants

- **工作区、暂存区和历史分开读取。** 来源分别为工作区、暂存区、历史提交对首父的差异、
  两个明确选定的 Git 提交之间的差异、选定提交的只读原文、
  以及选定提交原文与当前工作区比较。只有普通工作区 Diff 的文本可以编辑和保存；
  暂存和历史来源始终只读。工作区没有额外的 Review/Edit 模式或持久化模式偏好，
  干净工作区文件也可以直接编辑；保存不等于暂存或提交。
- **先判断原始字节。** 任一侧超过 5 MiB、包含二进制或不能解码为 UTF-8 时不提供文本 Diff；
  不能先丢掉 NUL 或无效字节再判断。
- **原生表面属于 `DiffTab`。** 切换项目或重挂载不得丢失编辑、撤销和滚动。
- **编辑后旧读取不得替换缓冲。** 过期请求和不同机器结果都不能生效，符号链接不作为普通文件写入。
- **分栏滚动尊重各自边界。** 两侧水平与垂直联动，短侧不能把长侧拉回；
  内容显示方式不创建第二套工作区分屏。首次打开长文件应在原生布局就绪后定位首个变化，
  不能被初始化期间的滚动同步拉回顶部。
- **Diff 被展示不等于获得键盘焦点。** Git／Files 的浏览可以显示 Diff 而不激活另一个可见组；
  Diff 内部选区、两侧编辑焦点与窗口级交接分别维护。

## 原生渲染

`DiffEngine` 计算行级及行内差异；超过 700 行的重复内容先尝试有编辑距离预算的精确匹配，
不能只因缺少唯一锚点就将小修改扩大为整段删除和新增。
`DiffSyntaxHighlighter` 使用编辑器同一语法与主题，
两侧独立解析结果在后台并行捕获，主线程负责原生富文本。原生视图绘制行号、增删标记和折叠上下文。
原生文本表面关闭自身不透明背景绘制，由下层 Diff 装饰视图统一绘制主题背景、
增删行及词级强调和编辑态删除行；否则系统默认文本背景会遮住真正的差异颜色。
只读差异的语法颜色属于派生富文本：不得对已安装的文本设置 `NSTextView.textColor`，
因为系统会将整篇逐词颜色改为单一颜色；工作区编辑器由原生语法插件管理颜色。
只读统一／分栏和工作区编辑均须检查亮暗外观下的最终像素。
这里不使用 WebKit 或 PierreDiffsSwift；浏览器仍使用 WebKit，两者不要混淆。

工作区 Diff 使用 Git 的清理规则和零上下文差异确认真正改动，再统一交给 `DiffEngine`。
Git 的 `core.autocrlf`、`.gitattributes` 的 `text`／`-text`／`eol` 和 clean filter
决定等价性；Git 的对象 ID 必须与本次读取的工作区内容匹配，
否则整次读取重新开始，不能把不同时间的行号和内容拼起来。
当 Git 的规范化文本与工作区原文逐行对应时，单一编辑器保留原始字节和行号，
并直接在原文上显示变化及删除行。
当过滤器改变内容或行数而无法逐行对应时，左侧同时显示 Git 实际比较的规范化差异，
右侧直接编辑原始工作区文件。不能用规范化行号错误定位原文，也不能丢掉被过滤器隐藏的行。
保存成功后重新读取 Git 比较快照；未保存草稿不会被异步读取覆盖。
源文件和可编辑缓冲区不被过滤器改写；Undo、保存始终保持用户编辑的原始字节。
暂存区和历史提交继续使用读取时已锁定 OID 的 Git blob；
未跟踪及无法进行单路径工作区映射的重命名使用原文比较。
Unicode 规范等价不意味着 Git 原文相同。
按 LF 码点分行，CRLF 的 CR 留在原行文本中，不把 CRLF 当作不可拆的 Swift Character；
源范围始终使用各侧原始 UTF-16 坐标。只读 Diff 的派生文档为 TextKit 行布局补齐最后一个 LF，
原始内容及末行无换行标记不变；裸 CR／Unicode 分隔符导致原生段落数更多时，不用 Git 行数裁剪文本高度；
编辑态行号仅在真正 LF 后递增；同一 Git 行的多段 TextKit 视觉片段都获得对应背景和强调；
长删除块按当前视口直接绘制，不能依赖不在视野中的正文锚点；
延续片段不重复行号／起始删除 ghost，末尾删除 ghost 与缺少换行标记只归真实行尾，
不以当前视口边界冒充文件末尾。删除行占位按实际段落首尾定位，正文全部删除后仍可滚动查看被删行。
换行类型随文本变更更新，滚动绘制不再重复扫描全文。编辑、保存和重载仍保持原字节。

图谱中普通提交默认对首父显示 Diff；⌘选择两条普通提交时，
使用真实 `git diff --name-status -z --find-renames --no-ext-diff <旧端> <新端> --`
获取文件范围，再按选定的两端 OID 读取不可变 blob。
新增、删除与重命名分别保持正确的空侧及旧／新路径；两端都必须是有效提交对象，
不能退化为当前工作树或以 merge-base 替代旧端。比较结果与过期操作须按窗口、
仓库、机器及请求身份核对；空结果不等于读取失败或输出截断。
历史 Git Diff 同样支持图谱里的 Stash：已跟踪文件比较 Stash 的基础提交和保存时的树；
第三父提交保存的未跟踪文件按新增文件读取，不与工作区混淆。
查看历史文件原文复用同一标签拥有的原生 TextKit 表面，
不显示整篇「新增行」或空文件的「没有变化」占位。只读原文和 Diff 均允许选择、复制文本，
但不向辅助功能声明值可写，也拒绝直接的辅助功能文本替换。
历史版本对工作区的 Diff 会在重新选中时读取最新工作文件，遇到真实重命名则解析当前路径；
历史 blob 本身保持不可修改。所有来源共用 5 MiB、二进制和 UTF-8 校验，
Git 命令失败不能被替换成空内容。

文本尺寸、固定行高和只读替换时的滚动是实际依赖契约。只读 Diff 和工作区编辑均沿用原生字宽：
短行不产生虚假横滚，未超过用户设置的超长行绘制宽度时保持可达，分栏只同步合法滚动范围；
普通宽度档位超出宽度时仅截断显示，原文、编辑和保存不截断。
选择「完整显示」时，工作区编辑、只读统一差异及历史原文将超过 24,576 点的长行折至后续视觉行，
避免极宽原生绘制表面导致文字漏画；分栏 Diff 保持 24,576 点单行截断，
否则左右两侧独立折行会打乱 Git 行对应关系。可切换至统一视图查看完整内容。
设置变化立即生效；段落折行不得破坏编辑态删除行占位，分栏仍保持对应行对齐。
只读 Diff 切换到不同正文时横向滚动回到开头，避免只剩长删除行末尾而较短新增行看似空白；
同一正文的主题／字体重绘及折叠展开保持既有横向位置。
替换正文后须以 TextKit 完成的视口布局计算可变行高的阅读锚点，
不能沿用固定「Diff 行号 × 行高」定位；长行折行、裸 CR 等非 LF 段落均在此范围内。
折叠提示的辅助功能按钮使用与屏幕一致的坐标：原生行号栏是翻转的绘制坐标，
不得直接把文字的顶部 Y 坐标当作按钮的无障碍父视图 Y 坐标。
原生布局片段的字符范围用于识别文末虚拟空行：不能用整段富文本长度判断。
Diff 与文件编辑共享 NSTextStorage 的 Undo 通知和只读辅助功能写保护；
编辑态 Diff 还通过原生 `NSTextViewDelegate` 把自有 UndoManager 交给 AppKit。
真实 App 的编辑／Undo／Redo／⌘S 已有独立 XCUITest，并核对实际工作区字节；
宿主直接调用 UndoManager 不能替代该路径。
核验入口见 [development.md](../development.md#依赖与本地补丁)。

## 保存与失败

工作区 Diff 的编辑、自动保存和原生缓冲保护遵守 [editor.md](editor.md)。保存失败保留内容及错误；
断线只读、重连绑定及旧结果失效遵守 [ssh.md](ssh.md)。不能为恢复显示重建一份内容或改写其他路径。

输入、保存、断线或换通道使读取失效时，同一加载拥有者同时结束该代次的等待；
旧读取不能清除后来请求的加载状态。撤销回干净内容后仍可重新选择并刷新，不会因遗留 loading 永久卡住。

历史 Git 操作后允许重读没有未保存改动的工作区 Diff，并更新同一原生表面的文本；
通常导航可刷新干净文件，未保存编辑阻止旧读取覆盖正文。
已成功加载的不可变历史标签再次打开时复用原文，不重新查询 Git；live 文件重新选择时继续检查外部变化。

Git 内容先通过原始 NUL 分隔的 index／tree metadata 匹配字面路径，选定 blob OID 后才读大小与字节；
冲突取 index 0／2／1；只有 HEAD 所指分支引用确实不存在，才允许首次提交的空旧侧；
暂存删除文件的空 index 和有效历史删除提交的空 tree 可以是空侧。
悬空分支、无效删除提交、仅有冲突阶段却没有 stage 0 的 index，以及无效 revision、损坏 metadata、
权限／断线／超时和短读都必须报错。读取失败时展示错误并保留已成功显示的原生文本，
包括之后更换字体或主题；不能把故障变为空文件。折叠展开仅使用对应当前内容的解析结果；
较新读取开始计算后，旧内容的折叠操作不能抢先发布旧文本。

## 验证

`DiffEngineTests` 验证行／词差异及字节坐标；
`NativeDiffTabTests` 与 `NativeGitHistoryFileTests` 使用真实临时 Git 仓库和原生 TextKit，
覆盖 Git 规范化／过滤器、布局、保存、只读来源、失败与恢复。
`WorkspaceGitUITests` 验证 Git Changes／Graph 打开、实际键盘输入、跨界面焦点及最终文件字节。
更改虚拟删除行绘制后，除首屏外必须在深处滚动的多个删除块之间验证可见像素；
只检查靠近正文锚点的一块会漏掉视口定位错误。
测试入口、适用环境和完成标准归 [testing.md](../testing.md)。
