# 差异查看与编辑

Diff 使用 Apple 原生 NSTextView/TextKit 2 显示统一或分栏差异。本页负责数据读取、渲染、编辑和重挂载；相关行为或底层文本依赖改变时更新。

## Invariants

- **工作区、暂存区和历史分开读取。** 来源分别为工作区、暂存区、历史提交对首父的差异、选定提交的只读原文、选定提交原文与当前工作区比较。只有普通工作区 Diff 的文本可以编辑和保存；历史来源即使全局编辑模式已开启也始终只读。保存不等于暂存或提交。
- **先判断原始字节。** 任一侧超过 5 MiB、包含二进制或不能解码为 UTF-8 时不提供文本 Diff；不能先丢掉 NUL 或无效字节再判断。
- **原生表面属于 `DiffTab`。** 切换项目或重挂载不得丢失编辑、撤销和滚动。
- **编辑后旧读取不得替换缓冲。** 过期请求和不同机器结果都不能生效，符号链接不作为普通文件写入。
- **分栏滚动尊重各自边界。** 两侧水平与垂直联动，短侧不能把长侧拉回；内容显示方式不创建第二套工作区分屏。

## 原生渲染

`DiffEngine` 计算行级及行内差异，`DiffSyntaxHighlighter` 使用编辑器同一语法与主题，两侧独立解析结果在后台并行捕获，主线程负责原生富文本。原生视图绘制行号、增删标记和折叠上下文。原生文本表面关闭自身不透明背景绘制，由下层 Diff 装饰视图统一绘制主题背景、增删行及词级强调和编辑态删除行；否则系统默认文本背景会遮住真正的差异颜色。统一、左右分栏与编辑模式须在亮暗外观下检查最终可见像素，而非仅验证差异数据。这里不使用 WebKit 或 PierreDiffsSwift；浏览器仍使用 WebKit，两者不要混淆。

文本、行和行内 token 按 UTF-8 原始字节比较；Unicode 规范等价不意味着 Git 原文相同。按 LF 码点分行，CRLF 的 CR 留在原行文本中，不把 CRLF 当作不可拆的 Swift Character；源范围始终使用各侧原始 UTF-16 坐标。只读 Diff 的派生文档为 TextKit 行布局补齐最后一个 LF，原始内容及末行无换行标记不变；裸 CR／Unicode 分隔符导致原生段落数更多时，不用 Git 行数裁剪文本高度；编辑态行号仅在真正 LF 后递增；同一 Git 行的多段 TextKit 视觉片段都获得对应背景和强调；延续片段不重复行号／起始删除 ghost，末尾删除 ghost 与缺少换行标记只归真实行尾，不以当前视口边界冒充文件末尾。删除行占位按实际段落首尾定位，正文全部删除后仍可滚动查看被删行。换行类型随文本变更更新，滚动绘制不再重复扫描全文。编辑、保存和重载仍保持原字节。

历史 Git Diff 同样支持图谱里的 Stash：已跟踪文件比较 Stash 的基础提交和保存时的树；第三父提交保存的未跟踪文件按新增文件读取，不与工作区混淆。查看历史文件原文复用同一标签拥有的原生 TextKit 表面，不显示整篇「新增行」或空文件的「没有变化」占位。只读原文和 Diff 均允许选择、复制文本，但不向辅助功能声明值可写，也拒绝直接的辅助功能文本替换。历史版本对工作区的 Diff 会在重新选中时读取最新工作文件，遇到真实重命名则解析当前路径；历史 blob 本身保持不可修改。所有来源共用 5 MiB、二进制和 UTF-8 校验，Git 命令失败不能被替换成空内容。

文本尺寸、固定行高和只读替换时的滚动是实际依赖契约。
原生布局片段的字符范围用于识别文末虚拟空行：不能用整段富文本长度判断。
Diff 与文件编辑共享 NSTextStorage 的 Undo 通知和只读辅助功能写保护，
核验入口见 [development.md](../development.md#依赖与本地补丁)。

## 保存与失败

工作区 Diff 的编辑、自动保存和原生缓冲保护遵守 [editor.md](editor.md)。保存失败保留内容及错误；断线只读、重连绑定及旧结果失效遵守 [ssh.md](ssh.md)。不能为恢复显示重建一份内容或改写其他路径。

输入、保存、断线或换通道使读取失效时，同一加载拥有者同时结束该代次的等待；旧读取不能清除后来请求的加载状态。撤销回干净内容后仍可重新选择并刷新，不会因遗留 loading 永久卡住。

历史 Git 操作后允许重读正在编辑模式的干净 Diff，并更新同一原生表面的文本；通常的导航重读仍不干扰编辑模式。在途读取及操作期间新增的未保存编辑都不得被覆盖。已成功加载的不可变历史标签再次打开时复用原文，不重新查询 Git；live 文件重新选择时继续检查外部变化。

Git 内容先通过原始 NUL 分隔的 index／tree metadata 匹配字面路径，选定 blob OID 后才读大小与字节；冲突取 index 0／2／1；只有 HEAD 所指分支引用确实不存在，才允许首次提交的空旧侧；暂存删除文件的空 index 和有效历史删除提交的空 tree 可以是空侧。悬空分支、无效删除提交、仅有冲突阶段却没有 stage 0 的 index，以及无效 revision、损坏 metadata、权限／断线／超时和短读都必须报错。读取失败时展示错误并保留已成功显示的原生文本，包括之后更换字体或主题；不能把故障变为空文件。折叠展开仅使用对应当前内容的解析结果；较新读取开始计算后，旧内容的折叠操作不能抢先发布旧文本。

## 验证

`DiffEngineTests` 检查原文字节重建及 UTF-16 行内范围；`DiffTabTests` 与 `GitHistoryFileTests` 检查原生文本、不同历史来源、空文件、Git 读错误、重命名、二进制、超限、只读边界、刷新与重新挂载。覆盖统一／分栏、行内差异、编辑、撤销、保存、未跟踪、暂存、历史、字节与大小边界、两侧内容宽度不同、快速切换及在途读取。

还需在完整工作区中验证文件→Diff→文件的内容身份和焦点。接口返回或桥接成功不代表用户可用；性能测量须包含 TextKit 首屏、滚动和编辑，而不是 WebKit 指标。入口见 [testing.md](../testing.md)。
