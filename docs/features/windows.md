# macOS 窗口与系统入口

维护原生窗口生命周期、系统菜单、Finder／Dock 文件投递和跨窗口路由。窗口接入或系统入口变化时更新；分屏和标签交互见 [Dock](dock.md)。

## Invariants

- **每个窗口只有一个模型。** 应用级只协调登记、路由和恢复，不复制项目。
- **系统动作绑定实际目标。** 晚到请求、后台窗口及临时菜单不得改变目标。
- **外部文件打开与复制分离。** Finder 投递由接收区域决定，不猜测项目或机器。
- **关闭是原生生命周期事件。** 数据保护成功后才释放内容；快照与文件保存独立。

## 原生窗口与菜单

`WindowRootView` 持有 `WorkspaceWindowModel` 协调单窗，
delegate 的 `WorkspaceApplication` 只负责跨窗口登记、路由及恢复。
窗口核对跨组焦点交接，输入仍归实际挂载的原生控件；见 [架构规范](../architecture.md#焦点协调边界)。
`WindowChromeAccessor` 在原生视图实际挂载到窗口时绑定 `NSWindow`，
不能依赖一次异步检查或 SwiftUI 恰好再次更新；
否则新建的空工作区窗口会显示「添加文件夹」却无法弹出选择器。
`.focusedSceneValue(\.baileyManager, manager)` 和菜单中的 `@FocusedValue` 连接当前窗口；
菜单栏「文件 → 打开文件…」（⌘O）打开当前窗口的本机文件选择面板，
标签栏「＋ → 打开文件…」在发起的停靠组打开。两者均支持单／多选、只选择文件且要求已有项目。
本机资源只交给本机后端。新文件须为可读普通文件，目录须可读取、可遍历；
不可读资源、命名管道等特殊文件、失效链接、包目录及非本机 URL 不创建新标签或项目。
已打开标签仍优先复用；外部打开不新增保存路径。
设置窗口或切换窗口后不得把 Sheet 和结果错误投到后台项目。

应用在真实场景登记时认领窗口。隔离 Dev 的 Commands 先登记开窗动作，AppKit 激活后才请求唯一首窗；
末窗关闭后连续 Finder 请求只触发一次新窗口，已请求或尚未附着的场景不重复创建。

## 系统文件投递

系统从 Finder／Dock 交给 Bailey 的本机文件请求，先检查所有窗口内已有的**本机文件标签**，
即使标签属于 SSH 项目也按文件自身的机器身份判断：存在时激活原窗口／原项目／原标签，
不制造第二份可写缓冲。否则在实际接收窗口的**当前项目**中新建本机标签，
项目目录范围不限制能打开的文件；没有项目时不自动创建项目。恢复中的窗口先完成附着再处理文件；
连续到达的合法文件打开事件逐个等待实际文件所有者附着，不以固定的请求条数丢弃后续事件，
已打开文件仍只保留一个标签。原 Finder 文件夹 Service 保留添加目录项目的语义。

Finder 的 `fileURL` 拖放按接收区域分流：空工作区、普通编辑／Diff、顶部工作标签栏、
空停靠组及 Git 面板为**打开或复用文件标签**；
每个分屏的顶部标签栏、空组内容区及普通编辑／Diff／Git／浏览器工具栏区域锁定实际接收的 `DockGroup`，
新文件在该组建立标签（含空组），已打开的文件仍激活原标签而不强制搬组；
Projects 面板为**文件打开当前项目的标签、文件夹添加目录项目**；
Files 面板则依据行／根标题／留白准确把文件或目录**复制进目标文件夹**，不额外打开 FileTab。
原生 WebKit 正文自行处理网页文件上传，Ghostty 终端正文只处理本机 Shell 路径文本，
**两者上方都不挂通用 Drop**；浏览器工具栏可打开文件。
唯一的 Finder `NSItemProvider<NSURL>` 异步转换由 `FinderWindowDrop.receive` 持有，再交给相应动作；
始终绑定触发时的 `WorkspaceWindowModel`、`NSWindow` 和项目身份；
文件 provider 晚到或跨窗口恢复队列延迟时，也不得重定向到后来选中的项目。
应用在向已有文件所属窗口分流前核对显式 `(projectID, groupID)` 是否仍属于接收窗口；
若用户已切换项目或原组已消失，拒绝该投放，不能无声改投另一个项目或默认组。
内部 Dock 标签移动只走 `DockTabDragCoordinator`，不伪装 Finder 文件 URL。

系统文件入口使用同一份 `Info.plist` 的 `CFBundleDocumentTypes` 将文本、
图片和目录注册为 **Alternate**（备用程序）。
`BaileyApplicationDelegate` 在 AppKit 启动阶段注册唯一的 `kAEOpenDocuments` 处理器，
从系统 Apple Event 的文件列表还原**整个批次**，再交给 `WorkspaceApplication.openExternalFiles`。
不能只依靠 SwiftUI `.onOpenURL`（只传第一个文件，且导致另建工作区窗口），
也不保留不会被执行的 `application(_:openFiles:)` 回调。此入口不替换 Finder Service `openInBailey`，
也不拦截任意非文件网页 URL。正式版文件声明表示 Bailey 是候选打开程序，
**不保证未知／二进制文件可编辑**。Bailey Dev 的相同文档类型声明使用 `LSHandlerRank=None`，
不参与默认文件打开程序竞争；开发版 Finder Service 名称另标记为 Bailey Dev。

Finder／Dock 的外部打开请求不是工作区快照。
冷启动及末窗关闭后收到的文件请求，会先等待已经保存的窗口完成创建和原生窗口附着，
再检查所有恢复文件标签是否已有目标；避免同一文件被提前打开为第二份可写缓冲。
若已有文件所属的未附着窗口提前关闭，立刻重新核对仍有效的接收窗口；
接收项目已改变则明确拒绝，不能让请求永久等待或改投另一个项目。
该等待只用于应用窗口生命周期，不新增持久化队列或任意重试计时器。

## 系统菜单

系统菜单按顺序为编辑、面板、项目、文件、终端、浏览器与窗口（应用菜单除外）。
「面板」依次提供命令面板、工具面板、上／下一个工作面板、关闭（⌘W）及已打开工作面板列表；
Projects、Files、Git 只保留固定入口，不参与动态列表与前后切换。
面板切换规则见[Dock](dock.md#面板切换与关闭)。
「项目」先提供 Add Projects、Add SSH Files or Projects、上／下一个项目、关闭项目，再列出项目；
「编辑」除原生剪切／复制／粘贴外，还提供 Save ⌘S。
「文件」提供新建、打开文件，复制路径 ⌥⌘C、相对路径 ⌥⇧⌘C，
以及本机 Finder 定位 ⌥⌘R；这些命令以当前 Files／Git 树或文件编辑器／标签栏的真实键盘目标为准，
没有有效路径时置灰；Finder 定位只支持本机文件（包括在 SSH 项目中打开的本机文件），
不支持 SSH 路径。右键菜单使用原生快捷键直接操作本次命中对象，不经系统菜单转发。
「文件」菜单提供 Stage All Changes（⇧⌘Y）、Diff 布局（⌥⌘U）与 Commit Staged（⌘Return）；
启用与执行目标分别遵循 [Git Changes](git-changes.md)和 [Diff](diff.md)，不另写业务规则。
菜单中的工作面板显示文件类型图标和浏览器 favicon（`README.md` 等 `.md` 文件统一显示 Markdown 图标）；
项目图标区分本机与 SSH；菜单显式使用标题＋图标样式，避免 macOS 27 默认隐藏。
工作面板与项目列表都显示全部条目。工作面板按 Dock 顺序排列，仅前九项使用 ⌃1–9；
Project 标识当前窗口的项目，Panel 标识活动 Dock 组的当前内容；只有当前项的文字和单色系统图标使用系统强调色（SwiftUI 原生 Label）。
文件类型图标及网站 favicon 保留原色；并排预览对应同一文件条目，活动工具面板则标识对应工具命令。不额外添加勾号。
系统 Panel／Project 菜单展开期间固定本次标题、图标、选中状态和条目顺序；关闭后恢复最新状态，
避免终端或浏览器标题的实时变化干扰原生菜单高亮。工作区标签始终显示内容标题。
项目列表仅前九项使用 ⌘1–9，其余条目不占用数字快捷键。
无工作面板时列表隐藏；不足两个工作面板时前后切换禁用。快捷键始终指向当前窗口的项目。
终端、浏览器的内容动作各归所属菜单；窗口保留新建、全屏、原生窗口管理及内容缩放命令。
Window 列表显示每个窗口的所有项目名（按项目顺序以 ` · ` 分隔），各窗当前项目以系统强调色标识。
当前主窗口的窗口图标使用从系统 Emoji 字体支持的自然／动物字符中随机选取、生命周期内固定的彩色 Emoji，不额外显示勾号；窗口切换仍由 AppKit 执行。
空窗口沿用应用名。原生菜单跟踪结束后恢复系统展示属性，不替换菜单项、动作或窗口身份。
Panel／Project 动态内容仅更新对应菜单行，不重建系统菜单，以保留 Window 的移动和平铺命令。
窗口保留原生标题栏拖动与 Window 菜单的移动、居中和平铺能力；
SwiftUI 禁用背景自动拖动，三组的真实留白仍可移动窗口；双击遵循系统设置（缩放、最小化或无动作）。
标签后方的空白覆盖层必须具有完整标题栏高度，不能只有可见宽度却无法接收双击。
标签／分隔线拖动仍交给 SwiftUI，右键与中键复用既有菜单命中层，不增加争抢左键的原生覆盖层。
当前标签、分隔线和「＋」按钮的悬停回调仍会临时更改整窗 `NSWindow.isMovable`；
窗口失焦、重新挂载或恢复后，必须检查原生窗口移动能力和空白区双击没有残留异常状态。
不使用额外的系统「显示」菜单或 macOS 原生窗口标签页，避免与 Bailey Dock 重复。

真正关闭窗口以 `NSWindow.willCloseNotification` 为准：从 `WorkspaceApplication` 注销窗口，
保存剩余窗口；若为最后一窗则保留可重开的末窗快照。关闭后终止并释放该窗口的项目及标签；不依赖 SwiftUI `.onDisappear`，重复通知不得重复清理或覆写快照。
Panel／Project 动态菜单只持有轻量标题、ID 和序号，不直接持有 `PaneTab` 或 `Project` 数组，
避免系统菜单缓存延长已关闭窗口的正文生命周期。

标签关闭及右键目标见[Dock](dock.md#面板切换与关闭)。
没有有效 Dock 面板目标时才进入原生窗口关闭流程，关闭窗口及退出仍等待保存，
不截断 SwiftUI 的窗口生命周期。

## 验证

**Finder 与窗口路由专项。**

- 单／双窗口、空态、已恢复窗口、普通编辑区、Git、实际目标分屏、顶部标签栏，验证新增／复用、不迁组。
- ⌘O、组「＋」的文件多选与 ⇧⌘A 的目录选择；Projects 文件／目录落点、重复项目与 SSH 单文件。
- Files、Ghostty、WebKit 的拖放必须核对原始字节、目录复制、输入路径或网页上传，而不是只核对鼠标事件。
  具体数据保护见 [文件操作](file-operations.md)，终端与网页规则见各自功能页。
- 取消、晚到、发起后切项目、Dock 组消失、本机／SSH 同名、50+ 混合重复文件；
  内部标签和 Projects 重排不得与外部投递混淆。

窗口恢复后的 Dock 双击曾被报告间歇性失效。现有用例分别覆盖新建双窗与关闭重启，尚无连续「新建第二窗 → 关闭两窗 → 退出 → 重启恢复 → 双击」的完整验收证据；三区测试在系统双击为「最小化」或「无动作」时跳过。

`AppIdentityTests` 检查应用身份、文件类型及原生快捷键注册；
`FinderDeliveryIntegrationTests` 验证批次、跨窗口复用、恢复队列和过期落点。
`WindowOwnershipIntegrationTests`、`WindowCloseIntegrationTests` 检查双窗归属、Sheet 与关闭否决；
`WorkspaceWindowsUITests`、`WorkspaceDockUITests` 检查系统投递、窗口菜单、拖动、双击及真实重启。
环境见[测试环境](../testing-environment.md)；保存契约见[文件保存](file-saving.md)。
