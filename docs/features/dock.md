# 自由停靠、标签与窗口

各类内容以独立标签进入可自由组合的工作区。本页负责布局、移动、焦点和关闭；相关行为或状态所有权改变时同步更新。

## Invariants

- **`DockNode` 是唯一外层布局。** 面板与标签一一对应，标签内部没有第二套分屏；Diff 的统一／并排显示只是内容布局。
- **每个区域地位相同。** 使用相同的「＋」入口，工具面板移动而不是重复创建；默认三列不是固定侧栏权限。
- **移动不等于重建。** 切项目、拖动、重挂载后仍使用原内容和原生表面，不结束 Shell、不丢编辑与滚动。
- **焦点属于当前窗口和内容。** 菜单不能借用后台窗口的管理者，关闭或移动后焦点必须落在有效内容。
- **关闭先保护数据。** 文件写入失败不能关闭窗口／项目，也不能结束其中正在运行的终端。

## 布局与标签

每个项目保留自己的停靠结构，初始配置只决定新项目的布局。`Project` 拥有布局和标签，`PaneTab` 恰有一份内容；同一位置切换 A、B 标签时，以标签 ID 区分 SwiftUI 身份，而不是复用错误的原生内容。

每组的 `selected` 决定展示内容，`DockWorkspaceModel.activeGroupID` 单独记录当前活动区域，可指向工具面板或空组。切换区域不会改变其它组展示的标签，也不触发快照保存。移动完成后活动区域跟随落点；删除区域或恢复布局后只保留有效组。`Project.selectedTabID` 仍记录最近工作标签和会话上下文，菜单内容目标则从活动组解析；工具活动时不会借用旧工作标签执行保存、清空、查找或浏览器动作，⌘W 关闭该工具面板。

显式选择工作标签使用 `Project.selectTab`；最近标签的关闭记账不再隐式激活区域。关闭后台标签不会把工具或另一个可见区域的焦点拉走。**文件树单击浏览**可以在另一个组显示文件标签而不激活那个组，双击才明确切入编辑器；若标签与 Files 实际同组、Files 因打开被隐藏，则焦点跟随可见编辑器，不能留下隐藏工具的虚假焦点。Git Changes 与 Git Graph 文件行单击、Space 或 Return 只在其它可见组展示 Diff，保留原 Git 活动组及各自的行键盘焦点；图谱提交的选择不等于详情展开。若 Git 组被 Diff 实际替换，则焦点跟随可见内容，不保留隐藏工具的假焦点。菜单、Finder、⌘P 与显式标签打开继续激活目标，不受工具列表浏览语义影响。

焦点视觉参考 Zed 默认行为：分屏不再绘制活动边框、不降低非活动内容的整体透明度。每组保留自己的 selected 标签背景；仅当前活动且真正接收输入的组突出已选标签的文字和图标，后台、临时输入及其余组则弱化。悬停和拖放预览不制造假焦点；不能只凭视觉判断原生输入归属。

命令面板显示时，切换 Files/Git 也不能抢走搜索框输入；取消时只在当前 key window 恢复可见原生控件。若面板期间切换过工具，旧编辑器或旧树不再属于当前活动组，则恢复当前可见的工具树，而不是旧输入控件。执行命令时不恢复旧控件。终端查找同样检查实际可见宿主，不能仅因停车表面仍有 `window` 就恢复它。移动成功才激活落点，hover 和取消不改变活动组。

移走标签只折叠它原来的空组，不提前删除其它空落点；空组中央和四个边缘都可接收工具。恢复产生新组 ID 时只重建轻量焦点读点，标签持有的原生文档不变。终端停车立即解除旧宿主动作，不依赖可能晚到的卸载回调。

标签、内容、工具和空白区域的点击都归属所在组。原生后台读点负责识别区域，但**不再在鼠标按下、原生控件处理事件之前强抢键盘焦点**：有编辑器、终端或浏览器的组交由内容自己的第一响应者接管；Files 行单击或通过标签从编辑器／Git 切回 Files 时，把原生第一响应者交给文件树并恢复选中行；文件树重新挂载也须等原生视图进入窗口，不能只更新 SwiftUI 行选择后留下旧编辑器继续接收按键；工具/空组在事件已交付后，只有新控件未取得焦点时才解除旧组编辑器的输入焦点。重命名、新建和查找输入框自行接管，不能被后台读点夺回。TextKit、Ghostty、WebKit 和 Diff 的原生焦点回调同步所属组，临时查找栏、命令面板和 Sheet 不另选工作组。自动焦点请求只在前台 key window 的活动内容有效，延迟执行前再次核对；移动同一活动内容不经过临时工具回退，不因布局变化额外保存。

共享 field editor 按实际输入控件判断归属；可见范围须与控件自身边界相交，不能把 SwiftUI 未裁剪的整窗可见范围当成输入框位置。

标签重命名属于显示名称：Return 或失焦提交，Escape 取消，空名称返回自动标题。各区域标签栏仅在标签总宽度超过可用空间时水平滚动；标签全部放得下时不回弹，窗口或分屏调整大小后自动重新判断。状态变更、恢复和持久化边界见 [session-restore.md](session-restore.md)。

## 窗口与菜单

主窗口由 `WindowRootView` 的 `TerminalManager` 协调。`WindowChromeAccessor` 在原生视图实际挂载到窗口时绑定 `NSWindow`，不能依赖一次异步检查或 SwiftUI 恰好再次更新；否则新建的空工作区窗口会显示「添加文件夹」却无法弹出选择器。`.focusedSceneValue(\.baileyManager, manager)` 和菜单中的 `@FocusedValue` 连接当前窗口；菜单栏「文件 → 打开文件…」（⌘O）打开当前窗口的本机文件选择面板，标签栏「＋ → 打开文件…」在发起的停靠组打开。两者均支持单／多选、只选择文件且要求已有项目。设置窗口或切换窗口后不得把 Sheet 和结果错误投到后台项目。

系统从 Finder／Dock 交给 Bailey 的本机文件请求，先检查所有窗口内已有的**本机文件标签**，即使标签属于 SSH 项目也按文件自身的机器身份判断：存在时激活原窗口／原项目／原标签，不制造第二份可写缓冲。否则在实际接收窗口的**当前项目**中新建本机标签，项目目录范围不限制能打开的文件；没有项目时不自动创建项目。恢复中的窗口先完成附着再处理文件；连续到达的合法文件打开事件逐个等待实际文件所有者附着，不以固定的请求条数丢弃后续事件，已打开文件仍只保留一个标签。原 Finder 文件夹 Service 保留添加目录项目的语义。

Finder 的 `fileURL` 拖放按接收区域分流：空工作区、普通编辑／Diff、顶部工作标签栏、空停靠组及 Git 面板为**打开或复用文件标签**；每个分屏的顶部标签栏、空组内容区及普通编辑／Diff／Git／浏览器工具栏区域锁定实际接收的 `DockGroup`，新文件在该组建立标签（含空组），已打开的文件仍激活原标签而不强制搬组；Projects 面板为**文件打开当前项目的标签、文件夹添加目录项目**；Files 面板则依据行／根标题／留白准确把文件或目录**复制进目标文件夹**，不额外打开 FileTab。原生 WebKit 正文自行处理网页文件上传，Ghostty 终端正文只处理本机 Shell 路径文本，**两者上方都不挂通用 Drop**；浏览器工具栏可打开文件。唯一的 Finder `NSItemProvider<NSURL>` 异步转换由 `FinderWindowDrop.receive` 持有，再交给相应动作；始终绑定触发时的 `TerminalManager`、`NSWindow` 和项目身份；文件 provider 晚到或跨窗口恢复队列延迟时，也不得重定向到后来选中的项目。显式 `(projectID, groupID)` 在真正打开前还须核对组是否仍有效；若用户已切换项目或原组已消失，拒绝该投放，不能无声改投另一个项目或默认组。内部 Dock 标签移动只走 `DockTabDragCoordinator`，不伪装 Finder 文件 URL。

「显示」菜单使用统一面板、项目和标签动作。保存读取聚焦内容的未保存状态；设置窗口或空工作区的关闭仍使用系统窗口关闭语义，不强行路由到某个工作标签。

关闭工具面板不删除项目；关闭工作标签只处理它自己的内容。关闭窗口与应用退出先等待真实保存，失败保留窗口；原生关闭通知仍须到达 SwiftUI，不能因自定义保护截断窗口生命周期。
