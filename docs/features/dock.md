# 自由停靠、标签与窗口

各类内容以独立标签进入可自由组合的工作区。本页负责布局、移动、焦点和关闭；相关行为或状态所有权改变时同步更新。

## Invariants

- **`DockNode` 是唯一外层布局。** 面板与标签一一对应，标签内部没有第二套分屏；Diff 的统一／并排显示只是内容布局。
- **每个区域地位相同。** 使用相同的「＋」入口，工具面板移动而不是重复创建；默认三列不是固定侧栏权限。
- **移动不等于重建。** 切项目、拖动、重挂载后仍使用原内容和原生表面，不结束 Shell、不丢编辑与滚动。
- **焦点属于当前窗口和内容。** 菜单不能借用后台窗口的管理者，关闭或移动后焦点必须落在有效内容。
- **关闭先保护数据。** 文件写入失败不能关闭窗口／项目，也不能结束其中正在运行的终端。

## 布局与标签

每个项目保留自己的停靠结构，初始配置只决定新项目的布局。`Project` 拥有布局和标签，`PaneTab` 恰有一份内容；同一位置切换 A、B 标签时，以标签 ID 区分 SwiftUI 身份，而不是复用错误的原生内容。

标签重命名属于显示名称：Return 或失焦提交，Escape 取消，空名称返回自动标题。各区域标签栏仅在标签总宽度超过可用空间时水平滚动；标签全部放得下时不回弹，窗口或分屏调整大小后自动重新判断。状态变更、恢复和持久化边界见 [session-restore.md](session-restore.md)。

## 窗口与菜单

主窗口由 `WindowRootView` 的 `TerminalManager` 协调。`.focusedSceneValue(\.baileyManager, manager)` 和菜单中的 `@FocusedValue` 连接当前窗口；新增菜单动作要核对双窗口焦点切换。

「显示」菜单使用统一面板、项目和标签动作。保存读取聚焦内容的未保存状态；设置窗口或空工作区的关闭仍使用系统窗口关闭语义，不强行路由到某个工作标签。

关闭工具面板不删除项目；关闭工作标签只处理它自己的内容。关闭窗口与应用退出先等待真实保存，失败保留窗口；原生关闭通知仍须到达 SwiftUI，不能因自定义保护截断窗口生命周期。

## 验证

`DockWorkspaceTests` 验证布局规则；`PaneRetentionTests` 和工作区 UI 测试验证原生身份、焦点、关闭保存与跨窗口隔离。模型测试不代替真实拖动、键盘和输入验收。覆盖上下／左右组合、跨区域拖动、A→B→A、双窗口切换、关闭失败与恢复。
