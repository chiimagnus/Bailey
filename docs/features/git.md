# Git 状态与操作

本页负责仓库状态、刷新、命令环境、提交和草稿。相关行为改变时同步更新；Diff 见 [diff.md](diff.md)，共享树见 [files.md](files.md)。

## Invariants

- **仓库身份包含机器和路径。** 状态、折叠、草稿与操作不能串仓库；工作区、索引和提交历史彼此不同。
- **核心先可用，失败时按阶段保留。** 文件状态、分支／HEAD、上游及进行中的 Git 操作先校验；Ref／远端、历史、Stash、忽略装饰和行数随后读取。核心查询失败保留已成功的分支、状态和历史，禁止 Git 写操作并提供重试。详情失败不撤销成功的核心，也不清空旧详情，但仅允许依赖**已经验证**的数据执行操作：暂存和提交只要求核心，Ref／远端操作还要求本次有效的 Ref 元数据，历史提交操作要求当前历史，Stash 记录操作要求当前 Stash 列表。Ref／远端查询失败只撤销引用和依赖引用的历史操作资格；已单独核验的 Stash 列表仍可使用，忽略装饰或行数失败不影响 Git 写操作。正常后台刷新不禁用目标未变的已验证操作，执行前仍核对当前项目和 HEAD；切目标或确认不是仓库时才清除。
- **旧结果不覆盖新操作。** 刷新合并进行中的请求；旧连接、旧范围和操作前的查询不能覆盖当前状态。
- **破坏性操作在确认后重新校验。** 用户确认前后项目、机器、HEAD 或文件变化都不能继续执行旧操作。
- **所有命令参数保留数据边界。** 文件名、提交说明和分支不能直接拼成未经处理的 shell 语法。

## 刷新与显示

应用激活、项目变化、Kero 终端命令完成和手动刷新仍立即请求 Git 状态。独立 CLI 不发这些事件，因此可见且 App 前台的 Git 面板复用已有周期任务：本机每 2 秒、SSH 每 5 秒检查一次，自动识别外部文件修改、暂存和新提交。本机也能发现普通目录中新初始化的 Git 仓库。正在刷新或执行 Git 写操作时跳过周期请求；App 后台或 Git 面板隐藏时停止查询，包括 SSH。远端复用原有批量 Git 查询，并与固定 SSH 项目的终端共享 OpenSSH master，不新增常驻监听；请求合并、超时与换连接后旧结果失效的约束不变。

**2／5 秒是刷新触发间隔，不是界面响应时限。** SSH 首次连接、网络和批量 Git 读取可能使实际刷新晚于一个周期。远端首先批量读取仓库身份、分支和文件变化，核对进行中的 Git 操作后即更新核心状态；Ref／远端、历史、Stash 与忽略装饰随后批量读取，文件行数单独受限统计。附加查询失败保留原有 Graph、Stash 与忽略装饰作为只读展示；已验证的 Ref、历史与 Stash 分别保留操作资格，不互相拖累；核心刷新失败时保留最后快照与错误提示，暂停 stage、discard、commit、push 等写操作，仍可查看历史和文件。切换 SSH 通道或从旧缓存恢复仓库时也先以只读方式展示，重新取得核心状态后才开放写操作。核心失败与历史/Stash 等详情失败显示不同提示；根目录探测失败时的重试重新解析当前项目，不对旧根盲目刷新。连接恢复且核心状态确认后恢复操作。自动工作区 Git 根探测保留 SSH 错误语义，断线不可误判为切换了仓库。

已知的暂存／取消暂存只重读核心与工作区行数（不重新查询 Ref／远端元数据）：HEAD、分支或进行中操作没有变化时继续使用已验证的历史／Ref／Stash，身份变化或尚无有效详情时立即补一次完整查询。历史分页只读取当前范围的状态、Ref 与扩大 limit 的日志，不重复查询 Stash 或文件行数；分页日志失败保留已验证的上一页与行数，不自动重查全部详情，只有仓库核心或 Ref／HEAD 发生变化才重新获取完整一致快照。其他 Git 操作、激活、周期、手动刷新仍做完整查询；排队中的完整刷新不得被局部操作降级。

尚无提交的仓库仍支持状态、未跟踪文件与首次暂存。暂存、取消暂存、普通提交和 Amend 只依赖已校验的核心，Amend 依据 HEAD 而非历史是否加载；分支、引用及远端操作只要求已校验的核心与 Ref；历史提交操作还要求本次有效的历史；既有 Stash 的 Apply/Pop/Drop 等要求本次有效的 Stash 列表。创建新 Stash、Reset、Clean 只要求核心；每次真正写入前仍核对目标、HEAD、相关 Ref 或 Stash。新建 Tag 后立即推送仍读取实际对象 OID，并在写操作前校验，不等待旧快照出现新 Tag。

首次加载失败或超时必须退出等待并允许重试。本机／SSH 的刷新工作共用整次预算，SSH 存活检查也计入调用预算；独立界面超时仍保留已成功状态。SSH 核心与详情分批读取，失败或缺帧不逐命令重新取整份快照。

未跟踪统计最多查看 2048 个文件，每文件最多读取 8 MiB、整次最多 32 MiB，实际读取也受剩余预算约束。前 8000 字节含 NUL 视为二进制，symlink 计一行，末行无换行仍计入。超预算显示省略号而非精确的零；读取失败保留状态并报告错误。远端统计只返回带预算校验的数值记录，文件名中的换行不能伪造行数。

核心状态刷新以 `GitStatus` OSLog 类别只记录请求序号、阶段、耗时及完成状态，不记录远端主机、私有仓库路径或命令输出。

Git 图谱按提交时间优先（Git `--date-order`，子提交仍在父提交之前）读取本地分支、远端跟踪分支、Tag 与 HEAD 可达的提交，与 VS Code Git Graph 默认顺序一致。每条记录保留完整父提交列表和有类型的引用，包含合法带逗号的分支及 Tag 名称；合并提交的文件列表及历史 Diff 都与第一父提交比较，不把其它父提交当作文件基线。

提交图谱沿已加载提交的真实父关系绘制多车道分支与 Merge 连线；颜色属于图谱逻辑路径，不再让当前 HEAD／main 固定占用蓝色，跨车道避障也不改变原分支线条颜色。第一个可见提交路径从蓝色开始，并行路径优先区分颜色、结束后可以复用，超过 12 条活跃路径时允许重复色位。每条父边沿空闲车道连接真实提交节点，避开其它提交节点，必要时临时绕行；尚未加载的父提交不绘制虚构连线，刷新同一历史输入的颜色保持稳定。Stash 是独立的展示节点，仅连接其可见基础提交，不继承／覆盖普通提交路径的颜色；展开文件时已有关系线持续贯穿。每个提交第一行在图谱右侧先显示 Ref／Stash 标签，再显示提交标题；Merge 只弱化标题文字，悬停或选中时恢复正常对比。第二行保持短 SHA、作者和靠右的相对时间；短 SHA 可复制完整哈希；点击提交整行（包括拓扑、作者、时间和留白）展开或收起历史文件，SHA 与 Ref 按钮继续独立操作，文件行继续复用共享树与历史 Diff。图谱车道、提交行高与文件缩进针对窄侧栏收紧，拓扑与文字紧邻；最近提交列表及拓扑不整体水平滚动；分支车道较多时按侧栏宽度收紧图谱，为提交信息保留空间。只有超出可用区域的提交标题与历史文件路径可以独立横向滚动，短文字不会左右回弹。同一提交上的本地分支与已配置远端的同名跟踪分支使用单一分段标签展示，各段仍绑定完整原始 Ref，并且彩色图标与对应节点同色；不同提交或不同分支名称不组合。侧栏空间不足时优先显示本地分支名称，过多 Ref（包括合并标签中被收起的远端段）经按隐藏真实引用数量计数的 `+N` 子菜单访问；远端跟踪分支已有独立右键菜单，包含检出、Fetch、Merge、Pull、删除及归档。提交右键提供创建分支/Tag、检出、拣选、撤销、合并、变基、复位、拓扑允许时的 Drop，以及复制 SHA/标题；历史文件右键可打开历史 Diff、只读查看选定提交的原文、与当前工作区比较、打开当前文件、经确认恢复该版本，或复制相对／绝对路径。已删除的历史文件只保留差异和路径操作；目录仅提供路径复制。本地 Branch Ref 的右键可以重命名、推送、导出归档；非当前 Branch 另支持检出、删除、合并和变基，折叠 `+N` 使用相同菜单。Tag 按真实 Git 对象区分轻量和带注释类型，右键分别提供适用的详情、删除、推送、归档和名称复制。

## 本机执行环境

本机执行器与终端共用登录 shell 选择。首次调用在用户主目录启动交互式登录 shell，而不是在仓库执行启动配置；读取导出环境的超时为 5 秒，成功后缓存。

NUL 分隔和唯一标记隔离启动输出，保留变量中的换行或等号；不输出环境内容。启动失败、超时或没有有效 PATH 就明确失败，重启后再尝试，不用残缺环境执行写操作。

Git 及 hook 工具按该 PATH 解析，命令继续通过独立 argv 传参，保留 `GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0` 和 `LC_ALL=C`。输出并发排空及超时终止使用现有执行机制；远端使用自己的环境，不接收本机变量。

## 写操作与草稿

### 历史提交操作

提交菜单的检出进入游离 HEAD；确认可勾选“总是接受”，后续略过这一步确认，但不会略过 Git 自身的错误。拣选可记录来源或只暂存不提交；拣选和撤销 Merge 提交时选择主线父提交，默认第一父。

变基默认忽略提交者日期，交互式变基不使用此选项，而是在新终端运行真实编辑器。Reset 默认 Mixed，也可选择 Soft 或 Hard；Soft/Mixed 不写工作文件，不要求保存无关的工作区编辑。Hard 先完成保存保护，再按 Git 原生规则覆写。Drop 只允许有父节点、通往当前 HEAD 且没有 Merge/多子分叉的路径；Tag 或同节点 Ref 不额外禁止，detached HEAD 也按相同规则处理。执行前核对真实拓扑，尊重用户 `rebase.updateRefs`，不自动强推。

合并默认即使可快进也创建提交。压缩合并优先于此选项；自动提交的 Squash 必须在开始前确认索引没有原先暂存的内容，否则拒绝操作并保留 HEAD、索引和工作区（可先提交或取消暂存）；选择 No Commit 时仍由用户自行处理暂存。没有选择“不创建提交”且 Squash 新增了暂存差异时，使用 `Merge commit '<完整 SHA>'` 创建单父提交。允许快进时，“不创建提交”并不阻止 HEAD 前移。冲突及 Hook 失败保留真实 index、工作区和错误，仍在现有终端继续、跳过或中止相应 Git 操作。

弹窗绑定发起窗口、项目、机器和仓库，确认及异步预检后重新核对。会改工作区的历史操作先等待项目内同一仓库、机器的文件和 Diff 保存；失败或保存期间再次编辑会停止，标签不关闭。执行前发现新编辑或在途写入也会拒绝；已开始的 Git 进程不声称能锁住外部 CLI。操作结束重读干净标签，包含正在编辑模式的干净 Diff，不覆盖新的未保存文本。

面板在解析新项目目标时停用旧快照的动作。GitStatusModel 记录当前已解析的 PanelContext 身份，并在目标改变时立即使旧请求失效；不在每个弹窗里重复查找另一个 Git 根。切走再切回也不能恢复旧确认。

操作互斥，执行前核对目标、路径、HEAD 和 upstream，错误与输出必须可检查。Git 文件行还绑定创建该行时的仓库、工作区代次、分支与 HEAD；旧菜单不能在切换分支后操作另一分支的同名文件。

Branch 和 Tag 的同名替换确认固定被替换对象；确认期间若引用被其他工具移动，即使列表已经刷新，也会拒绝旧确认。重新打开确认后才能替换新目标。

### 本地分支与归档

在历史提交新建 Branch 时可输入名称并选择是否检出，**默认不检出**；顶部的「新建分支」沿用从当前 HEAD 创建并检出的默认行为。已存在同名 Branch 时会询问替换或重新命名；只有确认替换才强制移动该分支引用，Git 对当前检出分支或其他 worktree 的拒绝不会绕过。检出前先保存属于同一仓库和机器的未保存编辑，保存失败不切分支、不关标签。

当前和其他本地 Branch 的操作绑定所选 Ref 的名称、OID 和原仓库。Rename 不覆盖重名分支；Delete 默认不用 Force，也不删远端。若普通 Delete 因尚未合并被拒绝，会单独询问是否强删；选择「同时删除远端」会列出已知的同名远端跟踪分支，只有本地删除成功才逐个向这些远端请求删除。中间某个远端失败不会阻止处理后续远端，操作日志保留真实的部分成功结果。

切换分支先按 Git 标准分支名校验；外部工具写入的非标准 Ref 不能被解释成命令选项或“上次分支”简写，导致切到另一个目标。

Branch Push 可选一个或多个远端，默认目标依次参考所选 Branch 的 `pushRemote` / `remote`、仓库 `remote.pushDefault`、`origin` 和首个远端。默认设置 upstream；模式为普通、`--force-with-lease` 或明确选择的 `--force`。依次推送，首个失败即停止并记录未执行目标；最后一次成功设置 upstream 的远端为最终追踪目标。非当前分支使用完整 Ref，不推送当前 HEAD 或同名 Tag。仓库没有配置任何 remote 时会显示原因并禁用 Push 确认，而不是点击后无响应。

Branch、Remote Branch 与 Tag 的「创建归档」只生成 ZIP，macOS 原生保存面板只选择文件名和位置，内容来自**确认时所选的 Git 对象**而非当前 HEAD。生成完成后才原子替换文件；失败不能损坏已有归档。本机使用 Git 的登录环境，SSH 在原机器生成临时文件后有界传输（最多 64 MiB），远端断线或清理失败明确报告残留路径。Remote Branch 按当前已知的远端跟踪 Ref 内容导出。

### 历史文件操作

对提交中选定的文件右键，可读取该提交实际保存的原文（只读，不将整篇内容伪装成新增差异），或查看该版本相对当前工作区的 Diff。若历史路径已经被重命名，打开工作区文件及比较会按需核对该提交至当前工作区的重命名；原路径仍存在时不凭猜测打开其它文件。读取 Git blob 失败与文件不存在必须区分；二进制、错误 UTF-8 与超过 5 MiB 不显示伪造文本，但二进制文件仍可通过真实 Git 恢复。

「恢复文件到此版本」明确提示将同时覆盖此路径的 Git index 与工作区，经确认后执行 `git --literal-pathspecs checkout <SHA> -- <path>`。先核对确认打开时的文件状态，再完成未保存编辑的保存保护；自己的保存不算外部改写。首次 Git 覆写前再次核对准备后的文件状态和原 index；外部修改、保存失败或新编辑都会拒绝操作。成功后只重读干净的打开标签，HEAD 与其他历史引用不改变。保留现有文件树的原生命中、图谱线和独立横向滚动。

### 远端分支操作

右键远端 Branch 或在 `+N` 菜单中选择相同操作，均绑定**实际 remote、完整分支路径与选定 Git Ref**；有多层路径或 remote 名称自身包含 `/` 时按配置识别最长匹配 remote。`origin/HEAD` 及其它符号远端引用按 Ref 快照的 `symref` 判定，只作为可查看、可复制名称的引用别名显示，不提供检出、Fetch、Merge、Pull、删除或归档操作；真正名为 `HEAD` 的非符号分支仍正常显示与操作。

Checkout Remote Branch 默认以远端分支名创建本地跟踪分支并切换，创建前保护同一项目尚未保存的编辑。同名本地分支出现时不会自动覆盖，而是选择“重新输入名称”，或明确“切换现有分支并拉取”。两条路径都先校验标准分支名，不把外部特殊名称当作 Git 选项或“上次检出”简写。后一种操作的切换已成功、拉取失败属于**部分成功**：保留当前分支、Git 冲突与错误，不假装撤销。

已有同名**非当前**本地分支时才提供 Fetch into Local Branch，默认不强制。它获取服务器最新分支，但执行前核对表单打开时的本地目标；期间本地分支被移动，即使勾选 Force Fetch 也拒绝旧确认。重新确认后可强制更新，仍不能修改其他 worktree 正在检出的分支。

Merge into Current Branch 使用历史提交相同的原生 Merge 表单；Pull into Current Branch 独立提供 No-FF 和 Squash（默认均关闭），不会混用顶部只允许快进的 Pull 快捷键。Squash 仅在确有暂存差异时创建单父提交。

删除远端 Branch 只作用于该 remote 的完整分支路径，服务端拒绝、认证错误或保护策略不被绕过。若服务器已删除该分支，Git 原生删除流程会清理**同一个**本地 remote-tracking Ref，不影响其它 remote 的同名分支。Archive 使用本次所选跟踪 Ref 的对象，不会先 Fetch 或擅自选取服务器上可能已移动的分支。

### 标签（Tag）

历史提交「添加标签」默认创建**带注释的 Tag**，可填写多行注释，也可选择轻量 Tag；切换类型保留尚未提交的注释输入。已有同名 Tag 时明确选择替换或保留输入重新命名；只有确认替换才强制移动本地 Ref，不自动强推远端。支持创建后选择一个远端推送，默认不推送；取消后续推送保留已成功创建的本地 Tag。

Tag 右键根据 Git 的实际对象类型显示「查看详情」（仅带注释标签，显示创建者/日期、标签及提交对象、注释与签名验证结果）、「删除标签」「推送标签」「创建归档」「复制名称」。删除默认只改本地；选择一个远端时**先请求远端删除，成功才删除本地**，服务器拒绝则保留本地 Tag。推送可以选择一个或多个远端，默认依次采用仓库 `remote.pushDefault`、`origin` 或首个远端，不使用当前 Branch 的设置。按选择顺序执行、首次失败即停止，不使用 `--tags` 或隐式 Force。其他同提交 Tag 不受影响。

推送前通过已存在的本地 remote-tracking 分支判断远端是否已知包含该提交；不因这个启发式自动 Fetch 或断言服务端一定缺失。查询失败会报告错误并停止，不当作允许推送。可能未包含时先询问是否仍要推送，可选择继续或取消；「以后总是继续」默认不勾选。这一选择仅关闭相应警告，不修改服务端权限或 Git 推送错误。创建后立即推送前先读取实际 Tag object OID 并核对它仍指向所选提交，不等待状态缓存碰运气。归档沿用 Branch/Remote 已有的 ZIP 原生保存路径。

暂存修改索引，取消暂存保留工作区。重命名同时处理新旧路径，路径参数使用 literal pathspec。丢弃普通已跟踪文件从索引恢复，不直接等同于 HEAD；未跟踪删除执行安全确认。

`GitStatusModel` 打开丢弃确认时保存原机器、仓库、分支、HEAD 和文件指纹，确认后再检查；读取失败、文件变化或连接切换不得回退本机或执行旧操作。确认呈现属于 Git 界面。

### 未提交改动与文件菜单

MERGE、STAGED、CHANGES 标题右键与顶部更多菜单都提供储藏、复位和清理表单；标题原有悬停按钮不增加。储藏消息可空，默认包含未跟踪文件；复位默认 Mixed（只重置 index），Hard 必须明确选择并遵循历史复位的保存保护。无 HEAD 时不能复位。

Clean 使用 Git 永久删除未跟踪文件，默认包含目录，不删除被忽略文件，也不移到废纸篓。它不替换原逐文件 Discard：后者仍从 index 恢复已跟踪文件，本机未跟踪文件仍移至废纸篓，SSH 删除仍经过审核。Git 文件夹和文件行共用右侧操作按钮：CHANGES 提供丢弃与暂存，STAGED CHANGES 提供取消暂存，MERGE CHANGES 提供标记已解决（暂存）。点击文件夹名称只展开或折叠；按钮与右键菜单作用于当前分组中该文件夹的文件，丢弃仍需确认，重命名仍处理新旧路径；搜索时只操作当前匹配的文件，不扩大到隐藏文件或其它目录。

文件右键可只读打开 HEAD 原文（有对应版本时）。同一路径执行 `git rm --cached` 后，STAGED 的索引删除和 CHANGES 的未跟踪文件必须分别显示，不能因为路径相同丢掉后者。CHANGES 中真正未跟踪的文件，以及包含未跟踪文件的目录，才提供「添加到 .gitignore」；已跟踪文件与已进入索引的 intent-to-add 不受忽略规则影响，不展示无效操作。添加时打开普通文件标签，在当前文本末尾追加精确路径规则后保存，保留已有未保存文本与原生撤销栈；读取或保存失败不宣称已经忽略。含换行等无法安全表达的路径拒绝自动添加。

默认仅提交已暂存内容；全部暂存并提交与 amend 由明确选择触发。顶部拉取仅快进；冲突不能当普通修改丢弃。

### 具体储藏（Stash）

Stash 直接作为带 `stash@{n}` 标签的节点嵌入 Git 图谱，而非单独列于提交区上方。节点沿保存时的**基础提交**画一条关系线，不把内部 index／未跟踪父对象伪装成分支。相同哈希但不同 selector 的多条记录分别显示；基础提交尚未加载时不画虚假连线。展开节点才读取已跟踪和未跟踪文件的变更，并提供对应版本的只读 Diff。`git stash list` 可查看现有储藏，`git stash show` 可查询详情；Drop 或成功 Pop 后从图谱消失，并非永久历史。切换仓库或更换 SSH 通道使旧的明细读取失效，避免一直卡在加载中；读取失败时可折叠重开相应节点重试。Git 状态暂时查询失败则保留最后有效快照。

右键某条储藏可应用、弹出、从它创建分支、删除或复制名称／哈希。应用与弹出默认不恢复暂存状态，勾选 Reinstate Index 才带 `--index`。应用始终使用选中对象的固定 OID，不移除条目；弹出及创建分支只在 Git 成功后移除相应储藏，冲突保留真实工作区、index 与 reflog。创建分支会检出该新分支并恢复变更，不只是创建一个 Ref。

弹出、删除和创建分支必须使用 selector；对话框打开时保留整份储藏列表，执行前在同一互斥操作中重读列表核对 selector、OID 和记录说明，外部新增／删除或同 SHA 条目移位时拒绝并要求重新选择。应用继续使用固定对象 OID。这不是外部 CLI 的跨进程原子锁。顶部「弹出最新储藏…」捕获显示时的首条身份，使用同一表单及校验，不再盲弹当前栈顶。应用、弹出及创建分支走现有保存／重载保护；仅删除 reflog 的操作不保存无关编辑，也不自动清空冲突。

提交草稿按当前窗口、机器和仓库保留，不持久化。失败保留草稿，成功只清除本次没有被继续编辑的说明。
