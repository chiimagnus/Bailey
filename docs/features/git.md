# Git 状态与操作

本页负责仓库状态、刷新、命令环境、提交和草稿。相关行为改变时同步更新；Diff 见 [diff.md](diff.md)，共享树见 [files.md](files.md)。

## Invariants

- **仓库身份包含机器和路径。** 状态、折叠、草稿与操作不能串仓库；工作区、索引和提交历史彼此不同。
- **暂时失败不代表仓库消失。** 同一仓库刷新失败时保留最后成功的分支、状态和历史，同时给出错误与重试；切目标或确认不是仓库时才清除。
- **旧结果不覆盖新操作。** 刷新合并进行中的请求；旧连接、旧范围和操作前的查询不能覆盖当前状态。
- **破坏性操作在确认后重新校验。** 用户确认前后项目、机器、HEAD 或文件变化都不能继续执行旧操作。
- **所有命令参数保留数据边界。** 文件名、提交说明和分支不能直接拼成未经处理的 shell 语法。

## 刷新与显示

应用激活、项目变化、Kero 终端命令完成和手动刷新仍立即请求 Git 状态。外部 CLI 不发这些事件，因此**本机 Git 面板仅在可见且 App 前台时**复用已有的 2 秒可见面板刷新周期：文件修改、暂存、新提交以及普通目录中新初始化的 Git 仓库都会重新识别。Git 正在刷新或执行写操作时跳过周期请求，避免重复查询；后台、隐藏的 Git 面板及 SSH 不做周期 Git 查询。原有请求合并、超时和远端批量查询保持不变，SSH 换用新连接时立即使旧连接结果失效。

尚无提交的仓库仍支持状态、未跟踪文件与首次暂存。首次加载失败或超时必须退出等待并允许重试。未跟踪行数保留文件数和字节预算，界面概览不表示已经统计所有内容。

Recent Commits 按拓扑顺序读取本地分支、远端跟踪分支、Tag 与 HEAD 可达的提交。每条记录保留完整父提交列表和有类型的引用，包含合法带逗号的分支及 Tag 名称；合并提交的文件列表及历史 Diff 都与第一父提交比较，不把其它父提交当作文件基线。

提交图谱按真实父提交绘制蓝色主干、多车道彩色分支与合并线；尚未加载的父提交不绘制虚构连线，当前 HEAD 不在已加载分页中时也不将其它分支误标为蓝色主干；展开文件时已有关系线持续贯穿。每个提交第一行是标题和有类型的 Ref，第二行是短 SHA、作者和靠右的相对时间；短 SHA 可复制完整哈希；点击提交整行（包括拓扑、作者、时间和留白）展开或收起历史文件，SHA 与 Ref 按钮继续独立操作，文件行继续复用共享树与历史 Diff。图谱车道、提交行高与文件缩进针对窄侧栏收紧，拓扑与文字紧邻；最近提交列表及拓扑不整体水平滚动；分支车道较多时按侧栏宽度收紧图谱，为提交信息保留空间。只有超出可用区域的提交标题与历史文件路径可以独立横向滚动，短文字不会左右回弹。过多 Ref 经可操作的 `+N` 子菜单访问；远端跟踪分支已有独立右键菜单，包含检出、Fetch、Merge、Pull、删除及归档。提交右键提供创建分支/Tag、检出、拣选、撤销、合并、变基、复位、拓扑允许时的 Drop，以及复制 SHA/标题；历史文件右键目前可打开 Diff 或复制路径。本地 Branch Ref 的右键可以重命名、推送、导出归档；非当前 Branch 另支持检出、删除、合并和变基，折叠 `+N` 使用相同菜单。Tag 的完整管理仍待实施。

## 本机执行环境

本机执行器与终端共用登录 shell 选择。首次调用在用户主目录启动交互式登录 shell，而不是在仓库执行启动配置；读取导出环境的超时为 5 秒，成功后缓存。

NUL 分隔和唯一标记隔离启动输出，保留变量中的换行或等号；不输出环境内容。启动失败、超时或没有有效 PATH 就明确失败，重启后再尝试，不用残缺环境执行写操作。

Git 及 hook 工具按该 PATH 解析，命令继续通过独立 argv 传参，保留 `GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0` 和 `LC_ALL=C`。输出并发排空及超时终止使用现有执行机制；远端使用自己的环境，不接收本机变量。

## 写操作与草稿

### 历史提交操作

提交菜单的检出进入游离 HEAD；确认可勾选“总是接受”，后续略过这一步确认，但不会略过 Git 自身的错误。拣选可记录来源或只暂存不提交；拣选和撤销 Merge 提交时选择主线父提交，默认第一父。

变基默认忽略提交者日期，交互式变基不使用此选项，而是在新终端运行真实编辑器。Reset 默认 Mixed，也可选择 Soft 或 Hard；Soft/Mixed 不写工作文件，不要求保存无关的工作区编辑。Hard 先完成保存保护，再按 Git 原生规则覆写。Drop 只允许有父节点、通往当前 HEAD 且没有 Merge/多子分叉的路径；Tag 或同节点 Ref 不额外禁止，detached HEAD 也按相同规则处理。执行前核对真实拓扑，尊重用户 `rebase.updateRefs`，不自动强推。

合并默认即使可快进也创建提交。压缩合并优先于此选项；没有选择“不创建提交”且确有暂存差异时，使用 `Merge commit '<完整 SHA>'` 创建单父提交。允许快进时，“不创建提交”并不阻止 HEAD 前移。冲突及 Hook 失败保留真实 index、工作区和错误，仍在现有终端继续、跳过或中止相应 Git 操作。

弹窗绑定发起窗口、项目、机器和仓库，确认及异步预检后重新核对。会改工作区的历史操作先等待项目内同一仓库、机器的文件和 Diff 保存；失败或保存期间再次编辑会停止，标签不关闭。执行前发现新编辑或在途写入也会拒绝；已开始的 Git 进程不声称能锁住外部 CLI。操作结束重读干净标签，包含正在编辑模式的干净 Diff，不覆盖新的未保存文本。

面板在解析新项目目标时停用旧快照的动作。GitStatusModel 记录当前已解析的 PanelContext 身份，并在目标改变时立即使旧请求失效；不在每个弹窗里重复查找另一个 Git 根。切走再切回也不能恢复旧确认。

操作互斥，执行前核对目标、路径、HEAD 和 upstream，错误与输出必须可检查。

### 本地分支与归档

在历史提交新建 Branch 时可输入名称并选择是否检出，**默认不检出**；顶部的「新建分支」沿用从当前 HEAD 创建并检出的默认行为。已存在同名 Branch 时会询问替换或重新命名；只有确认替换才强制移动该分支引用，Git 对当前检出分支或其他 worktree 的拒绝不会绕过。检出前先保存属于同一仓库和机器的未保存编辑，保存失败不切分支、不关标签。

当前和其他本地 Branch 的操作绑定所选 Ref 的名称、OID 和原仓库。Rename 不覆盖重名分支；Delete 默认不用 Force，也不删远端。若普通 Delete 因尚未合并被拒绝，会单独询问是否强删；选择「同时删除远端」会列出已知的同名远端跟踪分支，只有本地删除成功才逐个向这些远端请求删除。中间某个远端失败不会阻止处理后续远端，操作日志保留真实的部分成功结果。

Branch Push 可选一个或多个远端，默认目标依次参考所选 Branch 的 `pushRemote` / `remote`、仓库 `remote.pushDefault`、`origin` 和首个远端。默认设置 upstream；模式为普通、`--force-with-lease` 或明确选择的 `--force`。依次推送，首个失败即停止并记录未执行目标；最后一次成功设置 upstream 的远端为最终追踪目标。非当前分支使用完整 Ref，不推送当前 HEAD 或同名 Tag。仓库没有配置任何 remote 时会显示原因并禁用 Push 确认，而不是点击后无响应。

Branch「创建归档」在 macOS 原生保存面板选择 ZIP/TAR、文件名及位置，内容来自**确认时所选的 Git 对象**而非当前 HEAD。生成完成后才原子替换文件；失败不能损坏已有归档。本机使用 Git 的登录环境，SSH 在原机器生成临时文件后有界传输（最多 64 MiB），远端断线或清理失败明确报告残留路径。Remote Branch 也可按当前已知的远端跟踪 Ref 内容导出；Tag 的归档菜单仍属于后续任务。

### 远端分支操作

右键远端 Branch 或在 `+N` 菜单中选择相同操作，均绑定**实际 remote、完整分支路径与选定 Git Ref**；有多层路径或 remote 名称自身包含 `/` 时按配置识别最长匹配 remote。`origin/HEAD` 一类符号引用不作为独立可操作分支，真正名为 `HEAD` 的非符号分支仍正常显示。

Checkout Remote Branch 默认以远端分支名创建本地跟踪分支并切换，创建前保护同一项目尚未保存的编辑。同名本地分支出现时不会自动覆盖，而是选择“重新输入名称”，或明确“切换现有分支并拉取”。后一种操作的切换已成功、拉取失败属于**部分成功**：保留当前分支、Git 冲突与错误，不假装撤销。

已有同名**非当前**本地分支时才提供 Fetch into Local Branch，默认不强制；必要时可显式选择 Force Fetch，但 Git 仍禁止修改其他 worktree 正在检出的分支。Merge into Current Branch 使用历史提交相同的原生 Merge 表单；Pull into Current Branch 独立提供 No-FF 和 Squash（默认均关闭），不会混用顶部只允许快进的 Pull 快捷键。Squash 仅在确有暂存差异时创建单父提交。

删除远端 Branch 只作用于该 remote 的完整分支路径，服务端拒绝、认证错误或保护策略不被绕过。若服务器已删除该分支，Git 原生删除流程会清理**同一个**本地 remote-tracking Ref，不影响其它 remote 的同名分支。Archive 使用本次所选跟踪 Ref 的对象，不会先 Fetch 或擅自选取服务器上可能已移动的分支。

历史提交创建 Tag 暂时仍是轻量 Tag，不能将其当作 P4-T5 所需的 Annotated/Push/替换行为；该任务完成前不宣称 Tag 管理已齐全。

暂存修改索引，取消暂存保留工作区。重命名同时处理新旧路径，路径参数使用 literal pathspec。丢弃普通已跟踪文件从索引恢复，不直接等同于 HEAD；未跟踪删除执行安全确认。

`GitStatusModel` 打开丢弃确认时保存原机器、仓库、分支、HEAD 和文件指纹，确认后再检查；读取失败、文件变化或连接切换不得回退本机或执行旧操作。确认呈现属于 Git 界面。

默认仅提交已暂存内容；全部暂存并提交与 amend 由明确选择触发。拉取仅快进，储藏全部包含未跟踪内容；冲突不能当普通修改丢弃。

提交草稿按当前窗口、机器和仓库保留，不持久化。失败保留草稿，成功只清除本次没有被继续编辑的说明。

## 验证

`GitExecutionTests`、`GitStatusModelTests`、`GitBranchActionTests` 与 `GitRemoteBranchActionTests` 使用临时仓库核对工作区、index、HEAD、Ref、多个裸仓库推送和选中版本归档；`GitBranchDialogTests` 核对原生弹窗默认值与禁用条件；`RecentCommitsViewTests` 在原生窗口核对窄侧栏、整行点击、Tag 独立操作、短文字无回弹、长标题/路径独立滚动、图谱固定、文件 Diff 命中及只在滚至末端时加载历史；`GitExternalRefreshTests` 在原生 SwiftUI Git 面板中执行外部修改和提交，检查前台响应延迟、后台和隐藏面板停止轮询及手动刷新。覆盖首次提交前、特殊路径、重命名、超时、失败草稿、提交期间编辑、快速切换和临时刷新失败。

执行环境检查从精简 GUI PATH 出发，包含启动噪声、变量、Git 与 hook 解析、失败和超时。推送测试使用临时接收仓库并核对实际提交；涉及 LFS 时还核对接收端对象。真实 SSH 另行验收，不以 fake 后端结果代替。统一方式见 [testing.md](../testing.md)。
