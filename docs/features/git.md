# Git 仓库状态与执行环境

Git Manager 的共享状态、刷新、缓存、操作资格及命令环境由本页维护。
[Changes](git-changes.md)、[Graph](git-graph.md)、[Git 操作](git-operations.md) 和 [Diff](diff.md) 各自维护专属行为。

## Invariants

- **状态属于明确的仓库。** 机器、路径和项目代次共同确定身份；旧请求不能覆盖新状态。
- **按阶段读取并验证。** 核心失败保留只读快照；详情失败不撤销有效核心。
- **读取许可不等于写入许可。** 每次操作重新核验当前身份和实际 Git 状态。
- **参数保留数据边界。** 文件名、提交说明、分支等不直接拼入未经处理的 shell 语法。

## 刷新与显示

**本机 Git 只由事件触发查询，不再定时轮询。** macOS FSEvents 以 `NoDefer` 尽早投递首批事件，
Git 状态从首批事件起用 400 ms 窗口合并并刷新，不因持续事件反复延期；监听仓库、
关联 Worktree 和共享 Git 元数据；连续变化合并后刷新。Git 面板隐藏时仍能更新底部状态栏。
App 退到后台暂停监听，由 Git 状态模型在返回前台时重新校验，不再从窗口重复发起刷新；监听不可用时仍可手动刷新。
Files 复用同一原生监听实现的路径／事件标志能力，但目录列表仍由 FileTreeModel 独立读取，
不把 Git 状态或文件事件当作目录内容。
FSEvents 自身持有回调对象直至 Stream 释放；监听器可在回调期间销毁，
不得从回调队列同步等待自身。停止监听后旧事件不再刷新已切换的项目。

终端命令完成、Git 操作完成、项目切换及手动刷新也会立即触发查询。终端完成事件由所属项目汇总；开关终端不算命令完成，项目切换只提交一次身份变化。
**SSH Git** 尚无持续接收远端文件事件的通道，在 App 前台且 Git 面板可见时仍每 5 秒检查一次。
远端复用批量 Git 查询与既有 OpenSSH 连接。
SSH 上一轮详情查询尚未结束时，可见面板的下一次周期请求在原任务内等待并补读；
隐藏面板或 App 退到后台就取消等待，不在隐藏后产生新的查询。
Git 写操作期间不发周期请求，结束后由操作自身刷新。
刷新与 Git 写操作串行合并；切换仓库／SSH 通道、状态模型销毁或刷新超时会取消
旧 Git／SSH 读取及其超时等待，不让无人消费的命令继续占据进程或连接。
展开历史提交的二进制信息与 Stash 文件明细也由对应请求持有；切换项目／连接时
取消旧读取、清除过期的加载标记，同一仓库重新查询时不被失效任务阻挡；
历史重写或外部删除 Stash 后，也立即取消已不再可见的明细读取。
同一仓库的并发文件事件仍排队合并，不能取消当前状态栏仍需要的刷新；
请求身份校验继续阻止旧结果覆盖当前状态。

**FSEvents 不能保证系统异常时零事件丢失。** 遗漏变化时可重新激活 App 或手动刷新校验。
SSH 的 5 秒仍只是触发间隔，不是界面响应时限；连接建立、网络和批量读取会增加实际延迟。
远端首先批量读取仓库身份、分支和文件变化，核对进行中的 Git 操作后即更新核心状态；
Ref／远端、历史、Stash 与忽略装饰随后批量读取，文件行数单独受限统计。
附加查询失败保留原有 Graph、Stash 与忽略装饰作为只读展示；
已验证的 Ref、历史与 Stash 分别保留操作资格，不互相拖累；核心刷新失败时保留最后快照与错误提示，
暂停 stage、discard、commit、push 等写操作，仍可查看历史和文件。
切换 SSH 通道或从旧缓存恢复仓库时也先以只读方式展示，重新取得核心状态后才开放写操作。
只缓存最近使用的四个非活动仓库，合计最多五万条状态、引用及历史等源记录；超过预算从最久未使用者开始淘汰。
离开仓库时只保留前两页提交头，返回后继续按需分页；提交草稿与目录展开等导航状态不参与淘汰。
活动仓库的记录数和历史页数不设此上限。临时失去路径时保留受限的只读快照，无项目时释放全部快照。
`GitStatusModel.syncSelectedProject` 只接收本次选中项目和来自窗口的当前目标判定；
旧请求提交前须同时通过代次、项目许可和 `PanelContext.Identity` 校验，
两处 Git Retry 也重新从当前窗口读取目标，不能把旧项目的同步结果当成新仓库。
同目标刷新保留项目身份；项目、根目录或连接改变时统一更新代次及文件监听，即使两个项目共用仓库路径。
固定 SSH 主机即使复用同一个后端对象，也以连接代次废止旧查询与操作资格；断线保留最后快照，
重连通知立即核验新连接，不等待旧查询返回。断线本身不启动额外的重试循环。
核心失败与历史/Stash 等详情失败显示不同提示；根目录探测失败时的重试重新解析当前项目，
不对旧根盲目刷新。连接恢复且核心状态确认后恢复操作；SSH 断线不能被误判为切换仓库。

已知的暂存／取消暂存只重读核心与工作区行数（不重新查询 Ref／远端元数据）：
HEAD、分支或进行中操作没有变化时继续使用已验证的历史／Ref／Stash，
身份变化或尚无有效详情时立即补一次完整查询。
历史分页只读取当前范围的状态、Ref、工作树列表与扩大 limit 的提交元数据，不计算文件差异，不重复查询 Stash 或文件行数；
分页查询失败保留已验证的上一页与行数，不自动重查全部详情，只有仓库核心、
Ref／HEAD 或工作树列表发生变化才重新获取完整一致快照。
其他 Git 操作、App 激活、本机文件事件、SSH 定时检查和手动刷新仍做完整查询；
排队中的完整刷新不得被局部操作降级。后台查询期间保留已确认的行数和历史数据；
首次加载完成后，普通查询进度不再使 Git Graph 的菜单区域失效，相同结果不重复发布给 UI。

首次加载失败或超时必须退出等待并允许重试。
本机／SSH 的刷新工作共用整次预算，SSH 存活检查也计入调用预算；独立界面超时仍保留已成功状态。
SSH 核心与详情分批读取，失败或缺帧不逐命令重新取整份快照。

未跟踪统计最多查看 2048 个文件，每文件最多读取 8 MiB、整次最多 32 MiB，实际读取也受剩余预算约束。
前 8000 字节含 NUL 视为二进制，symlink 计一行，末行无换行仍计入。超预算显示省略号而非精确的零；
读取失败保留状态并报告错误。远端统计只返回带预算校验的数值记录，文件名中的换行不能伪造行数。

核心状态刷新以 `GitStatus` OSLog 类别记录请求序号、阶段、耗时及完成状态。
命令超时另以错误级别记录 Git 子命令名和退出码；界面等待超时单独记录 core／details 阶段，
以便区分命令超时与独立等待保护。日志不记录远端主机、私有仓库路径、命令参数或输出。

## 操作资格与目标

尚无提交的仓库仍支持状态、未跟踪文件与首次暂存。
暂存、取消暂存、普通提交和 Amend 只依赖已校验的核心，Amend 依据 HEAD 而非历史是否加载；
分支、引用及远端操作只要求已校验的核心与 Ref；历史提交操作还要求本次有效的历史；
既有 Stash 的 Apply/Pop/Drop 等要求本次有效的 Stash 列表。创建新 Stash、Reset、Clean 只要求核心；
每次真正写入前仍核对目标、HEAD、相关 Ref 或 Stash。新建 Tag 后立即推送仍读取实际对象 OID，
并在写操作前校验，不等待旧快照出现新 Tag。

核心查询失败后，同一有效目标的旧列表仍可展开、选择、导航、打开文件及读取 Diff／历史原文；
实际读取失败由内容标签反馈，不静默丢弃打开动作。
正常后台刷新不禁用目标未变的已验证操作；Ref／远端查询失败撤销引用及依赖引用的历史操作资格，
已核验的 Stash 列表仍可使用，忽略装饰或行数失败不影响 Git 写操作。

面板操作必须同时匹配当前窗口选中的项目和已解析的 PanelContext。
即使 GitStatusModel 仍持有有效的旧仓库快照，旧 Git Changes／Graph 行也不能向新项目打开 Diff，
旧暂存／弃置操作不能继续写入失焦仓库。GitStatusModel 在目标改变时使旧请求失效；
切走再切回不能恢复旧确认。

操作互斥，执行前核对目标、路径、HEAD 和 upstream，错误与输出必须可检查。
Git 文件行还绑定创建该行时的仓库、工作区代次、分支与 HEAD；
旧菜单不能在切换分支后操作另一分支的同名文件。

## 本机执行环境

本机执行器与终端共用登录 shell 选择。首次调用在用户主目录启动交互式登录 shell，
而不是在仓库执行启动配置；读取导出环境的超时为 5 秒，成功后缓存。

NUL 分隔和唯一标记隔离启动输出，保留变量中的换行或等号；不输出环境内容。
启动失败、超时或没有有效 PATH 就明确失败，重启后再尝试，不用残缺环境执行写操作。

Git 及 hook 工具按该 PATH 解析，命令继续通过独立 argv 传参，保留 `GIT_OPTIONAL_LOCKS=0`、
`GIT_TERMINAL_PROMPT=0` 和 `LC_ALL=C`。输出并发排空及超时终止使用现有执行机制；
远端使用自己的环境，不接收本机变量。

## 验证

`GitStatusModelTests` 使用临时仓库核对状态、index、HEAD、Ref、提交及错误恢复；
覆盖独立 Worktree 提交、干净／有改动、共享 HEAD、SHA-1／SHA-256、跨页加载、
监听初始化／释放、后台暂停及查询失败恢复。切换仓库、SSH 通道或退出模型时，
核对过期命令实际取消，不以旧结果覆盖新状态。
`GitExecutionTests` 检查精简 GUI PATH、登录 shell 噪声、Hook、超时与失败。

外部 CLI 修改由文件事件刷新；本机空闲无周期查询，SSH 前台 5 秒兜底。
`GitRemoteRefreshIntegrationTests` 使用受控慢响应及获准 Windows SSH 临时仓库验证轮询、取消后不补查和实际 Git 结果；
`SSHGitRecoveryLiveTests` 模拟测试后端失联，核对快照保留、拒绝写操作与恢复后重新暂存。
App 后台暂停，恢复前台重新读取，Git 面板隐藏而 App 前台时仍更新底栏。
`GitChangesUITests`、`GitGraphGeometryUITests` 核对真实 App 入口与挂载；
真实 SSH 的完整 GUI 隐藏／恢复组合未在该组 E2E 中执行，不以模型测试代替。
