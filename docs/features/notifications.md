# 通知与手机推送

维护终端通知归属、点击定位及 Bark HTTPS 推送。通知路由、凭据或分发改变时更新；Shell 生命周期见 [终端](terminal.md)。

## Invariants

- **通知属于发出它的会话。** 标题、点击及定位按真实项目与会话身份解析。
- **设备凭据只存钥匙串。** 普通偏好、日志和请求 URL 不包含 Key。
- **推送不影响终端和本机通知。** 隔离实例不访问真实设备凭据；单地址失败不阻塞其他地址。

## 通知路由与分发

通知使用对应项目名称并保留程序正文；
标题查询和点击定位都通过 GUI delegate 持有的 `WorkspaceApplication` 查找真正发出通知的会话，
而不是当前随意选中的标签或全局窗口数组。项目名和目标身份不应取自可随命令变化的窗口标题。

Codex CLI 在 `~/.codex/config.toml` 的 `[tui]` 下配置 `notifications = true` 和
`notification_method = "osc9"` 后，可在设置中添加多个 Bark HTTPS 推送地址，
将终端主动发出的桌面通知推送到每台手机。每个地址通过独立的 HTTPS JSON POST 请求发送，
某个设备失败不阻断其他设备。普通响铃、SSH 状态和其他应用通知仍只在 Mac 上显示；
推送与 macOS 通知授权相互独立。本机通知被禁用不影响已配置的 Bark 推送，远程失败也不影响本机提醒。
项目名和通知正文可能含敏感输出；不提供手机回复或公网入口。

## 手机通知设置

「手机通知」支持逐条添加、移除多个 Bark HTTPS 推送地址（或填写官方设备 Key），
并对所有已配置地址发送测试通知。支持官方及自建 HTTPS Bark 服务器。
设备 Key 与地址列表统一存于 macOS 钥匙串，配置文件、日志和实际请求 URL 均不包含 Key；
界面只展示主机名和 Key 后四位。地址列表为空时不推送；普通设置重置不删除钥匙串凭据，需逐条明确移除。
`--isolated-ui-test` 隔离实例不访问手机通知设置，也不转发通知，避免触及用户真实凭据和设备。

## 验证

`BarkPushServiceTests` 检查地址规范化、HTTPS JSON、跨服务器分发及单地址失败；
「发送测试通知」报告 Bark 服务端接受请求的数量，不代表手机已实际显示。
macOS 通知须真实点击并定位到原会话；实际手机接收在获准环境中单独验证。
