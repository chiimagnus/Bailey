# 文件保存与数据保护

⌘S 手动保存，失焦等事件触发自动保存。文件、可写 Git Diff 和图片标注共用版本校验、失败保稿及关闭保护。
本页负责写入、冲突、恢复和与文件／Git 操作的事务边界，不负责文本布局或各格式预览。

## Invariants

- **保存以实际原始字节为基线。** 旧版本、不同机器或路径不得写入；确认覆盖必须绑定当前比较版本。
- **失败保留草稿。** 不清除未保存状态、不盲目重试、不以关闭窗口或结束终端掩盖失败。
- **每个标签一个串行写入者。** 在途快照只确认自己的提交，后续编辑仍未保存。
- **外部操作先保护相关编辑。** 文件移动、删除、Git 改写和关闭必须等待并复核受影响内容；不保存无关仓库。

## 自动保存与队列

自动保存由编辑器失焦、工作标签／项目切换、窗口失焦等事件触发；文件内容不设保存定时器。
⌘S 仍可用，读取当前聚焦内容的保存资格。

切入工具或其它 Dock 组也保存离开的工作内容。
项目切换覆盖离开项目的全部脏缓冲，窗口失去 key 时覆盖该窗口各项目的脏文件和可编辑 Diff，
不再只保存最近标签。文件标签由一个写入者串行处理保存；重复普通保存只保留最新请求，
明确选择的编码转换单独执行。失败保留正文，不发生无限重试。

## 文件操作与版本绑定

文件管理器移动、重命名和删除受影响路径前，必须等待对应文件及可写 Diff 的保存队列；
操作中暂缓旧路径的后续写入，成功后更新标签路径并继续保存。
保存失败（包括正文干净但编码转换失败）或两个窗口存在同一路径的不同脏稿时拒绝文件操作，
不损坏缓冲与 Undo；已删除文件的迟到编辑保留只读，不因重连恢复对旧路径的保存。
每次写入在前一个请求完成后冻结当前正文、路径、后端、编码及目标代次，
编码检查与无损往返在后台完成。最新编辑不会被旧快照覆盖，
旧保存结果也不能把后续编辑误标为已保存。

## 保存冲突与恢复

**文件标签保存会核对最初读取的原始字节版本**（长度及 SHA-256），
而非仅比较文件大小或修改时间。提交前检测到目标改写、删除或重命名时拒绝保存，保留草稿并显示冲突；
冲突后暂停失焦自动保存；普通重试仍以原始基线校验，用户恢复原字节后可重试。
也可选择「与磁盘版本比较…」，原生只读 Diff 显示当前磁盘与草稿、编码和原字节摘要。
取消不写盘；明确选择覆盖才将所比较的磁盘版本作为本次条件写入的预期版本，
不修改原基线、不绕过现有保存队列。确认绑定文档、路径、目标代次、冲突、原基线与草稿的完整字节；
任一确认失效须重新比较。成功才推进基线，保存中的新编辑继续保持未存。
可写 Git Worktree Diff 复用同一比较机制；图片标注比较合法旁车 JSON，并继续验证原图。
无法读取、无损解码或生成有界比较时不提供盲目覆盖（比较的两侧合计最多约 50 万行）。
本机与 SSH 均先在目标目录中完整暂存并核验数据，保留原有执行权限，不沿符号链接覆盖链接目标。
本机已有目标使用原子交换，核验实际被替换的入口；若版本不符、无法核验或取消，
保留该入口于同目录的 `Bailey Save Recovery <UUID>`（移动失败时保留原暂存位置），显示恢复路径，
不确认保存、不清除草稿。此时目标可能已包含本次草稿，不自动回滚以免再次覆盖第三方修改。
失败时保留此前恢复路径，提示可以换行与选中复制。
成功保存后清除错误提示，不会删除恢复文件。不支持交换的文件系统拒绝条件覆盖。
SSH 上传必须同时通过字节长度和 SHA-256 校验，最后校验后原子替换；远端尚无上述交换恢复能力。
远端保存结果不确定时，保留该次提交的冻结快照。只读核对实际字节；
同一机器重连后先确认上次提交，再保存新草稿。已发布才推进基线，
确认仍是旧版才允许下一次条件写入，第三个版本保留冲突，不盲目重试。
在途撤销不能把尚未确定的文本提交误标为干净。
无条件写入仅用于其它明确文件操作；FileTab 和可写 Diff 的保存不得回退到无条件写入。
这不是严格的文件系统 compare-and-swap。交换已经改变目标路径；即使核验旧入口成功，
持有其旧文件描述符的独立进程仍可能在旧入口删除后写入。SSH 最后核验与替换之间也存在非协作竞态。
无跨进程协调协议不能保证任意第三方写入不丢失。

## Git 操作前保护

历史 Git 操作等待相应仓库的保存完成，不使用会关闭标签的保存路径。
文件版本恢复还核对打开确认时该路径的 index 和工作区内容；取消或发现内容已变更时不得覆写。
保存失败或等待期间再次编辑时停止 Git；操作结束只重载干净缓冲。
Git 操作的选项与目标检查由 [Git 操作](git-operations.md#历史提交操作) 维护。

本机保存范围使用系统标准化路径比较，`/private/var` 与 `/var` 的同一文件不会漏过保护；
远端路径不交给 Mac 的文件系统解析。其他仓库的未保存文本不随本次 Git 动作保存。

## 保存与关闭

单标签、批量关闭、项目、窗口及应用退出，都须等待脏草稿和显式编码转换的在途写入。
即使正文干净，未解决的转换失败仍否决关闭；再次关闭提示「保存／不保存／取消」。
只有保存成功或明确选择「不保存」才移除内容。失败、取消或所属窗口不存在时保留编辑，
确认 Sheet 只在所属可见窗口呈现，不借用全局 key window 或模态对话框。

重复关闭请求不能提前删除其它标签；项目关闭须等待仍在进行的标签关闭。
异步保存结束后、销毁项目或允许窗口／App 退出前，再次检查全部编辑器；
若出现新的草稿则终止本次关闭，下一次重新保存。
窗口注销、项目释放与原生关闭通知见 [macOS 窗口](windows.md#系统菜单)，
旧编辑器退役见 [原生编辑器](editor.md#文档退役)。

远端断线、重连与保存结果失效规则见 [ssh.md](ssh.md)。重新启动只重新读取磁盘，不承诺恢复未保存文本，
见 [session-restore.md](session-restore.md)。

## 验证

`FileTabPersistenceTests`、`NativeFileTabTests`、`NativeDiffTabTests` 与 `ImageAnnotationTests`
核对原生编辑、脏状态、实际写盘字节、版本竞争、冲突恢复及条件保存。
`SSHFileTreeLiveTests` 经独立授权 SSH 连接核对同大小、同修改时间改写，
旧磁盘／旧连接确认拒绝及重新确认后的精确保存；图片标注另核对旁车版本和原图保护。
本机同路径文件不受远端写入影响。

`WindowCloseIntegrationTests`、`WindowOwnershipIntegrationTests` 核对关闭否决与跨窗口目标。
覆盖单标签、批量、项目、窗口及 App 退出，包含正文干净但编码转换仍在写盘、
受控远端挂起期间其它文件变脏、关闭请求与异步执行竞争、失败后再次关闭及重试成功。
原生 Sheet 的「保存」「不保存」「取消」须分别验证失败转换不丢稿、明确丢弃及取消关闭。
转换失败后 Files 移动／重命名／删除及同仓库 Git 操作须拒绝，成功保存后恢复。

跨窗口使用不同路径的同名文件验证目标，核对未保存正文、实际磁盘、脏状态和编辑器归属。
完整 App 的 ⌘S 还须核对前台焦点、最终字节及重启结果；宿主集成与后台事件派发不能代替。
测试入口见 [testing.md](../testing.md)，授权 SSH 与写入失败夹具见 [testing-environment.md](../testing-environment.md)。
