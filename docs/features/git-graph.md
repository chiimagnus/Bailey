# Git Graph

维护提交图谱、历史分页、工作树与引用展示、导航和选择。
仓库状态见 [Git](git.md)，命令执行见 [Git 操作](git-operations.md)。

## Invariants

- **历史来自真实提交关系。** 不凭日期、分支名或图谱几何推断父子关系。
- **展示快照和导航目标一致。** 只发布当前仓库的完整投影，保留仍有效的行身份。
- **浏览、选择、展开和命令分开。** 浏览不修改 Git；批量操作必须使用真实目标。

## Git 图谱与工作树

Git Changes 与 Git Graph 共享一条垂直滚动区域。
新增提交、历史分页、Ref 或 Stash 变化时，滚动内容高度、轨道连线和点击区域必须同步更新，
不能依赖切换 Project 或重建整棵 Graph 恢复显示；已有提交的展开状态和原生键盘焦点应保留。
Git Graph 的布局仅随有序节点、节点类型或父关系变化重算；
检出分支、引用标签、聚焦、选区、字号、主题和侧栏尺寸不改变这些输入时复用原有轨道与色位。
HEAD 的可证实祖先归属独立更新。
历史组合和已知远端可达关系复用各自输入对应的派生结果；切换仓库、机器或历史／引用后
不得继续复用旧结果。
Graph 的提交、目录、文件和分组标题共享同一行投影；行投影和轨道布局在可取消的后台任务中准备，
结果匹配当前仓库、历史和展开请求后一次发布。同一仓库在工作树状态变化、历史增删或重写、分页及展开期间，
保留上一份完整的行、提交与轨道快照，键盘导航也使用实际展示的快照；不会短暂清空图谱或显示整图加载指示。
不同仓库／机器的快照不得交叉使用。连续同高行分组保留仍有共同内容的原生视图身份，
插入或删除组首行不会重新挂载整个分组。提交头只含元数据；首次展开才查询该提交相对第一父提交的文件变化（根提交相对空树）。
折叠提交或离开 Graph 时取消其详情查询，释放文件数据、二进制标记及对应树索引；
展开状态保留，返回时按需恢复。连续同高行分段懒加载，
由行数和字号确定精确滚动高度，不依赖离屏行的尺寸估算，也不重建滚动宿主。
方向键导航在移动方向上保留一条完整的相邻行；空间不足或已到首尾时只保证焦点行可见。
焦点与所需相邻行已完整可见时不滚动；否则按实际行坐标最小距离滚动。
历史分页由末端进入视口触发，不因创建离屏容器而提前加载。

Git Graph 的键盘行游标独立于 Git Changes；行身份包含机器范围、仓库、
提交及文件分组／路径。单击可移动游标并展开提交或浏览文件 Diff，
游标与展开状态不是一回事。Files、Changes 和 Graph 的修饰键点击仅使用本窗口的左键事件，不继承无关键盘或其它窗口的事件标记。已展开的提交在暂时切换到 Files、再返回 Git 时保留；
更换项目、仓库或机器时清理旧展开；这些变化及 SSH 连接重建都会撤销临时右键目标。
即使两个项目指向同一目录，也不能复用前一项目的 Graph 局部状态。
密集轨道在极窄侧栏下压缩间距；引用、Stash 和 Worktree 徽章可只显示图标，
仍保留完整名称的悬停提示与辅助功能信息，不让标签尺寸撑大图谱宽度。
↑／↓ 在可见提交、目录和文件之间移动，←／→ 折叠／展开层级，Space／Return 执行当前行的既有点击动作。
⌘↓ 导航至普通提交的首父，⌘⇧↓ 至第二父；⌘↑ 导航至已加载 DAG 的子提交，
⌘⇧↑ 至替代子分支。目标不存在时不跳转；Stash 和 Worktree 节点不参与父子导航。
键盘导航会展开目标提交，不修改 HEAD、index、工作区，也不在双击或导航中隐藏执行 Checkout／Reset。
单击提交、目录或文件明确选中一行：图谱取得键盘焦点时显示主题色底，
失焦时选中底色变灰；键盘游标、纯方向键与 ⌘方向键仅绘制独立细描边，不改变原选中。
Space／Return 执行当前行动作时才更新明确 Selection。
右键菜单另有临时上下文描边，期间覆盖目标行的填充，关闭后恢复原选区。
历史提交、Stash 及 Uncommitted Changes 展开本身不留下灰底，只有悬停暂时变灰；
正在显示的历史／其它工作树 Diff 文件仍有独立灰底，不随方向键游标移动；
单击短 SHA 复制完整哈希；普通提交右键只提供复制标题，引用菜单保留各自的复制动作。
Graph 右键只更新临时上下文目标，不移动键盘游标、不改选，也不触发 Diff 浏览或展开；
关闭菜单立即撤销临时描边。
历史文件、工作树文件、分支标签的菜单继续作用于各自真实身份。
Git Graph 的压缩目录仅用于展开／折叠，不再提供文件路径右键菜单；
Changes 的目录操作见 [Git Changes](git-changes.md)。
图谱的历史文件及其它工作树文件单击／键盘浏览 Diff 时保持 Git 活动组（只要 Git 仍可见），
显式打开内容标签才切入目标。提交说明与过滤输入框仍使用原生文本焦点，输入按键不触发列表动作。

## 托管平台与 Git Remotes

提交行及 Branch／Tag 引用右键仅对**本地已知远端跟踪分支包含的提交**
提供「在托管平台打开」。只有本地提交、尚未 Push 的新提交，
或缺少远端跟踪证据时，不显示提交链接；多 Remote 仅列出包含该提交的远端。
Merge 的两个父分支及历史祖先均按实际提交关系判断，
不会把本地分支、Tag 或 Remote 配置本身当作已上传证据。
这一判断基于当前 Git 引用快照，无额外网络请求；
它是最近 Fetch／Push 后的本地认知，不保证服务器在此后没有发生强制推送或删除。
需要确认最新状态时先 Fetch。

GitHub、GitLab、Bitbucket、Gitee、GitCode、Codeup、Azure DevOps、Gitea／Forgejo、Codeberg、SourceHut
等常见远端按各自 URL 规则打开。不能生成可信提交详情 URL 的服务，
不在提交右键提供错误的仓库主页回退；仓库主页始终由独立的 Git Manager 菜单打开。
从配置的 Git Remote 地址生成链接，移除认证信息和参数，不调用托管平台 API。
SSH Remote 的网页地址一般使用 HTTPS；自部署实例的特殊域名可在 Git Manager 设置中映射平台类型。

「⋯ → Open Remote in Browser」提供仓库主页入口；
仓库的多个 Git Remotes 由 Git 原生配置管理，不在 Git Panel 增加管理 Sheet。
设置仅保留自托管域名映射，见[设置与配置](settings.md#git-设置与托管平台)。

## 历史顺序与轨道

图谱按 `git --date-order` 读取本地分支、远端跟踪分支、Tag，
以及当前目录和所有有效工作树检出位置可达的提交。工作树即使没有关联分支，或没有未提交改动，
其独立提交也正常显示；共享提交只显示一次。
子提交始终在父提交之前，与 VS Code Git Graph 的默认时间顺序一致。
每条提交保留完整父关系和有类型的引用（包括名称中带逗号的分支与 Tag）；
Merge 的文件列表和历史 Diff 仍以第一父提交为基准。

首次加载和分页共用排序、去重后的工作树完整提交 ID，不额外优先传入当前符号 HEAD；
同秒独立 Worktree 提交不因当前查看的目录改变遍历顺序。不按工作树分别拼接历史，
也不把全部 Reflog 或 Stash 内部提交当作普通历史。
当前工作树尚无首次提交时，其他工作树的历史仍正常读取。工作树列表读取失败时保留旧历史并报告错误；
分页发现工作树新增、移除或检出位置变化时，重新读取完整快照，使提交、检出标记和文件状态保持一致。

连线只来自已加载的真实父关系。按历史顺序分配第一父路径、空闲轨道和色位，
不强制当前 HEAD 占左侧。相同有序提交及父关系不因切换分支而改形或改色；
不为未加载的父提交补假线。颜色属于图谱路径，不按分支名称固定；
12 个路径色位由当前 Ghostty 主题生成，普通与亮色槽重复时派生不同颜色，确保线条可见、标签图标可辨。
切换明暗主题只改变配色，不重新分配车道或改变拓扑；合并后保留路径颜色；
连线避开其它提交节点，空闲车道可复用颜色，超过 12 条活跃路径允许重复色位。
相同历史输入的色位分配保持稳定。Stash 只连接可见的基础提交，不把内部父对象当成分支。
仅在已加载祖先关系可证实时才显示 HEAD 归属提示。
标签颜色、折叠、点击与布局由[图谱视觉](#图谱视觉) 维护。

当前工作树的文件状态来自已验证的 `status --porcelain=v2 -z`；
其他工作树来自 `git worktree list --porcelain -z`，并按各自机器和路径读取暂存、未暂存、
冲突与未跟踪文件。只有存在改动才增加菱形状态节点：对应 HEAD 已加载时沿其车道竖直连接，否则独立显示，
不伪造 Git 提交、SHA 或新分支。同一 HEAD 可对应多个独立工作树状态；干净工作树不产生修改节点。

未提交节点按冲突、暂存与未暂存分组，文件列表支持 Tree/List，打开 Diff 时必须指向所属工作树，
不得串写本机和 SSH 文件。暂存重命名／复制后的未暂存 Diff 以目标路径的 index 为基线；
冲突状态显示 `U`。节点不提供普通提交或 Stash 的破坏性操作。
外部读取失败保留上次可见状态并提示不完整，不得把缺失结果当作工作树已干净；历史分页仍只加载真实提交。

干净工作树也在真实 HEAD 提交上保留具名标签：有关联的真实 Branch 时，
在分支标签内显示 Worktree 图标和必要的数量；没有关联分支时，显示唯一目录名和「未关联分支」，
不伪造 Git 分支或当前 HEAD 引用。主标签和 `+N` 统一选择，避免远端别名与空 Worktree 图标并排；
完整规则见[图谱视觉](#图谱视觉)。
相同 HEAD 的工作树共享提交及标签，在右键菜单中按唯一目录名区分；
完整路径在悬停提示中可查看，工作树菜单仅保留打开、访达定位和移除。
具体创建、打开和删除规则见[本地分支与归档](git-operations.md#本地分支与归档)。

## 选择与多选

多选不依赖历史拓扑：
单击选择一项并按原行为展开提交或浏览文件，⌘ 单击增减选项、Shift 单击按图谱显示顺序扩选，
修饰键点击不触发展开或浏览。⌘A 选择当前已加载的全部真实提交，
Shift＋↑／↓ 扩选可见键盘行，普通方向键只移动 Focus，Escape 清空选区。
Shift 可横跨分支和 Merge；展开的文件及临时 Stash／Worktree 节点不混入真实提交范围。
选区内右键提供作用于整组选区的菜单项，选区外右键只作用于当前目标。
切换仓库、范围或 HEAD 清除选区；历史分页、展开或折叠时保留仍存在的选择。

多选真实提交时，右键可复制完整哈希、标题或「哈希＋标题」摘要，
也可用 ⌘C 复制哈希（以换行分隔），并提供 Cherry-pick、Revert、Drop 和 Squash。
Git Graph 不提供路径复制右键菜单；多选文件／目录或混合提交、Stash、文件时，
也不生成可能误导为文件操作的批量菜单。⌘C 仍可复制当前图谱选区的文本。
右键命中已选提交的标题、轨道节点、分支／Tag／Stash／Worktree 徽标时，
都使用同一多选菜单；未选中的徽标仍保留原有的单个引用或 Worktree 菜单。
未选中行右键不能意外借用之前的选区。
创建 Branch／Tag、Checkout、Merge、Rebase、Reset 需要唯一目标，不出现在多选菜单。

## Stash 节点

Stash 直接作为带 `stash@{n}` 标签的节点嵌入 Git 图谱，而非单独列于提交区上方。
节点沿保存时的**基础提交**画一条关系线，不把内部 index／未跟踪父对象伪装成分支。
相同哈希但不同 selector 的多条记录分别显示；基础提交尚未加载时不画虚假连线。
展开节点才读取已跟踪和未跟踪文件的变更，并提供对应版本的只读 Diff。
`git stash list` 可查看现有储藏，`git stash show` 可查询详情；
Drop 或成功 Pop 后从图谱消失，并非永久历史。切换仓库或更换 SSH 通道使旧的明细读取失效，
避免一直卡在加载中；读取失败时可折叠重开相应节点重试。Git 状态暂时查询失败则保留最后有效快照。

## 图谱视觉

Git 图谱保留 12 个稳定的路径色位，颜色从当前明暗 Ghostty 主题的 ANSI 色槽派生；
重复或低对比色会调整为仍可辨认的主题派生色，不回退旧版固定调色板。
节点、轨道和对应 Branch／Tag／Stash 标签图标底色同色，图标笔画按亮度选择对比色，
当前分支边框也随轨道着色；提交、作者、SHA、日期及标签文字使用主题前景色和深浅层级，
未连接工作树节点保持中性。当前 HEAD 为空心圆，Stash 为双环，其余提交为实心圆；
检出标记不改变既有图谱轨道与色位，展开文件后连线仍贯通。

每条提交只显示一个主标签，其余 Branch、远端分支和 Tag 收进 `+N`，原有右键操作不丢失。
有匹配的真实分支时，主标签显示分支名，并在内部合并 Worktree 图标及必要的数量；
没有关联分支的 Worktree 显示「目录名 · 未关联分支」，不再与引用标签并排显示一个没有文字的小图标。
目录名在当前图谱已知工作树中保持唯一，完整路径可悬停查看。
当前检出位置优先，其次是已检出的本地分支、其他本地分支、远端分支、Tag 和远端别名；
`origin/HEAD` 不抢占真实分支的主标签。没有匹配分支的 Worktree 自身作为主标签，
其真实引用仍保留在 `+N`。

引用菜单保持稳定的视图身份。常规宽度下，主标签显示中间截断的名称；
密集轨道、最大字号与极窄侧栏同时出现时，主标签可仅保留可点击的同色图标，
完整名称仍通过悬停提示与辅助功能提供，存在其它引用时仍可使用 `+N` 菜单。
图谱按真实视口宽度布局，标签不得把提交标题推出侧栏边界，轨道不随标题横滚。
标签高度 16 pt、文字 9 pt，随面板字号缩放；长名称中间截断，把空间留给提交标题。
Stash 在正常宽度显示完整的 `stash@{n}` 序号；极窄时通过悬停与辅助功能提供完整名称。

未提交修改以菱形节点单独显示：第一行是修改状态，第二行是工作树目录，不重复绘制分支标签。
同一 HEAD 的多个工作树仍各有自己的状态节点；HEAD 不在已加载历史中时只显示灰色孤立节点，
不虚构提交或关系线。

键盘、选区与右键行为见本页导航规则；图谱只负责对应状态的绘制。
提交行依次展示图谱、必要标签与标题，下一行显示 SHA、作者和时间；
Merge 标题通常保持较弱对比度，悬停时恢复正常对比度；展开本身不改变标题样式。
窄侧栏压缩轨道间距（最多约占宽度三分之一），整个图谱不水平滚动；
长标题和文件路径独立滚动，短文字不回弹。悬停图谱节点仍能查看完整 SHA、标题和已确认的引用。
工作树删除保护与失败恢复见[Git 操作](git-operations.md)。

## 验证

`GitGraphSelectionTests` 核对独立多选、⌘ 切换、Shift 范围、离散选区、全选及刷新清理；
`GitStatusModelTests` 核对真实分支切换、分页、同秒 detached Worktree 历史顺序及无变化刷新不使观察依赖失效。
`CommitGraphLayoutTests` 验证拓扑、色位、检出标记变化时的几何复用和字号／宽度／车道数极值；
`GitGraphPaletteTests`、`GitGraphReferenceGroupTests`、`GitGraphWorktreePresentationTests`
分别验证颜色、引用分组和 Worktree 路径与状态。
`GitPanelVisibilityTests` 核对真实 Dock、离屏刷新、连续 Commit／Amend、48 组布局极值、
1,026 项 Changes × 20 分支交叉压力，以及原生 AX／AppKit 鼠标命中。拓扑测试同时核对
长历史冷计算、重复输入复用及 HEAD／Ref 变化后的缓存失效。
容量与长会话按 [testing-performance.md](../testing-performance.md) 的多仓库场景执行。

`GitGraphUITests`、`GitGraphGeometryUITests` 核对真实 App 的行命中、Dock 拖动、横滚、
深浅像素、键盘、多选、历史文件、分页、多级菜单及剪贴板。Tag／Stash 徽标右键需核对所属提交或混合选区。

多 Ref、多 Worktree 下实际展开 `+N → Branch → Worktree → 目录 → 操作`；
菜单打开期间触发无变化刷新、外部文件修改、分支／Worktree 变更及侧栏宽度调整，
核对纯查询或布局变化不关闭菜单，真实目标变化后仍重新校验。
覆盖超过 10 秒的悬停、首次加载、深浅色和窄宽侧栏，核对短 Branch 不被拉宽、
可用空间允许时引用名实际可见、`+N` 与提交标题仍可见。
不能用静态菜单结构、OCR、辅助功能名称或图标代替真实绘制、点击和悬停结果。
历史与工作树的数据读取、去重和恢复见 [Git 状态](git.md#验证)。
