# UI 与交互规范

本页描述 **Bailey 当前界面** 的主题、共享组件和行为，不是未来设计稿。修改 View、主题、窗口外壳、交互或本地化前阅读；相关变化同步更新本页和对应功能文档。

## 产品与视觉方向

Bailey 是自由组装的 AI IDE，以原生终端工作区支持开发者使用 CLI 和代码智能体。文件、Git 与浏览器辅助终端工作，不争夺注意力，不做网页仪表盘式装饰，不逐像素模仿其他编辑器。

保留上下文、明确操作目标、常用操作就近；破坏性操作不能出其不意。项目与各面板可自由停靠，默认三列只是初始布局，不存在特殊左右侧栏。

## Invariants

- **共享界面保持共享。** Files、Git 工作区、暂存和历史使用同一树语义、行样式及命中规则，不能只修一个区域。
- **主题来自现有所有者。** 新增颜色、字体或间距先复用对应共享值，不复制另一套 Theme 或设计系统。
- **精简不能丢失图谱语义。** 减少重复标签时，必须保留轨道对应颜色、所有真实引用的菜单入口和未提交状态的独立性；用明暗主题的原生窗口验证。
- **纯重构不改变外观与行为。** 布局、颜色、字号、图标、动效、文案、点击、拖动、键盘、焦点、滚动和无障碍都要保持。
- **原生内容不因重绘重建。** Shell、WebView、TextKit 编辑器及其缓冲、撤销和滚动由长生命周期内容持有。
- **后台检查不等于界面变化。** Git 图谱、底部状态栏和远程连接标题只在显示值改变时更新，不重复写入相同状态，也不临时清空已确认的信息。
- **用户设置优先。** 尊重终端／编辑器字体及面板字号，不能用固定文字大小替代可调整字号。

外观支持系统、浅色、深色。终端和周边 UI 从选择的 Ghostty 主题解析，Bailey 内置 Default 主题保留既有材质效果，其他主题按对应颜色呈现；动态主题改变应更新现有原生表面，而不是重新创建内容。

共享值由表中各自所有者维护；文档不复制数值表，也不为“统一”新建并行设计系统。

## 共享树行

整行高亮区域可点击，包括缩进、上下边缘和留白；右侧动作独立。Git 文件夹与文件使用同一套右侧悬停按钮，操作不会触发展开；Files 与历史树无按钮时保留原有点击区域。目录压缩指向真实末级目录，仅超长文字独立水平滚动且短文字不回弹，按钮和整行布局保持固定，列表保持懒加载。

状态融入文件名颜色，不使用最右侧字母状态列；颜色不是唯一信息，提示和辅助功能仍应表达完整状态。修改行距、缩进、命中或悬停时，验证所有 Files／Git 使用方，不复制私有变体。

## 标签、焦点与输入

标签的名称、图标、未保存状态及关闭按钮使用共享外壳，工具面板的「＋」行为一致。外层停靠布局与内部内容布局分开，不能用额外分屏修复某个标签的样式。

焦点既影响视觉也影响动作目标。菜单、⌘S、查找、关闭和通知必须作用于真实聚焦窗口／内容；视图切换不能结束后台命令。焦点和生命周期由 [dock.md](features/dock.md) 维护，不在 View 中复制平行状态。

Finder 文件投放按目标区处理：Projects 的文件打开／复用当前项目标签，文件夹添加目录项目；Files 按明确目录复制；顶部工作标签栏和编辑区打开／复用标签。分屏标签栏中新文件归实际命中组、已有文件不迁组；系统菜单的 ⌘O 与标签栏「＋ → 打开文件…」共用原生多选文件对话框，添加本机目录则用 ⇧⌘A。Ghostty 终端只插转义路径，WebKit 网页正文保留上传。文件管理器复制没有自动移动、覆盖或远端上传；失败显示所属窗口原生 Sheet，不能在焦点变化后投递错误机器。

普通点击用 `Button`；仅需坐标或点击次数时使用手势。图标按钮有明确辅助功能名称，核心操作可用键盘。原生编辑器、菜单和输入法各自的事件顺序不能被“加一次异步派发”掩盖。

## 对话框、设置与原生桥接

设置窗口使用系统 SwiftUI `Settings` 场景与 `NavigationSplitView`。左侧原生分类列表、右侧原生分组表单；较长内容滚动，暂无搜索或历史按钮。普通偏好、Git 文件布局和光标控件使用 SwiftUI；旧有端口转发面板与终端加粗预览暂按原后端保留，后续独立演进。

SwiftUI 是主要界面，AppKit、TextKit、Ghostty 与 WebKit 分别承担已有能力。确认、错误和文件选择沿用所属窗口的原生呈现路径，不另建一套弹窗或反馈实现。

展示层负责呈现，ViewModel 负责结果及动作编排，底层 IO 留在后端。保存失败必须保留内容和可操作反馈，不能只写日志。

Git 历史操作使用发起窗口的原生 sheet；另一窗口成为 key 不改变归属，切项目或关闭原窗口使确认失效。多个选项使用原生复选框和父提交选择器；本地 Branch 的创建/重名、重命名、删除及 Push 共用原生表单；远端 Branch 的 Checkout、Fetch、Pull 通过同一窗口的原生表单呈现，重名时保留用户输入并明确二次选择；Tag 的创建、重名、删除和推送使用原生表单/确认；详情在可选择文字的原生视图中展示，推送风险警告与偏好由同一发起窗口处理。归档仅支持 ZIP，系统保存面板不再提供格式选择。各选项默认值和 Git 结果见 [git.md](features/git.md#历史提交操作) 与 [本地分支与归档](features/git.md#本地分支与归档)。

Git 分组标题的储藏、复位、清理仅出现在原有右键菜单，不增加悬停按钮；Files 等其它标题不变。未提交改动表单明确显示仓库、选项与永久删除警告，所有入口绑定发起窗口。

## Git 图谱

Git 图谱使用独立于 App 强调色的 12 色路径调色板。节点、轨道和对应 Branch／Tag／Stash 标签的图标底色同色；图标笔画按亮度使用黑色或白色，当前分支的边框也随轨道着色，文字和其余背景保持中性。当前 HEAD 可见时，第一父路径优先位于左侧；HEAD 为空心圆，Stash 为双环，其余提交为实心圆，展开文件后连线仍贯通。

每条提交优先显示一个引用标签，其余 Branch、远端分支和 Tag 收进 `+N`，原有右键操作不丢失。引用菜单保持稳定的视图身份，不能因布局宽度切换而销毁已经展开的子菜单。已检出的 Worktree 通过匹配标签内的小图标和必要的数量显示；没有匹配引用时才有独立的紧凑入口。标签高度 16 pt、文字 9 pt，随面板字号缩放；长名称中间截断，把空间留给提交标题。Stash 始终保留完整的 `stash@{n}` 序号。

未提交修改以菱形节点单独显示：第一行是修改状态，第二行是工作树目录，不重复绘制分支标签。同一 HEAD 的多个工作树仍各有自己的状态节点；HEAD 不在已加载历史中时只显示灰色孤立节点，不虚构提交或关系线。

单击提交、标签或 Stash 节点展开／收起对应详情；复制名称、工作树路径及 Git 操作通过右键菜单完成，短 SHA 仍可单击复制。提交行依次展示图谱、必要标签与标题，下一行显示 SHA、作者和时间；Merge 仅弱化未选中时的标题。窄侧栏压缩轨道间距（最多约占宽度三分之一），整个图谱不水平滚动；长标题和文件路径独立滚动，短文字不回弹。悬停图谱节点仍能查看完整 SHA、标题和已确认的引用。历史关系、工作树删除保护与失败恢复见 [Git 功能文档](features/git.md)。

## 本地化

应用维护英语 `en` 与简体中文 `zh-Hans`，开发语言为英语；自有文档为中文。字符串表位于 `Bailey/Resources/Localization/`。

`Git`、`Sidebar`、`Terminal`、`Workspace`、`Browser`、`Editor`、`Settings` 对应功能；`Interface` 负责菜单、命令面板、标签和窗口，`InfoPlist` 负责权限说明，`ServicesMenu` 负责 Finder 服务。调用必须指定正确表，移动文案同步修改 `table`。

面板统一称项目、文件管理器、Git 管理器、浏览器、终端与编辑器；文件搜索结果仍叫文件，不把内容名称和面板名称混同。

使用完整句子、复数形式和正确占位符，不拼接翻译片段；保留快捷键与产品名称。文件名、用户内容和终端输出使用原文语义，例如 `Text(verbatim:)`。新增文案先按构建提取，再补翻译；资源类型按需要使用 `LocalizedStringResource`。

“系统默认”跟随 macOS 及单独 App 的语言偏好，不支持的语言回退英语；应用内切换需重启，恢复边界见 [settings.md](features/settings.md)。

## 修改与验收

从真实原生界面建立基线，不根据猜测修改几何值。视觉修改用同尺寸、内容和动作的前后并排录屏，检查两种外观和亮背景；静态截图辅助检查，不能替代原生交互。

只改外观时不增加未请求行为；纯架构重构不替换样式 API。字体缩放、长文案、中文／emoji、键盘焦点、悬停和现有基础无障碍语义属于受影响区域的回归。不主动新增 VoiceOver 专项功能，也不将语音走查列为一般 UI 改动的强制验收；专项需求另行确认，测试边界见 [testing.md](testing.md#人工回归)。
