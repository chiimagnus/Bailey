# UI 与交互规范

本页描述 **Bailey 当前界面** 的主题、共享组件和行为，不是未来设计稿。
修改 View、主题、窗口外壳、交互或本地化前阅读；相关变化同步更新本页和对应功能文档。

## 产品与视觉方向

Bailey 是自由组装的 AI IDE，以原生终端工作区支持开发者使用 CLI 和代码智能体。
文件、Git 与浏览器辅助终端工作，不争夺注意力，不做网页仪表盘式装饰，不逐像素模仿其他编辑器。

保留上下文、明确操作目标、常用操作就近；破坏性操作不能出其不意。
项目与各面板可自由停靠，默认三列只是初始布局，不存在特殊左右侧栏。

## Invariants

- **共享界面保持共享。** Files、Git 工作区、暂存和历史使用同一树语义、行样式及命中规则，
  不能只修一个区域。
- **主题来自现有所有者。** 新增颜色、字体或间距先复用对应共享值，不复制另一套 Theme 或设计系统。
- **精简不能丢失图谱语义。** 减少重复标签时，必须保留轨道对应颜色、
  所有真实引用的菜单入口和未提交状态的独立性；用明暗主题的原生窗口验证。
- **纯重构不改变外观与行为。** 布局、颜色、字号、图标、动效、文案、点击、拖动、键盘、焦点、
  滚动和无障碍都要保持。
- **原生内容不因重绘重建。** Shell、WebView、TextKit 编辑器及其缓冲、
  撤销和滚动由长生命周期内容持有。
- **后台检查不等于界面变化。** Git 图谱、底部状态栏和远程连接标题只在显示值改变时更新，
  不重复写入相同状态，也不临时清空已确认的信息。
- **用户设置优先。** 尊重终端／编辑器字体及面板字号，不能用固定文字大小替代可调整字号。

## 共享树行

整行高亮区域可点击，包括缩进、上下边缘和留白；
可选择的文件／文件夹采用普通交互行而非整个行充当 `Button`，仍沿用现有懒加载树布局。
右侧独立操作按钮仍然是按钮，不能与行的单击／双击同时执行；行焦点、已打开文件和悬停不是一个状态。
Git 文件夹与文件使用同一套右侧悬停按钮，操作不会触发展开；Files 与历史树无按钮时保留原有点击区域。
Git Graph 历史文件行与 Git Changes 同名文件行使用不同的无障碍标识，
不能按同一路径误触另一个区域的危险菜单。紧凑目录行的每段名称各自命中真实路径，
当前段单独高亮并供右键／拖放操作，整行展开仍控制末级目录；仅超长文字独立水平滚动且短文字不回弹，
按钮和整行布局保持固定，列表保持懒加载。

共享树行以 VS Code `listWidget.ts` 的 Focus／Selection 分离为基线：
**展开／折叠**仅控制可见性，**Selection** 决定 AX 选中及背景；
列表接收键盘时采用主题强调色底，失去输入焦点后保留中性色的选中底色。
**Focus** 是独立的键盘游标，只绘制细边框，不自动更改 Selection；
Focus 与 Selection 在同一行时两层同时生效。**Hover** 只强调未选中且未聚焦行。
文件／资源树的无障碍 Selected 只反映明确 Selection，不从游标描边或当前展示内容推导；
没有资源选择集合的历史树不因方向键导航而宣称文件已选中。
Files 的当前展示文件不再独立绘制弱灰底：活动文件变化按 Auto Reveal 更新树的
Focus／Selection，使旧文件不残留第二条灰底；不匹配的文件不伪选。
Git Changes 同样由活动文件／Diff 标签自动定位匹配资源并更新 Selection，
支持 ⌘ 切换、Shift 范围、⌘A、Escape 的真实资源多选；
选中底色只反映当前合法资源集合，键盘焦点和右键目标仍是独立描边。
不再把已展示 Diff 绘制为独立的第二条灰底；Git Graph 历史文件仍保留其独立
Displayed 语义，提交展开本身不产生持续灰底。
**右键菜单目标**优先于其它视觉状态：菜单期间该行仅绘制主题色细边框，
不叠加选中底色或 Hover 灰底，也不表示列表已取得第一响应者。
实际 Selection 仍保留；菜单关闭后撤销临时边框，恢复原本应显示的选中底色与真实键盘描边。
右键切换到其它行时必须替换旧目标。
Files 右键只建立临时 Context Target，不改变当前 Focus 或 Selection：
目标在已选集合内则菜单操作整组，在集合外则只操作本次右键目标。
菜单期间目标仅显示细边框；Escape 取消后旧选区与游标保持不变。
菜单结束不抢 Terminal／Editor 的原生输入焦点。
菜单期间 ⌘N／⌥⌘N 以右键文件夹为目标，转交系统 File 菜单前保留该目标，
命令接收后清除；取消菜单后仍按普通选区／焦点确定新建目录。
↑／↓ 只移动 Focus，不改变 Selection 与当前展示文件；
Space 明确浏览文件时同步选择游标文件，不夺走 Files 键盘焦点；
Esc 在普通文件树中清除 Selection、保留 Focus。普通键盘 Focus 可以叠加 Selection；
右键目标独占描边，并在菜单期间暂时压过该行的其它背景。
右键不触发左键的打开或展开；菜单对既有选中集合内部操作整组，
对集合外目标只操作该目标。菜单项的快捷键提示必须与真实可执行命令一致，
不能仅凭右键命中的路径假装普通输入焦点已经切换。
Files、Git Changes、Git Graph 分别维护自己的键盘游标；
Git 树保留原有焦点呈现，共享树行不复制 Files 的多选模型，
不保留 SwiftUI `@FocusState` 备用路径；失焦列表只可显示有效的右键上下文边框，
不制造假的键盘焦点环；SwiftUI 系统自动焦点环不叠加；
右侧按钮、输入框、Diff 展示与图谱展开互不抢焦点。状态融入文件名颜色：
新增／未跟踪、删除、修改、重命名／复制与冲突分别沿用当前 Ghostty 主题的 ANSI 绿、红、黄、蓝、
紫色槽；颜色不是唯一信息，提示和辅助功能仍应表达完整状态，不使用最右侧字母状态列。
修改行距、缩进、命中或悬停时，验证所有 Files／Git 使用方，不复制私有变体。

## 标签、焦点与输入

标签的名称、图标、未保存状态及关闭按钮使用共享外壳，工具面板的「＋」行为一致。
Dock 标签使用专属样式：展示项与额外多选项采用不同底色，失活组使用中性色；
键盘游标与菜单目标使用细描边，菜单目标不叠加选中和悬停背景。
无障碍选中反映组选区，不从鼠标悬停或键盘游标推断。
窄 Dock 组优先保留实际可点击的标签区域，左上角拖动留白随组宽收缩。
外层停靠布局与内部内容布局分开，不能用额外分屏修复某个标签的样式。

**展开、选中、悬停、展示、激活、焦点各自独立。** 仅浏览文件或 Diff 不等于激活别的组；
显式打开可以依既有动作同时改变展示、活动组和焦点。
菜单、⌘S、查找、关闭与通知使用当前窗口的有效命令目标，真正的键盘输入以原生第一响应者为准；
二者不总是同一个控件（例如查找框）。视图切换不能结束后台命令。
交互和生命周期由 [dock.md](features/dock.md) 维护，
策略与原生组件的职责见 [焦点协调边界](architecture.md#焦点协调边界)，不在 View 中复制平行状态。

Bailey 的活动 Dock 组不绘制强调色外框，也不整体降低非活动分屏的透明度。
每组仍保留自己的 selected 标签背景：前台活动组使用主题色，
后台组保留中性底色；前台 selected 标签的文字和图标对比度更强。
命令面板或 Sheet 接管输入时不制造假聚焦。
Projects 当前项目同样使用活动／非活动的选中底色，独立键盘游标仅有描边。
Hover 与拖放预览不等于原生第一响应者；文件／Git 树行规则一致。
Projects 和 Dock 标签的右键目标仅显示临时细边框，不能同时叠加蓝色底色，
不切换非活动内容；菜单取消后立即撤销描边及临时关闭目标。
Dock 标签的右键目标仅在菜单期间优先作为 ⌘W 的关闭目标。
命令面板当前结果使用选中底色，⌃Tab 的预览候选使用键盘游标描边；
右键不触发行打开、重排或拖动。

Finder 文件投放按目标区处理：Projects 的文件打开／复用当前项目标签，文件夹添加目录项目；
Files 按明确目录复制；顶部工作标签栏和编辑区打开／复用标签。
分屏标签栏中新文件归实际命中组、已有文件不迁组；
系统菜单的 ⌘O 与标签栏「＋ → 打开文件…」共用原生多选文件对话框，添加本机目录则用 ⇧⌘A。
Ghostty 终端只插转义路径，WebKit 网页正文保留上传。
Finder 投放 Files 始终是复制，不会自动移动、覆盖或上传 SSH；Files 同树拖放默认移动、按 Option 复制。
原生拖放光标与最终操作使用同一次 Copy/Move 协商；有效目标目录以主题色填充和描边标示，
紧凑目录只标示真实命中的目录段，离开或取消即清除；不增加额外的文字徽标。
采用私有拖动身份并复用文件操作，跨窗口及其它机器拒绝，不回退为 Finder 复制。
Files 明确选择剪切、移动或删除则走其自身文件操作。
**应用级快捷键只在 macOS 系统主菜单（SwiftUI `.commands` 或既有 AppKit 菜单项）注册。**
右键菜单、工具栏和命令面板只显示对应提示，不重复绑定 `.keyboardShortcut`
或 `NSMenuItem.keyEquivalent`，也不在普通树键盘事件中重复解释应用快捷键。
SwiftUI 原生右键菜单跟踪时，Files 的 ⌘C 等操作只作用于本次合法目标；
Dock 的 ⌘W 优先使用已启用的原生菜单动作。若 AppKit 先结束跟踪再交给系统主菜单，
仅保留本次关闭目标到命令消费后清除，不新增第二套快捷键或重复执行。
Files 右键上下文只认领当前有效文件行所属的原生菜单，避免其它窗口或菜单的跟踪事件误清选择。
动作执行、菜单取消或窗口失效后必须撤销临时监听，普通 Edit 恢复第一响应者路由。
菜单提示按本次可操作目标显示，不能以 Terminal 仍聚焦为由隐藏本次可执行的 ⌘C。
Edit 的复制／剪切／粘贴／删除／全选通过 macOS 第一响应者路由。
文本输入、列表方向键、Esc／Return、终端 Shell 按键以及系统对话框固有按键
属于控件自身输入，不需要强制转为应用级菜单快捷键。
Files 使用同一套文件操作；菜单没有展开时，只有 Files 树真正持有键盘焦点
才由系统 Edit 修改文件选择，原生编辑器、终端及输入框不被劫持；
菜单展开时命令优先作用于本次右键目标，菜单关闭后不残留该优先级；
跨项目或远端连接变化拒绝剪贴板粘贴，远端永久删除由所属窗口 Sheet 确认。
失败在所属窗口反馈，不转向其它机器。

普通点击用 `Button`；仅需坐标或点击次数时使用手势。图标按钮有明确辅助功能名称，核心操作可用键盘。
原生编辑器、菜单和输入法各自的事件顺序不能被“加一次异步派发”掩盖。

## 对话框、设置与原生桥接

设置窗口采用 SwiftUI `Settings` 场景和 `NavigationSplitView`：左侧分类，右侧原生 `Form`，
内容过长时滚动。具体设置见 [settings.md](features/settings.md)。

侧栏选中行使用 Ghostty 主题强调色，标题为白色、图标使用 `Color.primary`；
未选中图标及两栏背景也随主题变化。普通文字、下拉菜单和按钮保持正文色，强调色只用于选中行、
滑块与开关，不向整个窗口应用 `.tint`。SwiftUI 直接使用解析后的主题颜色，切换主题时不得保留旧色；
内置 Default 主题保留原生材质。System／Light／Dark 在 macOS 27 起使用 `.tabs`，
旧系统使用 `.segmented`。

偏好和 Git 布局使用 SwiftUI；端口转发面板与终端加粗预览沿用现有后端，不另建控件体系。

SwiftUI 是主要界面，AppKit、TextKit、Ghostty 与 WebKit 分别承担已有能力。
确认、错误和文件选择沿用所属窗口的原生呈现路径，不另建一套弹窗或反馈实现。

展示层负责呈现，ViewModel 负责结果及动作编排，底层 IO 留在后端。
保存失败必须保留内容和可操作反馈，不能只写日志。

Git 历史操作使用发起窗口的原生 sheet；另一窗口成为 key 不改变归属，切项目或关闭原窗口使确认失效。
多个选项使用原生复选框和父提交选择器；本地 Branch 的创建/重名、重命名、删除及 Push 共用原生表单；
远端 Branch 的 Checkout、Fetch、Pull 通过同一窗口的原生表单呈现，重名时保留用户输入并明确二次选择；
Tag 的创建、重名、删除和推送使用原生表单/确认；
详情在可选择文字的原生视图中展示，推送风险警告与偏好由同一发起窗口处理。
归档仅支持 ZIP，系统保存面板不再提供格式选择。
各选项默认值和 Git 结果见 [git.md](features/git.md#历史提交操作) 与
[本地分支与归档](features/git.md#本地分支与归档)。

Git 分组标题的储藏、复位、清理仅出现在原有右键菜单，不增加悬停按钮；Files 等其它标题不变。
未提交改动表单明确显示仓库、选项与永久删除警告，所有入口绑定发起窗口。

## Git 图谱

Git 图谱保留 12 个稳定的路径色位，颜色从当前明暗 Ghostty 主题的 ANSI 色槽派生；
重复或低对比色会调整为仍可辨认的主题派生色，不回退旧版固定调色板。
节点、轨道和对应 Branch／Tag／Stash 标签图标底色同色，图标笔画按亮度选择对比色，
当前分支边框也随轨道着色；提交、作者、SHA、日期及标签文字使用主题前景色和深浅层级，
未连接工作树节点保持中性。当前 HEAD 可见时，第一父路径优先位于左侧；
HEAD 为空心圆，Stash 为双环，其余提交为实心圆，展开文件后连线仍贯通。

每条提交只显示一个主标签，其余 Branch、远端分支和 Tag 收进 `+N`，原有右键操作不丢失。
有匹配的真实分支时，主标签显示分支名，并在内部合并 Worktree 图标及必要的数量；
没有关联分支的 Worktree 显示「目录名 · 未关联分支」，不再与引用标签并排显示一个没有文字的小图标。
目录名在当前图谱已知工作树中保持唯一，完整路径可悬停查看。
当前检出位置优先，其次是已检出的本地分支、其他本地分支、远端分支、Tag 和远端别名；
`origin/HEAD` 不抢占真实分支的主标签。没有匹配分支的 Worktree 自身作为主标签，
其真实引用仍保留在 `+N`。

引用菜单保持稳定的视图身份。常规宽度下，主标签显示中间截断的名称；
密集轨道、最大字号与极窄侧栏同时出现时，主标签可仅保留可点击的同色图标，
完整名称仍通过悬停提示与辅助功能提供，存在其它引用时仍可使用 `+N` 菜单。
图谱按真实视口宽度布局，标签不得把提交标题推出侧栏边界，轨道不随标题横滚。
标签高度 16 pt、文字 9 pt，随面板字号缩放；长名称中间截断，把空间留给提交标题。
Stash 在正常宽度显示完整的 `stash@{n}` 序号；极窄时通过悬停与辅助功能提供完整名称。

未提交修改以菱形节点单独显示：第一行是修改状态，第二行是工作树目录，不重复绘制分支标签。
同一 HEAD 的多个工作树仍各有自己的状态节点；HEAD 不在已加载历史中时只显示灰色孤立节点，
不虚构提交或关系线。

Git Graph 的键盘焦点与详情展开是不同状态：点击提交仍展开／收起，
Space／Return 在当前图谱行执行同一操作，方向键可选中可见历史文件或其它工作树文件；
展开历史提交、Stash 或 Uncommitted Changes 只改变子内容，不改变提交行背景；
实际键盘焦点所在行显示主题描边，右键菜单使用独立的临时描边，
输入框获得焦点即撤销键盘描边。右键与历史 Diff 浏览都不强抢图谱焦点。
复制名称、工作树路径及 Git 操作通过右键菜单完成，短 SHA 仍可单击复制。
提交行依次展示图谱、必要标签与标题，下一行显示 SHA、作者和时间；
Merge 标题通常保持较弱对比度，悬停时恢复正常对比度；展开本身不改变标题样式。
窄侧栏压缩轨道间距（最多约占宽度三分之一），整个图谱不水平滚动；
长标题和文件路径独立滚动，短文字不回弹。悬停图谱节点仍能查看完整 SHA、标题和已确认的引用。
历史关系、工作树删除保护与失败恢复见 [Git 功能文档](features/git.md)。

## 本地化

应用维护英语 `en` 与简体中文 `zh-Hans`，开发语言为英语；
维护者文档以中文为主，用户 README 提供中英文。字符串表位于 `Bailey/Resources/Localization/`。

`Git`、`Sidebar`、`Terminal`、`Workspace`、`Browser`、`Editor`、`Settings` 对应功能；
`Interface` 负责菜单、命令面板、标签和窗口，`InfoPlist` 负责权限说明，
`ServicesMenu` 负责 Finder 服务。调用必须指定正确表，移动文案同步修改 `table`。

面板统一称项目、文件管理器、Git 管理器、浏览器、终端与编辑器；
文件搜索结果仍叫文件，不把内容名称和面板名称混同。

使用完整句子、复数形式和正确占位符，不拼接翻译片段；保留快捷键与产品名称。
文件名、用户内容和终端输出使用原文语义，例如 `Text(verbatim:)`。新增文案先按构建提取，再补翻译；
资源类型按需要使用 `LocalizedStringResource`。

“系统默认”跟随 macOS 及单独 App 的语言偏好，不支持的语言回退英语；
应用内切换需重启，恢复边界见 [settings.md](features/settings.md)。

## 修改与验收

从真实原生界面建立基线，不根据猜测修改几何值。视觉修改用同尺寸、内容和动作的前后并排录屏，
检查两种外观和亮背景；静态截图辅助检查，不能替代原生交互。

只改外观时不增加未请求行为；纯架构重构不替换样式 API。
字体缩放、长文案、中文／emoji、键盘焦点、悬停和现有基础无障碍语义属于受影响区域的回归。
不主动新增 VoiceOver 专项功能，也不将语音走查列为一般 UI 改动的强制验收；
专项需求另行确认，测试边界见 [testing.md](testing.md#人工回归)。
