# 开发规范

本页负责命名、Swift、并发、注释和工程取舍。开发约定或平台基线变化时同步更新；架构见 [architecture.md](architecture.md)，实际完成标准只由 [testing.md](testing.md#完成标准) 维护。

## 平台与现代化

Bailey 支持 Apple Silicon、macOS 15.6 及以后版本，自有 App 和 XCTest 使用 Swift 6。语言模式、默认隔离和 SDK 以 Xcode 工程及 CI 配置为准，不为使用新写法擅自提高最低系统版本。

优先当前可用的 Swift 和 Apple API。迁移时直接采用等价实现、删除被替代调用，不保留仅包装旧写法的兼容层；遇到废弃 API 核对替代语义，不把未解决的编译诊断当作正常状态。必要的平台桥接和依赖能力缺口按真实证据处理。

**短小的 UI 与状态操作保持同步。** 只有真实异步操作或阻塞工作才引入并发；共享状态本身不构成增加 `Task`、actor 或异步接口的理由。保持同步回调的返回语义和事件顺序。

## 职责与命名

业务领域内保持纯数据、可观察状态、原生呈现和底层效果的边界。复用现有状态所有者，从 App／窗口装配点传入依赖；简单无业务状态的 View 不必强造 ViewModel。

类型名称应说明真实职责，语义优先于后缀整齐：

| 名称 | 应表达的职责 |
| --- | --- |
| Model / State / ViewModel | 分别表达领域数据、状态或展示编排；不凭名字推断纯度 |
| Store / Repository | 持久化与存取语义，包括冲突或修订边界 |
| Backend / Service | 被调用的 IO 或平台能力 |
| Manager / Coordinator | 实际的生命周期管理或动作编排 |
| Controller / Surface | 原生窗口、控件或表面的管理 |
| Session / Tab | 一次会话或长生命周期内容 |
| Engine / Policy | 计算或决策；应明确输入与输出 |
| View / Row / Panel | 对应可识别的界面部分 |

新增文件以主要类型或职责命名；紧密相关的私有辅助类型可放同一文件。不为套表重命名 `Project`、`TerminalManager`，不复制几个文件外已有的实现。

## Swift 与错误处理

- 优先早返回、明确的值和单一职责；无需变化时用 `let`，避免难懂缩写与隐式全局状态。
- 使用 Swift 原生字符串方法、Foundation URL 与数字格式化。普通用户文本匹配可用 `localizedStandardContains()`；它不替代路径精确比较或已有模糊搜索。
- 错误由所属状态保留，再由 View／原生呈现层展示。用户数据路径不能用静默 `try?`、`try!` 或强制解包掩盖失败。
- 日志使用带明确 `subsystem`／`category` 的 `os.Logger`；凭据、路径、终端输出和用户内容按隐私边界处理，不把日志当用户反馈。
- 自有逻辑应能从用户入口追到真实副作用。复用 helper、失败恢复或重试路径时，也要证明它最终完成了目标。

## 并发与生命周期

可观察展示状态由 `MainActor` 管理，跨隔离边界的数据满足 `Sendable`。文件、Git、SSH、解析等耗时任务走异步后端并明确离开主 actor；`Task {}`、`async` 或函数名字本身都不能证明后台执行。

长任务有唯一拥有者和明确结束路径。取消必须传到调用者拥有的生产任务，不能把一个等待者取消扩展成取消共享资源。每次暂停后，在实际回写或执行动作前重新确认目标和操作身份。

不要用无依据的 `nonisolated(unsafe)`、`@unchecked Sendable`、`MainActor.assumeIsolated` 或延迟派发消除编译错误、遮掩竞态。确需 AppKit 事件或第三方桥接时保留相应机制，并解释安全依据；不把 Swift Concurrency 当成删除所有原生回调的理由。

闭包只在实际存在循环引用或超出预期生命周期时使用弱引用；有意的有界工作可以强持有。continuation 在成功、失败、取消之间只完成一次，不能遗留等待者或重复恢复。

## SwiftUI

`@Observable`、`@State`、`@Bindable` 的职责以及必要 Combine/KVO 桥接由 [architecture.md](architecture.md#observation-与事件) 定义，不建立第二套观察机制。

- 普通点击使用 `Button`；只有确需坐标或点击次数时使用手势。图标按钮提供文字语义和辅助功能名称。
- 复杂且独立的界面块提取为 `View` 类型，不堆返回 `some View` 的计算属性和无必要的 `AnyView`。
- `ForEach` 使用稳定身份。可用原生布局解决时不增加几何读取；停靠拖动与精确命中保留确需的几何信息。
- 在语义、视觉和部署目标均允许时使用 `foregroundStyle()`、`clipShape(.rect(cornerRadius:))`、`.scrollIndicators(.hidden)`、`Task.sleep(for:)` 等当前写法。
- 纯架构重构不顺手替换样式 API。自定义 Dock 不是系统导航，不为套 `TabView`／`NavigationStack` 示例改写工作区。
- SwiftUI 图片渲染优先 `ImageRenderer`；AppKit／WebKit 表面使用自己的原生接口。字体、焦点与无障碍规则见 [ui.md](ui.md)。

## 性能与内存

先测量，再优化和缓存。保护启动、输入、首屏和切换路径；避免逐键、逐行重复读取与分配。已有增量解析、懒加载、刷新合并和 SSH 批量执行不得在重构中丢失。

资源关闭后应释放其独占状态，不泄漏原生视图、进程或无限增长的缓存；恢复需要保留的数据由其明确所有者持有。记录启动、使用峰值与关闭后稳定状态，测量方法见 [testing.md](testing.md#性能与内存测量)。

容量限制由相应功能契约规定；测量数据记录环境，不把一次观测写成已满足的永久指标。

## 简单与可维护

只实现已确认需求，优先标准库、原生能力和已有依赖。协议、工厂、容器、配置和缓存都需要当前用途，不为未来预建。

修复应落在失效不变量的所有者或最小公共位置，不能只修某个调用点。替代实现落地的同一任务中清理旧状态、旧路径和重复文档；无关清理另行提交，不掩盖功能差异。安全、数据保护、无障碍和用户明确要求不因精简而省略。

## 注释

新增注释优先一行，只解释原因、边界或不易发现的约束，不复述代码、不讲改动过程。单行按包含缩进的 100 字符控制；说明需要连续多行时，优先命名函数／类型，或移到所属文档。第三方版权、许可证及协议必须的原文不适用此压缩规则。

不要为遵守新规范批量重写无关旧注释。仅有非显然且真实的简化上限时使用中文 `ponytail:` 注释，写清上限与升级条件。

## 文档和实际检查

本页约定指导新改动，不表示所有历史代码已经逐条通过静态规则。当前没有独立的 SwiftLint、格式化或纯层扫描 gate；以真实 Swift 6 构建、XCTest、变更审查和必要实测验证。机械入口、完成标准和未测范围统一见 [testing.md](testing.md)。

文档按 [docs 索引](README.md#文档维护) 保持单一归属，行为变化的同一任务更新事实、原因、导航和验证边界。维护者文档以中文为主，用户 README 提供中英文；第三方原文及许可证保留；提交规范见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
