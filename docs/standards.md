# 开发规范

本页负责命名、Swift、并发、注释和工程取舍。开发约定或平台基线变化时同步更新；
架构见 [architecture.md](architecture.md)，实际完成标准只由 [testing.md](testing.md#完成标准) 维护。

## 平台与现代化

Bailey 支持 Apple Silicon、macOS 15.6 及以后版本，自有 App 和 XCTest 使用 Swift 6。
语言模式、默认隔离和 SDK 以 Xcode 工程及 CI 配置为准；当前 App Target 使用
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`。不为使用新写法擅自提高最低系统版本。

当前只开发和验收 macOS；
其它 Apple 平台暂缓，具体范围见 [architecture.md](architecture.md#平台范围)。
AppKit 原生能力可以直接使用，不为假定的移植需求预建适配层。

优先当前可用的 Swift 和 Apple API。迁移时直接采用等价实现、删除被替代调用，
不保留仅包装旧写法的兼容层；遇到废弃 API 核对替代语义，不把未解决的编译诊断当作正常状态。
必要的平台桥接和依赖能力缺口按真实证据处理。

**短小的 UI 与状态操作保持同步。** 只有真实异步操作、耗时计算或阻塞工作才引入并发；
共享状态本身不构成增加 `Task`、actor 或异步接口的理由。保持同步回调的返回语义和事件顺序。
技术选型按实际能力和证据决定：优先 Swift Concurrency、标准库与现有 Apple 原生框架，
再复用已安装依赖；新增第三方框架、单独 actor 或执行引擎须证明现有能力无法满足。
不以 API 新、抽象多或线程多推断性能更好。

## 职责与命名

业务领域内保持纯数据、可观察状态、原生呈现和底层效果的边界。
复用现有状态所有者，从 App／窗口装配点传入依赖；业务层只接收完成操作需要的身份、事实、动作或回调，
不为读一个项目状态依赖整个窗口对象。简单 View 不强造 ViewModel，单一实现不强造协议。
状态与依赖规则以 [architecture.md](architecture.md#模块化与依赖) 为准。

类型名称应说明真实职责，语义优先于后缀整齐：

| 名称 | 应表达的职责 |
| --- | --- |
| Model / State / ViewModel | 分别表达领域数据、状态或展示编排；不凭名字推断纯度 |
| Store / Repository | 持久化与存取语义，包括冲突或修订边界 |
| Backend / Service | 被调用的 IO 或平台能力 |
| Manager / Coordinator | 实际的生命周期管理或动作编排 |
| Controller / Surface | 原生窗口、控件或表面的管理 |
| Session / Tab | 一次会话或长生命周期内容 |
| Engine / Policy | 计算或决策；应明确输入与输出 |
| View / Row / Panel | 对应可识别的界面部分 |

新增文件以主要类型或职责命名；紧密相关的私有辅助类型可放同一文件。
名称误导职责时，随真实所有权迁移修正类型、文件、调用方和现行文档；不保留旧名 alias 或转发壳。
**不以增加 Manager、Coordinator、Protocol、Store 或目录数作为模块化成果**；
一个新抽象必须有需要独立管理的状态／生命周期或真实多实现边界，且应替代现有重复代码与反向依赖。
不复制已有实现或再建可写镜像状态。

## Swift 与错误处理

- 优先早返回、明确的值和单一职责；无需变化时用 `let`，避免难懂缩写与隐式全局状态。
- 使用 Swift 原生字符串方法、Foundation URL 与数字格式化。
  普通用户文本匹配可用 `localizedStandardContains()`；它不替代路径精确比较或已有模糊搜索。
- 错误由所属状态保留，再由 View／原生呈现层展示。
  用户数据路径不能用静默 `try?`、`try!` 或强制解包掩盖失败。
- 日志使用带明确 `subsystem`／`category` 的 `os.Logger`；
  凭据、路径、终端输出和用户内容按隐私边界处理，不把日志当用户反馈。
- 自有逻辑应能从用户入口追到真实副作用。
  复用 helper、失败恢复或重试路径时，也要证明它最终完成了目标。

## 并发与生命周期

**分清异步等待与后台执行。** 展示状态、AppKit 与 SwiftUI 交互由 `MainActor` 管理，
小而有界的状态转换保持同步；文件读写、Git／SSH 命令、解析与大量计算不占用主 actor。
`Task {}` 会继承创建处的 actor 隔离；`async` 和 `await` 只表达可能暂停，
不保证同步计算或阻塞 API 已转到后台。实际执行位置取决于函数隔离、语言模式和调用链，
须按当前编译设置与运行测量核对，不能靠包一层 `Task` 修卡顿。

**选择能表达真实生命周期的最小并发机制。** 优先用现有异步 API 与 `async/await`；
有明确父子关系的并行工作用 `async let`／任务组，并限制实际并发数量。
后台 CPU 工作在明确非主 actor 的执行边界运行；必须调用同步阻塞 API 时，
复用已有后台队列／进程泵。`Task.detached` 只在确需脱离继承隔离时使用，
显式承担优先级、取消、结果和引用寿命，不能当作所有耗时函数的默认包装。
不用每行、每页或每次状态变化创建无主 `Task`，不为没有共享可变状态的计算新建 actor。

**数据与结果按身份交接。** 跨隔离边界传递满足 `Sendable` 的必要值或不可变快照，
不让后台工作直接读写原生控件或可观察展示状态。
每次 `await` 后若目标可能改变，回写和产生副作用前重新核对窗口／项目、
机器、连接、路径及请求代次；actor 隔离不自动避免暂停期间的状态过期。
不要用无依据的 `nonisolated(unsafe)`、`@unchecked Sendable`、
`MainActor.assumeIsolated` 或延迟派发消除编译错误、遮掩竞态。

**取消与流量控制属于生产过程。** 长任务由实际业务对象拥有，在切换目标或退役时
取消本次生产任务并收敛其 IO／计算／资源释放，而不只是忽略迟到回调；
不能因一个等待者取消就终止仍被其它使用者需要的任务或共享 SSH master。
输入输出量与生产速度可能失衡时使用有界缓冲、背压和批处理；
允许合并／丢弃的仅是可再生的界面事件，原始文件字节和保存结果不能静默丢弃。
合并重复刷新与派生计算，但不通过任意 `sleep`、无限预取或无界并行掩盖性能问题。

确需 AppKit 事件或第三方桥接时保留其机制并说明安全依据；
不把 Swift Concurrency 当成删除所有原生回调的理由。
闭包只在实际存在循环引用或超出预期生命周期时使用弱引用；有意的有界工作可以强持有。
continuation 在成功、失败、取消之间只完成一次，不能遗留等待者或重复恢复。

## SwiftUI

`@Observable`、`@State`、
`@Bindable` 的职责以及必要 Combine/KVO 桥接由 [architecture.md](architecture.md#observation-与事件)
定义，不建立第二套观察机制。

- 普通点击使用 `Button`；只有确需坐标或点击次数时使用手势。图标按钮提供文字语义和辅助功能名称。
  对浏览、打开、激活、聚焦传递明确意图；不能把 `selected`／hover 的变化当作另一个隐式操作。
- 复杂且独立的界面块提取为 `View` 类型，不堆返回 `some View` 的计算属性和无必要的 `AnyView`。
- `HStack`／`VStack` 默认不指定间距或对齐；确需特殊布局时再传参数。
  避免重复 `frame`、`padding`、`contentShape`、按钮／菜单样式和只转发参数的 View。
  精简前后使用隔离 App，在相同窗口、数据和焦点状态下对照截图、无障碍尺寸与实际点击区域；
  任何视觉或交互变化都恢复原写法。
- `ForEach` 使用稳定身份。可用原生布局解决时不增加几何读取；停靠拖动与精确命中保留确需的几何信息。
- 在语义、视觉和部署目标均允许时使用 `foregroundStyle()`、`clipShape(.rect(cornerRadius:))`、
  `.scrollIndicators(.hidden)`、`Task.sleep(for:)` 等当前写法。
- 纯架构重构不顺手替换样式 API。
  自定义 Dock 不是系统导航，不为套 `TabView`／`NavigationStack` 示例改写工作区。
- SwiftUI 图片渲染优先 `ImageRenderer`；AppKit／WebKit 表面使用自己的原生接口。
  字体、焦点与无障碍规则见 [ui.md](ui.md)。

## 性能与内存

先测量，再优化和缓存。保护启动、输入、首屏和切换路径；避免逐键、逐行重复读取与分配。
已有增量解析、懒加载、刷新合并和 SSH 批量执行不得在重构中丢失。

资源关闭后应释放其独占状态，不泄漏原生视图、进程或无限增长的缓存；
恢复需要保留的数据由其明确所有者持有。记录启动、使用峰值与关闭后稳定状态，
测量方法见 [testing.md](testing.md#性能与内存测量)。

容量限制由相应功能契约规定；测量数据记录环境，不把一次观测写成已满足的永久指标。

## 简单与可维护

只实现已确认需求，优先标准库、原生能力和已有依赖。协议、工厂、容器、配置和缓存都需要当前用途，
不为未来预建。

修复应落在失效不变量的所有者或最小公共位置，不能只修某个调用点。
跨组件问题按能独立验收的真实调用链拆分，每段同时清理自己替换的旧状态、旧路径和重复文档；
不用“大一统协调器”或层层转发掩盖原有混乱。
安全、数据保护、原生输入、无障碍及用户明确要求不因精简而省略。

## 注释

新增注释优先一行，只解释原因、边界或不易发现的约束，不复述代码、不讲改动过程。
单行按包含缩进的 100 字符控制；说明需要连续多行时，优先命名函数／类型，或移到所属文档。
第三方版权、许可证及协议必须的原文不适用此压缩规则。

不要为遵守新规范批量重写无关旧注释。仅有非显然且真实的简化上限时使用中文 `ponytail:` 注释，
写清上限与升级条件。

## 文档和实际检查

本页约定指导新改动，不表示所有历史代码已经逐条通过静态规则。
当前没有独立的 SwiftLint、格式化或纯层扫描 gate；
以真实 Swift 6 构建、XCTest、变更审查和必要实测验证。
机械入口、完成标准和未测范围统一见 [testing.md](testing.md)。

文档按 [docs 索引](README.md#文档维护) 保持单一归属，行为变化的同一任务更新事实、原因、
导航和验证边界。维护者文档以中文为主，用户 README 提供中英文；第三方原文及许可证保留；
提交规范见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
