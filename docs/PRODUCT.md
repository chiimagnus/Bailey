# 产品原则

本文指导产品与设计取舍。调整定位、项目范围或关键交互时同步更新；用户可见变化另行更新 [README](../README.md)。

## 为谁解决什么问题

Kero 面向以 macOS 终端为主要工作环境的开发者，尤其是同时使用多个代码智能体的人。
目标是让用户在终端旁审查修改、处理 Git 和查看文件，不必切换到完整 IDE，也不必信任不透明的自动操作。

## 项目范围

项目列表统一承载本地和 SSH 文件、目录，默认位于左侧，但可以拖动停靠。文件与 Git 跟随选中的项目，不因面板位置或终端在目录内切换位置而改变范围。
添加目录不启动终端；关闭所有终端也不删除项目或其检查工具。

## 设计取舍

- **终端优先**：文件、差异和仓库操作辅助终端工作，不争夺注意力。
- **结果可检查**：范围和操作结果明确；破坏性操作不能出其不意。
- **保留上下文**：切换项目、标签和窗格后，用户能继续手头工作；每个项目记住自己的停靠布局，工作区默认结构由统一配置决定。
- **常用操作就近**：每个标签栏都能通过相同的「＋」添加终端或面板；默认三列仅是初始位置，不存在特殊的左右侧栏。
- **克制、原生、准确**：不做网页仪表盘式装饰，不逐像素模仿其他编辑器，不堆噪声或不透明的一键自动化。

## 树行与无障碍

文件、Git 未提交、暂存和提交历史使用同一套树语义与行交互。
压缩目录指向真实末级目录；高亮范围可点击，右侧动作独立；长名称可滚动，固定按钮不移动。
这些约定在窄侧栏、放大字体和大树下也要成立。

状态用文件名颜色表达，不另设字母列；同一状态必须能通过提示与辅助技术获知。
控件提供清楚的名称，核心操作支持键盘。设计应遵循 macOS 外观与交互习惯，尊重用户的辅助功能偏好。
