---
title: 常见问题
description: 关于费用、隐私，以及 Kero 和你的 shell 是什么关系。
---

<Accordions>

<Accordion title="Kero 免费吗？">

是的。可从源码自行构建，基于 GPLv3 开源，不需要账号或订阅。

</Accordion>

<Accordion title="它会替换我的 shell 吗？">

不会。Kero 运行的就是你已经在用的 shell——它启动 `$SHELL -l`，不碰你的提示符、别名、函数和
dotfiles。终端窗格使用 Ghostty。

</Accordion>

<Accordion title="它会收集数据吗？">

不包含使用情况遥测、统计脚本或自动更新检查。[浏览器窗格](/zh/docs/browser)、SSH
连接和 Agent CLI 会在你使用时访问网络。

</Accordion>

<Accordion title="它会读我的 Ghostty 配置吗？">

不会。字体、配色和输入行为都来自 Kero 自己的[设置](/zh/docs/configuration)，而非 `~/.config/ghostty`。

</Accordion>

<Accordion title="退出之后我的会话会怎样？">

项目、标签页和窗格布局会在重启后回来，每个终端会在原目录里以全新的 shell 打开。退出之后不会有任何东西继续在后台跑。

如果你打开 [`terminal.restore-history`](/zh/docs/configuration#terminalrestore-history)，之前的滚动历史也会回来——它以静态文本的形式出现在 `Session Contents Restored` 分隔线上方。

</Accordion>

<Accordion title="这是一个 IDE 吗？">

不是，也不打算往那个方向走。终端始终是核心。git 和文件面板的存在，是为了让你不切换应用就能审阅并提交终端里完成的工作——而不是变成你主要的工作场所。

</Accordion>

<Accordion title="为什么有个对话框问我某个程序能不能读剪贴板？">

因为确实有程序在问。`OSC 52` 转义序列允许终端程序读取系统剪贴板，包括通过 SSH 跑在远程主机上的程序。Kero 会先跟你确认，而不是悄悄交出去——这和 Ghostty 的默认行为一致。

</Accordion>

<Accordion title="能和 AI 编码工具一起用吗？">

很大程度上就是为此而做的。打开 AI 后，直接用自然语言让受支持的 agent 在后台窗格运行任务，或把范围明确的工作交给另一个 agent。不同 Kero 窗格里的 agent 还可以互相询问、传递发现和补充要求，不再需要你来回复制上下文。Kero 会显示 provider 报告的 working、blocked 和完成状态，不会根据终端文字猜测；批准与最终 diff 仍由你决定。见[与 AI Agent 协作](/zh/docs/automation)。

当然也可以把 agent 当作普通终端程序使用：在 [Git 面板](/zh/docs/git)里审阅它的 diff，在旁边读文件，然后只暂存真正想要的部分。

</Accordion>

<Accordion title="在哪里报告 bug？">

在 [GitHub](https://github.com/chiimagnus/kero/issues) 上开一个 issue。写清 macOS 版本，以及出问题时你在做什么，通常就够排查了。

</Accordion>

</Accordions>
